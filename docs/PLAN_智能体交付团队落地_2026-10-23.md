# 智能体交付团队（minimax-bot）落地计划

> **执行方式**：本计划可整体交给主 Bot「大内总管」自主执行（它有 `create_bot`/`create_group` 权限，是唯一有权限的角色）。
> 也可由人在 Mini App 中逐 Task 执行。**执行前必读「自动执行边界」一节。**
> 步骤使用 checkbox（`- [ ]`）语法跟踪。

**Goal:** 把 minimax-bot 从「6 个闲置角色的默认模板」改造为「7 Bot 双轨交付团队 + 15 subagent 编制 + 两闸口 + 3 小时态势报告」，跑通一条完整交付链。

**Architecture:** Bot 层 7 个（长期上下文承担者，跑在宿主 `mavis` agent 上），Subagent 层 15 个（每父会话 10 并发，是真正的并行口）。流程为双轨：定义轨（产品经理→架构师）→ 闸口1 人工确认 → 执行轨（CTO→QA→书记员）→ 闸口2 人工确认。进度可见性分三层：L1 宿主自带任务页/执行记录（0 成本）、L2 闸口里程碑（0 成本）、L3 每 180 分钟态势报告（1 槽/次，归书记员）。

**Tech Stack:** minimax-bot v0.7.7 官方插件（22 个 MCP 工具）、宿主 MiniMax Code local-runtime-v2（agent `mavis`）、ATS-NEW（Django + Vue）。

**相关文档**

- 设计全文：`docs/02-architecture/ARCH_智能体交付团队_2026-10-23.md`
- 回滚基线（改造前快照，唯一副本）：`docs/02-architecture/ARCH_智能体交付团队_回滚基线_2026-10-23.md`

## Global Constraints

以下约束来自实测基线，适用于本计划的每一个 Task：

- 全局并发回合恒为 **3**（`engine.mjs:19` `TOP_LEVEL_SLOTS=3`）；任务执行并发 **2**（`task-dispatcher.mjs:8`）。
- 单任务实测均耗 **33.1 分钟**（n=9 done）；单次交付 ≈ 2.2 小时。
- `Bot.instructions` 上限 **4000** 字符，`Bot.role` 上限 **60** 字符（`team.mjs:125-126`）。
- `replyMode=all` 时一条消息依次叫醒全部群成员（`engine.mjs:1012`）→ **所有群一律 `admin`**。
- 定时任务**只在 Mini App 进程运行时触发**（`miniapp.json` `lifecycle: on-demand`）。
- 幂等语义：同 `request_id` + 同内容返回原任务 → 失败重派必须换新 ID（`<原ID>-r2`）。
- `unknown` = 结果待确认，**不自动重派**。
- 团队记忆每轮仅注入 **6,000** 字符；只放已确认的跨需求决定。
- `update_bot` 覆盖 instructions **不可逆** → 动手前必须确认回滚基线文件存在（Task 0）。
- 本计划**不执行任何 git 命令**。

## 自动执行边界（交给大内总管自主执行时的硬规则）

1. **只执行 Task 0 – Task 6。** Task 7 是真实交付（会改代码、跑构建、改仓库），**必须由人发起**，不得自动执行。
2. **每个 Task 前先读现状**：`list_team`（Bot 与群）、`list_schedules`（定时任务）。已达成目标状态就**跳过**该 Task，并在摘要里写「已满足，跳过」。
3. **`create_bot` 前必须查重**：`list_team` 里已存在同名「产品经理」就**不要**再创建——`create_bot` **无幂等**，重复执行会多建一个同名 Bot。
4. **每个 Task 后按该 Task 的验收步骤自检**，不通过就**停下来报告**，不要继续下一个 Task。
5. **不臆造**：本文件里 `<产品经理bot_id>` 是占位符，执行前必须从 `list_team` 取真实 id 替换。
6. **不执行 git 命令**。仓库 `main` 上已有他人未提交改动，本计划不碰版本控制。
7. **只读回滚基线**：`docs/02-architecture/ARCH_智能体交付团队_回滚基线_2026-10-23.md` 是改造前状态的唯一副本，**只读不改**。
8. **不臆造执行结果**：每个验收步骤的判定依据必须是工具的真实返回，不得凭印象声称通过。
