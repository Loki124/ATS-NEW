
## 1. 通用约定（三 app 通用，不再重复）

### 1.1 模型基类与字段

```python
from apps.common.models import FullAuditModel, UUIDModel   # 时间戳+软删+创建人；nanoid(21) 主键
class Xxx(FullAuditModel, UUIDModel):
    class Meta:
        db_table = 'campus_xxx'      # 全小写下划线，前缀 campus_
        verbose_name = '…'
        ordering = ['…']
```

- 所有模型必须继承 `FullAuditModel, UUIDModel`（主键 nanoid 21 位 CharField）。
- **软删**：列表默认过滤 `deleted_at__isnull=True`；提供 `restore` 动作。
- **人员引用**：一律 `models.ForeignKey('campus_control.Person', ...)`，`related_name` 用域前缀（如 `assessment_records`），**禁止**写库内 Person 之外的第二套人员主数据。
- **用户引用**：`models.ForeignKey('core.User', ...)`。
- **JSON 字段**：`models.JSONField(default=list)`（列表）/ `default=dict`（对象）。
- **枚举**：用 `models.TextChoices` 内嵌在模型里，禁止裸字符串。

### 1.2 视图与权限

```python
from apps.core.pagination import StandardResultsSetPagination   # 按仓库实际 import 路径核对
class XxxViewSet(viewsets.ModelViewSet):
    permission_required = 'recruit:campus:<sub>:list'
    permission_map = {
        'create': 'recruit:campus:<sub>:create',
        'update': 'recruit:campus:<sub>:edit',
        'partial_update': 'recruit:campus:<sub>:edit',
        'destroy': 'recruit:campus:<sub>:delete',
    }
    pagination_class = StandardResultsSetPagination
```

- 权限码格式：`recruit:campus:<submodule>:<action>`，`submodule` snake_case，`action` ∈ 仓库 `ACTION_WHITELIST`（view/list/create/edit/delete/export/import/publish/approve/reject/assign/close/start/stop/advance/confirm/evaluate/sync/feedback）。
- 菜单码：`recruit:campus:<submodule>:menu:view`（每个 submodule **仅一条** MENU，R5）。
- **资源码必须同时落三处**（仓库 0045 迁移教训）：`permission_resources` 行、`role_permission` 授权、`permission_templates.permission_codes`。由**父会话**统一在 `core` 迁移里做；子任务只需在 `permission_required`/`permission_map` 里引用正确码。

### 1.3 可见范围（数据隔离）

新域所有列表**必须**按当前用户可见人员范围过滤，规则（与逆向清单一致）：

| 用户角色 | 可见人员 |
|---|---|
| admin / 超管 | 全部（`Person.objects.filter(deleted_at__isnull=True)`） |
| 班主任（`Person.head_teacher == user`） | 自己带的班 |
| 导师（`Person.mentor == user`） | 自己带教的人 |
| HRBP（`Person.hrbp == user` 或班级 HRBP） | 归属 HRBP 范围 |
| 校招生（本人） | 仅本人 |

实现统一走 `campus_control` 的可见性助手；**若该助手不存在，新建 `apps/campus_control/visibility.py`**，由本契约的考核/定岗两个后端任务共用（父会话负责最终合并，见 §7）。

### 1.4 分页与响应封装

- 后端：DRF 分页，列表响应 `{"count":n,"results":[...]}`（沿用仓库既有 `StandardResultsSetPagination` 实际输出，前端按 `r.data?.data ?? r.data?.results ?? []` 兼容解析）。
- 前端 API 层统一导出**已解包**的数组/对象（照抄 `web/app/src/api/campusControl.ts` 的 `listData` 写法：`const listData = <T>(r:any):T[] => (r?.data?.data ?? r?.data?.results ?? []) as T[]`）。

### 1.5 迁移

- 每个新 app 的首个迁移序号 `0001_*`；`makemigrations --check` 必须无漂移。
- 迁移文件头写清业务背景（仓库惯例：docstring 写「背景/根因/改动点」）。

### 1.6 真实数据导入

- 导入命令：`apps/django/apps/campus_control/management/commands/import_campus_lifecycle_data.py`（由父会话实现，模型字段按本文 §2/§3/§4 的字段名对齐）。

### 2.3 排名算法（**必须严格照此实现**，逆向清单 A1~A9）

```
月度总分   totalScore = round(KPI×0.6 + 考试×0.4) + 加减分
累计均分   avgTotal   = 所有月度 totalScore 的算术平均，保留 1 位
KPI 维度   dimKpi   = round(所有月度 kpi 的算术平均)
学习成长   dimLearn = round( mean(课程进度均值, 考试得分均值) )   # 有哪项算哪项
五行五力   dimForce = round( 5 个维度分值的算术平均 )
附加分     dimAdd   = Σ活动奖励分值 + Σ历月加减分
综合得分   comp = round(dimKpi×0.5) + round(dimLearn×0.3) + round(dimForce×0.2) + dimAdd
```
- 排名范围：**全体可见在校人员**（排除已离职）；`dim` 切换时按对应实际值降序。
- 班主任排名：`avgTotal` = 所带学生 avgTotal 的算术平均（1 位）；`rankAvg[dim]` = 所带学生在该维度**名次**的算术平均（名次在全体在培范围内算）。
- 考勤维度值：`round(Σ(出勤 − 迟到×0.5) / 月数, 1)`。

### 4.2 批次规则（挂既有 `campus_control`，追加到该 app 的 `models.py` 末尾）

| 模型 | db_table | 字段 |
|---|---|---|
| `BatchRule` 批次规则 | `campus_batch_rules` | `code` Char(32) / `name` Char(64) / `start_date` Date / `end_date` Date / `enabled` Bool / `sort` PositiveInt |
| `BatchNaming` 批次命名配置（单例） | `campus_batch_naming` | `template` Char(64) 默认 `{YY}{MM}{SEQ}` / `seq_width` PositiveInt 默认 2 / `seq_start` PositiveInt 默认 1 / `cycle` Char(16) choices(month/year/none) 默认 month / `date_field` Char(16) choices(entryDate/hireDate) 默认 entryDate / `auto_apply` Bool 默认 True |

**端点**（挂 `/api/v1/campus/`）：
| 方法 | 路径 | 说明 |
|---|---|---|
| CRUD | `batch-rules/` | 批次规则区间（可增删改、启停） |
| GET/PUT | `batch-naming/` | 命名配置（单例，PUT 覆盖） |
| GET | `batch-rules/preview/` | 实时预览：给定 template/seq_width/seq_start/cycle/date_field → 返回生成样例 + 每规则命中人数 + 未命中人数 + 无批次人数 |
| POST | `batch-rules/apply/` | 按规则回写人员批次（**只补空值**，不覆盖人工填过） |
| POST | `batch-rules/recalc/` | 按命名规则重算全部批次号，返回「原批次 → 新批次」变更清单（**先返回预览，不落库**；body `{ "apply": true }` 才落库） |

**批次号生成算法**（逆向清单 A10/A11）：
```
模板变量：{YYYY}{YY}{MM}{M}{DD}{SEQ}{N}（{N} = 「第1批」形，含第/批字样）
序号：按 cycle 归零（month=同月内递增 / year=同年内递增 / none=全局递增），
      序号 = seq_start + 计数，宽度 = seq_width 补零
匹配：按 start_date ≤ 日期 ≤ end_date 命中唯一规则；无命中则不归属
```
`{YYYY}{YY}{MM}{M}{DD}` 取自**区间起始日**（逆向清单 A11 原文：「批次号 = 命名模板 ＋ 区间起始日 ＋ 批次序号」）。

### 4.3 定岗双选撮合状态机（逆向清单 §4.3 / A14，**必须照此实现**）

```
① 校招生填报 N 个志愿（N = 该批次 wish_limit，缺省继承全局默认 2）
② 撮合启动后：第一志愿推送至「岗位所属业务 BP」
③ BP 录取 → 后续志愿自动释放（status=已释放）；BP 放弃 → 下一志愿自动推送
④ 两志愿均未被选 → 进入人才市场（status=人才市场），全员 BP 可选
⑤ 仍未被选 → 班主任/管理员指定分配（channel=指定）
⑥ 管理员发布双选结果
```
- 流程**按校招批次独立推进**；`SelectionFlow.started=True` 后校招生**不可再修改志愿**（服务端拒绝，返回明确错误信息）。
- 岗位开放判定顺序（逆向清单 §4.3）：审核状态 → 开放开关 → 发布范围（all/batch/intentDept）→ 面向届数/班级 → 窗口期。

结构：`{ "meta": {...}, "students": [...], "teachers": [...], "mentors": [...], "hrbps": [...], "schools": [...], "exceptions": [...], "offerStats": [...], "orgPlan": [...], "rotPlan": [...], "finalPlan": [...], "pendings": [...], "rotRes": {...} }`

**导入纪律**：
- **幂等**：以稳定业务键（employee_id / code / bill_no / name+date）upsert，重复执行不产生重复行。

- **可回滚**：命令支持 `--dry-run`（只统计不写）与 `--limit N`（抽样试跑）。
- **输出摘要**：每个集合「新增 / 更新 / 跳过 / 冲突」四类计数 + 警告清单（无法映射的院校标签、找不到的 User 等）。
