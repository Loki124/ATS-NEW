# 日期类型指标 —— 出参单位与值域规范

> 适用范围：`MetricTemplate` 引用的指标 `data_type == 'date'`（即出参为日期）时的
> **出参单位**与**值域配置**口径。
> 落地位置：`apps/django/apps/metrics/models.py`（字段语义）、
> `apps/django/apps/metrics/serializers.py`（校验）、
> `web/app/src/pages/settings/MetricsWorkspace.vue`（编辑与预览）。
> 相关文档：`docs/ARCH_指标作为条件源.md`（data_type → value_type 映射）、
> `apps/django/apps/metrics/services/operator_matrix.py`（日期运算符白名单）。

---

## 1. 背景与问题

日期是 `MetricDataType` 的四类之一（number / string / boolean / date），
运算符白名单也早已按类型给出（日期走 `EQ/NEQ/GT/GTE/LT/LTE/BETWEEN/IS_EMPTY/IS_NOT_EMPTY`）。
但「出参单位」与「值域配置」两处一直是**按数值口径**实现的，导致日期型出参出现语义错误：

| 项 | 数值口径下的表现 | 日期型下的问题 |
|---|---|---|
| 出参单位 | 自由文本量纲（岁 / 元 / 月） | 日期没有量纲，单位框只能显示「（无单位）」，粒度无处表达 |
| 值域配置 | `段1: 1 ~ 3，步长 1` → 共 3 个值 `1, 2, 3` | 枚举出的是与日期无关的裸数字，规则里出现「出生年月 ≥ 1」这种无意义条件 |

**根因**：把「日期」当成了「带单位的数字」。日期的可选范围本质是一段**时间区间**，
不是一个可等距枚举的刻度序列。

---

## 2. 规范正文

### R1：日期型出参的「单位」= 日期粒度

日期无量纲（不像「岁 / 元 / 月」），因此「单位」在此处**唯一有意义的语义是日期精度**，
即该日期精确到年、月还是日。

- 取值集合：**`年` / `月` / `日`**，默认 **`日`**（未指定时按 `日` 处理，不再显示「无单位」）。
- 复用平台既有语义：取值与动态字段的 `YEAR / MONTH / DAY` 精度枚举一致。
- 后端校验：日期型模板的 `unit` 必须 ∈ `{年, 月, 日}`，其余值一律拒绝
  （如误填「岁」→ `400 日期型出参的单位是日期粒度，只能取 年 / 月 / 日`）。

粒度决定三件事（一处配置，三处生效）：

| 粒度 | 边界选择器精度 | 存储/传输格式 | 展示格式 |
|---|---|---|---|
| 年 | `year` | `YYYY`（读写时补齐为 `YYYY-01-01`） | `1950` |
| 月 | `month` | `YYYY-MM`（补齐为 `YYYY-MM-01`） | `1950-06` |
| 日 | `date` | `YYYY-MM-DD` | `1950-06-15` |

### R2：日期型出参的「值域」= 可选日期区间，不是数值刻度

值域回答的是「**哪些日期可选**」，因此每段是一段区间约束，而不是 `min/max/step` 数值刻度。

数据结构（`MetricTemplate.value_domain`）：

```jsonc
{
  "segments": [
    {
      // 边界二选一形态
      "from": { "type": "absolute", "date": "1950-01-01" },
      "to":   { "type": "relative", "n": -30, "unit": "年" },   // 今天-30年
      "step": 1,            // 步进数量，必须为正整数
      "stepUnit": "年",      // 步进粒度（年/月/日），缺省取出参粒度
      "label": ""
    }
  ]
}
```

边界的两种形态：

| 形态 | 结构 | 含义 | 文案 |
|---|---|---|---|
| 绝对日期 | `{type:'absolute', date:'1950-01-01'}` | 固定日期，格式由粒度决定 | `1950-01-01` |
| 相对今天 | `{type:'relative', n:-30, unit:'年'}` | 相对当前日期偏移，即 `T-30年` | `今天-30年` |

> 相对边界沿用平台动态字段既有的 `T±N` 语义并**扩展到 年/月/日**
> （字段层原 `T±N` 只支持「天」，见 `apps/django/apps/dynamic_field/validators.py`）。
> 指标引擎取值走 `MetricDataType.DATE` 的 `date.fromisoformat` 解析，
> 相对边界在**配置与预览阶段**解析成真实日期，落库保留相对表达以便随日期推移自动生效。

约束规则（前后端一致，后端为权威校验）：

1. `step` 必须是**正整数**（日期按粒度步进，小数步长无意义）；
2. `stepUnit` ∈ `{年, 月, 日}`，缺省取出参粒度；
3. 每段**至少一个边界**（`from` 或 `to`）；仅单边时该段不枚举，只给出一个取值点
   （`X起` / `X及以前`）；
4. 双边界时**起始必须早于结束**（解析成真实日期后比较）；
5. 相邻分段**不得重叠或共用边界**（会枚举出重复的可选日期）；
6. **禁止**在日期型模板上出现数值 `min/max` —— 属旧口径遗留数据，一律拒绝并要求重配。

### R3：非日期型出参维持原数值口径

`number / string / boolean / enum` 仍用 `segments:[{min, max, step, label}]`。
两套结构由**出参类型**互斥判定，切换指标时若出参在「日期 / 非日期」之间跨越，
前端清空值域以免残留读不懂的旧结构（同一类型内切换则保留）。

### R4：预览与总览必须展示真实日期

- 值域总览枚举出**真实日期**（如 `1950-01-01, 1951-01-01, …`），而非裸数字；
- 按「日」步进的宽区间可达上万项，故**只展示前 40 个**，文案标明
  「共 N 个值（展示前 40 个）」，避免误以为只有 40 个可选；
- 配置预览的「校验值」下拉随之变为日期；选择「区间」运算符时呈现**起始 / 结束两个日期框**。

---

## 3. 示例

「出生年月范围」（引用原子指标 `出生日期 candidate.birth_date`，出参=日期）：

| 配置 | 值 |
|---|---|
| 出参粒度 | `年` |
| 值域段 1 | 起始 `1950-01-01`（绝对） ~ 结束 `今天-30年`（相对），步长 `1 年` |

效果：可选日期为 `1950, 1951, …, 1996`；规则里呈现为
「出生年月范围 ∈ 1950 ~ 1996」，而不是旧版的「≥ 1」。

## 4. 存量数据处理

迁移 `0025_normalize_date_value_domain`：把日期型模板上遗留的数值段清空
（留空 = 自由区间，语义正确），并归零非法单位值。
被清掉的是无法解释的无效值（如 `{min:1, max:3}`），**不可反向**。

> 已知受影响记录：`MT0004 出生年月范围`（原 `{min:1, max:3, step:1}`）。
> 迁移后需在编辑弹窗按新口径重新配置值域。

---

## 5. 未覆盖（明确边界）

- 相对边界的解析发生在**配置与预览**侧；指标引擎求值时比较值仍按 ISO 日期字符串处理，
  暂不支持把 `T±N` 直接作为运行时比较值（如有需要应另行扩展引擎取值链路）。
- 日期值域目前只约束「可选范围」，不参与服务端求值校验 —— 与 `param_config` 一样，
  属配置期约束（参见 `deliverables/software-company/metrics-rule-engine-code-review-2026-10-07.md` M-9）。
