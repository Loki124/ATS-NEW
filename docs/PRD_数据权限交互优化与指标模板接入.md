## 1. 产品目标与非目标

### 1.1 一句话目标

> **让管理员在一个页面里把"谁能看什么 / 能做什么 / 哪些字段敏感"配清楚、配得对，并且看得懂叠加后的最终结果；同时把指标模板作为权限条件的一种可靠来源接进来。**

### 1.2 三个正交目标

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | **不出错**：权限配置"保存成功"必须等于"重开还在" | 写范围保存往返用例 100% 通过；`write` 缺失时后端拒收而非静默清空 |
| G2 | **看得懂**：多角色叠加结果可解释，字段敏感度可配置 | 叠加预览面板上线；字段 ACL 从只读死页变为可配矩阵 |
| G3 | **接得上**：指标模板可作为权限条件源，且模板变更不会静默改权限 | `kind='metric'` 条件可用；模板改版后权限规则漂移可见、需显式升级 |

### 1.3 明确的非目标（这次不做什么）

| # | 不做什么 | 理由 |
|---|---|---|
| N1 | 不动 V1 遗留权限类（`permission_resources` 体系外的旧路径） | 存量 0 流量，动它风险无收益 |
| N2 | 不做权限审批流 / 授权工单重构 | 独立课题，本次只接入 `approve_l1/l2` 校验点（P1-6） |
| N3 | 不复活 `kind='attribute'` 词汇（D1/B 方案） | 2026-10-13 已主动下线，复活会产生第三套平行概念 |
| N4 | 不引入"运行时外链"指标模板（D6） | 会导致"管理员改一次模板、所有在用规则静默漂移"的事故级缺陷 |
| N5 | 不做三套权限模型（功能 / 数据 / 字段）的**数据合并** | 本次只做**统一入口 + 裁决规则显式化**，模型仍各自独立 |
| N6 | 不做权限资源树的大规模重构（`parent_code` 回填） | 降级为 P2（S2），本次只补父选联动 |
| N7 | 不引入新的设计令牌 / 手写品牌色 | 见 `AGENTS.md` R-210/R-214，令牌 MUST 由 CLI 生成 |
| N8 | 不做多租户/白标相关的权限改造 | 与本需求无关 |

## 2. 用户故事与验收标准

> 格式：Given-When-Then。角色三类：系统管理员（配置者）/ 业务 HR（使用者）/ 被授权普通员工（受影响者）。

### 2.1 系统管理员

**US-1（P0-1）我配的操作权限不会被系统悄悄吃掉**

- Given 我在角色「HRBP」的候选人模块，展开「写范围」，选了「全部可写」并勾选了「删除候选人」
- When 我点击「保存角色权限」并看到成功提示，然后关闭再重新打开该角色
- Then 写范围仍显示「全部可写」且「删除候选人」处于勾选态
- **And** 若前端因任何原因未提交写范围字段，后端 MUST 拒绝保存并返回明确错误，MUST NOT 静默清空已有写范围

**US-2（P0-2）我能为敏感字段设置可见性**

- Given 我打开身份管理下的「字段可见性」
- When 我为角色「HR」把候选人模块的「手机号」设为「脱敏可见」，为角色「审计员」设为「不可见」
- Then 保存后重新打开，配置仍在；用「HR」登录看到脱敏手机号，用「审计员」登录看不到该字段
- **And** 页面 MUST NOT 再出现"请在上方角色矩阵中配置"这类指向不存在入口的引导

**US-3（P0-2/P0-4）我配的字段脱敏真的生效在所有业务对象上**

- Given 我把「投递（application）」的手机号设为「脱敏可见」
- When 任何角色通过投递列表 / 详情接口取数据
- Then 返回的手机号按 ACL 脱敏，MUST NOT 出现未脱敏原值

**US-4（P1-7）我需要知道叠加后到底生效成什么**

- Given 用户「张三」拥有角色 A、B、C
- When 我在角色详情页打开「生效预览」并选中张三
- Then 我看到功能权限（并集）、数据范围（并集）、列权限（从严）三块结论，且每条结论可展开到"来自哪个角色"
- **And** 我能看到冲突清单（哪些配置被从严规则覆盖、哪些因模板失效导致不生效）

**US-5（P0-3）我不用担心给已删除的用户/角色留下授权口子**

- Given 库里存在指向不存在用户的授权记录、指向已不存在的角色 `test` 的权限记录
- When 系统完成数据修复
- Then 孤儿记录被清理；此后删除用户或角色时其授权自动随之删除
- **And** 新建授权时 MUST NOT 允许选择不存在的用户或角色

**US-6（M1~M10）我想用指标来配数据范围**

- Given 指标模板中心有一个启用中的模板「月面试转化率」，可按部门取值
- When 我在角色「招聘负责人」的招聘流程模块，读范围选「指定范围」，添加一个「指标条件」
- Then 我依次选择：指标模板 → 算子 → 取值方式 → 对象，四个下拉联动
- **And** 对象候选来自模板的实体值域，越界值无法选中
- **And** 保存后重开，条件仍在，且显示"引用版本 v2"

### 2.2 业务 HR

**US-7（P1-2/P1-3）我能在一次浏览里看清一个模块的读/写/字段三件事**

- Given 我打开角色编辑的数据权限部分
- When 我查看「候选人管理」模块卡
- Then 同一张卡内并列展示三个分区：读范围 / 写范围 / 字段可见性，各分区默认显示一行中文摘要
- **And** 我不需要展开多层弹窗就能知道"这个模块现在能读什么、能做什么、哪些字段看不到"

**US-8（P1-4）我知道"勾了功能权限但没勾写动作"意味着什么**

- Given 我在功能权限勾了「导出候选人」，但写范围的动作清单里没勾「导出」
- When 我查看写范围分区
- Then 页面明确提示："功能权限已勾选『导出候选人』，此处未勾选 → 实际不可导出（从严）"
- **And** 「导入」「导出」「审批」等动作 MUST 有独立分组，MUST NOT 与增删改平铺混排

**US-9（P1-1）我建角色不用来两趟**

- Given 我要新建一个「面试官」角色并给它数据权限
- When 我从新建入口一路配完基础信息、功能权限、数据权限并保存
- Then 一次保存即完成角色创建 + 权限配置
- **And** 中途关闭且有未保存内容时，草稿被保留；下次进入提示"已恢复上次填写的内容"并提供「清空草稿」出口

### 2.3 被授权的普通员工

**US-10（P1-7）我作为被授权者，能预先知道我会看到什么**

- Given 我有 2 个角色
- When 我查看自己的权限摘要（或管理员为我查看）
- Then 我看到的是叠加后的最终结果（读=并集、字段=从严），而不是某一个角色的配置

**US-11（P0-4）我的敏感字段被保护**

- Given 我是普通 HR，薪资字段被配为「脱敏可见」
- When 我查看候选人详情
- Then 薪资显示为脱敏格式，且我无法通过接口拿到原值

**US-12（fail-closed）模板停用时我得到的是明确说明而不是"莫名其妙没数据"**

- Given 我的数据范围依赖一个指标模板，该模板被停用
- When 我打开相关列表
- Then 我看到明确提示："你当前无权查看该模块数据（依赖的指标模板已停用）"，并给出联系管理员的出口
- **And** 我配置的内容 MUST 被保留，不被自动删除

### 3.1 P0 — 阻断级（4 项）

| 编号 | 名称 | 用户价值 | 验收标准（可测） | 端 |
|---|---|---|---|---|
| **P0-1** | 写范围保存被抹除（前后端契约断裂） | 管理员配的操作权限真的生效，不再"保存成功但配置消失" | ① 用例：配写范围→保存→重开，模式与动作勾选全部保持（T5）<br>② 提交 payload 不含 `write` 字段时，后端返回 4xx 且**原写范围规则在库中不变**（用行数/快照断言，不用"提示成功"）<br>③ 该契约断裂不得复现：任何新增模块字段若前端漏传，后端 MUST 拒收而非忽略 | FE+BE |

| **P0-3** | 授权数据完整性失控（孤儿授权） | 授权不会指向不存在的用户/角色，不留隐性放行口子 | ① 迁移后 `user_roles` 中指向不存在用户的记录数 = 0；指向已不存在角色（如 `test`）的权限关联 = 0<br>② 删除用户 → 其角色授权自动清除；删除角色 → 其权限关联与规则自动清除<br>③ 授权创建接口对不存在的用户/角色返回明确错误，不静默成功 | DB+BE |
| **P0-4** | 字段 ACL 接入面补齐（投递手机号裸奔） | 脱敏规则在所有承载敏感字段的业务对象上真实生效 | ① 字段 ACL 仅接入 4 个序列化器（`candidate/serializers.py:29,69`、`talent_pool/serializers.py:16,43`），MUST 扩展到 `application` / `interview` / `onboarding` / `demand` 等含敏感字段的序列化器<br>② 验收：投递列表与详情接口返回的手机号按 ACL 脱敏/隐藏，抓包断言无原值<br>③ 每次裁剪写入审计日志且 `masked_fields` / `hidden_fields` 不再全空 | BE |

### 3.3 P1 — 系统级（指标模板接入核心 10 项）

| 编号 | 名称 | 用户价值 | 验收标准（可测） | 端 |
|---|---|---|---|---|
| **M1** | `kind='metric'` 条件分支（编译/校验/求值） | 指标条件能被真正执行 | ① 数值 / 日期 / 枚举 / 实体四类各 1 条用例编译 + 求值正确（T1）<br>② 复用既有指标条件求值能力，不新增第二套运算符定义 | BE |
| **M2** | 权限条件字段目录接口（模板驱动） | 四个下拉有数据可填 | ① 目录下发：模板列表（含原子/派生标识）、算子白名单、值控件类型、枚举候选、区间 min/max/step、实体候选、可空标记、单位与前后缀<br>② 目录仅包含**启用中**的模板 | BE |
| **M4** | 保存期值域校验 | 配不出无效权限 | ① 值必须落在模板 `value_domain` 内，越界拒绝保存并给出行内错误（T2）<br>② 算子不在白名单 → 拒绝保存（当前是求值时才报错）<br>③ 校验发生在前后端两侧，前端先拦、后端二次校验 | FE+BE |
| **M9** | 条件行四框联动编辑器 | 配置体验与阶段规则一致、复用已定稿交互 | ① 条件行结构 = 指标模板 → 算子 → 取值方式 → 对象<br>② 取值方式仅在实体类指标出现；对象候选来自模板实体值域，且提供「全部」单标签形态<br>③ 切换上游任一框，下游选项 MUST 级联重置，不残留脏值 | FE |
| **M10** | 值控件按类型分化 | 日期/人员/部门不再用文本框手输 | ① number=步进数字框（BETWEEN 为双框）；date=日期选择器+粒度；enum=可搜索下拉；entity=取值方式+对象双框；boolean=是/否下拉<br>② string 自由文本 MUST 显式标注"无法穷举，建议改用包含/正则"<br>③ 当前所有类型落 `n-input` 的缺口关闭 | FE |
| **M14** | 值控件消费 `min/max/step`、实体候选、可空标记 | 参数限制真的生效（现为死数据） | ① 前端字段定义补齐这三个键与实体候选、可空标记<br>② 模板允许为空的参数，条件值 MUST 允许留空（当前规则侧强制必填，与模板语义冲突） | FE |

## 5. 指标模板条件（`kind='metric'`）产品定义

> 技术路线：**B 方案**（新建 `kind='metric'`，不复用已下线的 attribute 词汇；attribute 分支保留只读兼容，存量 0 条）。**D6：必须快照，禁止运行时外链。**

### 5.1 术语与职责边界

| 概念 | 回答什么 | 归属 |
|---|---|---|
| 指标模板 | 用什么指标、可以怎么比、能填什么值 | 指标中心（配置能力） |
| 权限规则 | 在什么条件下、对哪个模块、谁能读/能做什么 | 身份管理（授权决策） |

> 指标模板**不直接持有权限语义** → 同一模板可被多个角色/模块复用。

### 5.2 四个下拉的产品定义

| 顺序 | 下拉 | 候选来源 | 联动与校验 | 用户可见文案 |
|---|---|---|---|---|
| ① | **指标模板** | 仅启用中模板；分组按"原子指标 / 派生指标" | 选定后决定 ② 的算子集与 ④ 的对象域 | `〔原子〕月面试转化率` / `〔派生〕部门人均简历数` |
| ② | **算子** | 模板声明的算子白名单（唯一来源，与阶段规则一致） | MUST NOT 出现白名单外的算子；越权选择 MUST NOT 被保存 | `≥ 大于等于`、`介于…之间` |
| ③ | **取值方式** | **仅实体类指标**（人员/部门）出现；非实体类指标该框不出现 | 选定后决定 ④ 的对象类型与候选集 | `全部` / `本人` / `本部门` / `本部门及下属` / `指定人员` / `指定部门` |
| ④ | **对象** | 模板实体值域候选（≤ 配置候选值）；`全部` 为单标签形态，不可删除 | 越界候选 MUST NOT 出现（非禁用置灰，而是不可选，避免误导） | 人员/部门选择结果；`全部` 单标签 |

**校验规则**

| # | 规则 | 失败反馈 |
|---|---|---|
| V1 | 值必须落在模板值域内（数值区间/日期区间/枚举/实体候选） | 拒绝保存 + 行内错误 + 定位到具体条件行 |
| V2 | 算子必须在白名单内 | 拒绝保存（前端不可选，后端二次校验） |
| V3 | 模板声明"参数可为空"时，条件值允许留空 | 留空时不报错；不可为空时留空 → 阻断保存 |
| V4 | 引用已停用/已删除模板 | 拒绝保存 + 红字说明 |
| V5 | 模板改版 | 允许保存，但标记漂移，不自动跟随 |

**值控件形态**

| 指标数据类型 | 控件 | 候选来源 | 备注 |
|---|---|---|---|
| 数值 | 数字框（按步进步进）+ 候选下拉 | 区间枚举候选 | 区间算子用双框 |
| 日期 | 日期选择器 + 粒度下拉 | 绝对/相对区间 | 当前全落文本框，需修 |
| 枚举 | 可搜索下拉 | 模板枚举参数 | — |
| 实体（人员/部门） | 取值方式 + 对象双框联动 | 实体值域候选 | 复用已定稿交互 |
| 布尔 | 下拉 是 / 否 | 内置 | — |
| 自由文本 | 文本框 | — | MUST 显式标注"无法穷举，建议改用包含/正则" |

### 5.3 快照与升级的用户体验

| 状态 | 触发 | 用户可见表现 | 用户可做什么 |
|---|---|---|---|
| **最新** | 引用后模板未变 | 条件行右侧小标签"v2" | — |
| **漂移** | 模板已升到 v3 | 条件行右侧琥珀标签"模板有新版本 v3"，hover 显示"当前配置基于 v2，模板更新不会自动改变你的权限" | 点「升级到 v3」→ 展示差异预览（算子是否仍合法 / 候选值是否越界）→ 确认后写入新快照 |
| **失效（停用）** | 模板停用 | 条件行红色标签"模板已停用"；分区底部红色提示"该模块当前不返回任何数据" | 「查看模板」「改为其他指标」；**配置保留不删** |
| **缺失（删除）** | 模板删除 | 条件行红色标签"模板已删除" | 同上 |
| **升级越界** | 新版本候选值已不含原值 | 升级预览中高亮该条件：「新版本已不支持取值『张三』，请重新选择」 | 必须改值后才能完成升级 |

**失效语义（锁定）**：模板停用/删除 → 该条件组 **fail-closed（整组不返回数据）**，比阶段规则的条件级 FAIL 更严。选择更严是因为权限场景下"给不出数据"比"给错数据"安全。

**用户可见文案模板（错误三段式，禁"抱歉"开头）**

> 「"招聘流程"模块的数据范围依赖指标模板《月面试转化率》，该模板已停用 → 该模块当前不返回任何数据。**你的配置已保留，没有被删除。** [查看模板] [改为其他指标] [复制错误信息]」

|---|---|---|---|
| E1 权限侧主入口 | 模块卡 → 读/写范围 → 条件组 → 「+ 指标条件」 | 配置权限时按指标挑模板 | P1（M9/M10） |

| E3 批量入口 | 指标模板 → 「应用到权限」 | 常用模板一次铺开到多个模块/角色 | P2（M12） |

> 每条给出推荐选项 + 理由 + 不决策的影响。

### Q1　`priority` 字段下掉会不会造成已有配置丢失？【我的调研结论：不会】

- **推荐**：按原计划下掉（S1）。
- **理由**：我已核代码——该字段**全仓唯一写入点是硬编码 `0`**（`role_scope_api.py:284,306`），前端无任何输入控件，仅在列表默认排序中被读取（`data_permission/views.py:67-68` 的 `-priority`）。且 `enforcement` 从不读取它。因现存 11 条规则的 `priority` 全为 0，**下掉不会丢失任何用户配置**，列表排序表现也不变（实际由创建时间倒序决定）。
- **不决策的影响**：字段继续定义但不生效，管理员看到"优先级（大者优先）"会误以为能调冲突顺序，形成**第二套叠加语义**，与 G2「看得懂」直接冲突；同时 S1 挂在清理阶段会持续拖延。

### Q2　字段 ACL 放独立页还是并入模块权限卡三分区？

- **推荐**：**独立页做批量矩阵 + 模块卡内做入口，双向互链**（即上游 D5 的建议）。
- **理由**：字段维度是「实体 × 字段 × 角色」，与「模块 × 范围」的维度不同构；硬塞进模块卡会导致单卡塞入实体×字段×角色三维选择，违反"一屏一主角"（R-202）且必然横向溢出（R-103，320px 约束）。批量配置也只有独立矩阵才做得动。
- **不决策的影响**：P1-2 与 P0-2 的入口归属悬空，前端会各做一套；或强行合并导致模块卡不可用。

### Q3　列/字段权限三态的用户可见文案以哪套为准？

- **推荐**：UI 用「**可读 / 脱敏可见 / 不可见**」，与后端枚举 `READ / MASK / NONE` 一一对应；从严顺序 `NONE > MASK > READ`。
- **理由**：我已核实后端枚举实为 `READ/MASK/NONE`（`field_acl/models.py:11-15`、`enforcement._SEVERITY = {'READ':0,'MASK':1,'NONE':2}`），**上游方案文档写的 `VIEW/MASK/HIDE` 与代码不一致**。前端若自建映射表，就是 P2-7（运算符口径三处分叉）的同款病因——映射表必然分叉。
- **不决策的影响**：前后端各持一套映射，字段 ACL 与列级从严裁决会出现口径漂移，且难以在测试里发现。

### Q4　模板失效要不要给"临时放行"开关？

- **推荐**：**不给**。保存期硬拦截（不让保存引用失效模板）+ 存量引用在生效预览面板标注"不生效（fail-closed）"+ 修复入口。
- **理由**：权限场景"给不出数据"比"给错数据"安全；加临时放行等于引入第三套叠加语义（与 Q1 同类错误），且失效原因可能随时消失，开关会长期留存变成后门。
- **不决策的影响**：实现方大概率自行加一个"忽略失效模板"的开关（因为用户会抱怨"数据看不到了"），届时要回收很难。

### Q5　模板漂移升级是否需要批量入口？

- **推荐**：**一期只做单条显式升级**（带差异预览），批量升级放 P2。
- **理由**：批量升级里必然混入"新版本已不支持该取值"的越界项，自动修复会静默改权限；批量场景必须逐条确认，收益低于风险。
- **不决策的影响**：M7 范围不定；若一期就做批量而无差异预览，会产生"管理员批量点升级，权限悄悄变了"的事故。

### Q6　P0-1 后端改为 fail-closed 报错，会不会打断存量角色的正常保存？【必须在动工前定】

- **推荐**：采用**兼容式强校验** —— 仅当该角色**历史存在过写范围规则**，或前端显式提交了 `write` 字段时才强校验；存量 11 条无 WRITE 规则的角色允许首轮保存并由后端一次性补 `write: {mode:'none'}` 默认值。
- **理由**：现库 11 条规则无一条 WRITE（与"从未成功保存过"一致）。若一刀切强校验，会让管理员**只想改读范围却无法保存**，属于修 P0 引入新 P0。
- **不决策的影响**：架构师大概率直接按方案文档实现"缺失即拒"，上线后所有存量角色的数据权限页全部保存失败 —— 这是本次改造最大的回归风险点。
