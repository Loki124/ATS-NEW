# 「编辑指标模板」弹窗 · UI/UX 改进方案 v4

> 目标：在不改变核心业务逻辑与数据契约的前提下，重构弹窗的信息层级、输入项、校验、反馈与响应式表现。
>
> 事实基线：`web/app/src/pages/settings/MetricsWorkspace.vue`（弹窗模板 L354–559 / 逻辑 L1449–1872 / 样式 L2536–2701、L2775–2784）、
> `web/app/src/locales/metrics.ts`、`web/app/src/styles/tokens.css`、`brand-tokens.css`、`glass.css`（弹窗类名铁律 L1215–1223）。
>
> 约束权威源：`AGENTS.md`（P0/P1/P2 + §7 自检）、`docs/04-ui/UI_DESIGN_SPEC.md` v2.3、`docs/04-ui/MODAL_DIVIDER_CONVENTION.md`。
>
> 配套原型：`docs/ui/metric-template-modal-v4-prototype.html`（可交互，含状态/断点/主题切换）。

---

## 0. 一句话结论

当前弹窗的问题是**「四个平权编号分区 + 一行行挤满控件」**：分区用实心编号方块争夺注意力、必填与选填无差别、
继承（只读）信息与可编辑字段混在一起、两个「步长」同名异义、值域段填写错误被静默丢弃、校验只有 Toast、
保存中表单仍可编辑、窄屏有横向溢出风险。v4 的做法是**「决策先行 + 主干/可选分层 + 就地校验 + 显式反馈」**。

## 2. 信息架构重构

### 2.1 从「四个平权编号区」到「决策 → 主干 → 可选 → 只读」

```
┌ Header（固定）───────────────────────────────────────────┐
│ [图标] 编辑指标模板  [编辑中]                        [ ✕ ] │  ← 关闭命中区 44×44
│ 引用指标定义 · 平均工作时长（candidate.workExperience）    │  ← 唯一的副标题，兼作 A3 去重
└──────────────────────────────────────────────────────────┘
┌ Body（区域滚动，仅此一处滚动）────────────────────────────┐
│ ▸ 01 引用指标定义  必填 ★主干                              │
│     定义选择器（分组：原子/派生）                          │
│     选中后：继承信息只读卡（出参类型 / 取值方式 / 出参单位）│
│     未选中：区内空态「先选择指标定义，其余配置将自动展开」  │
│ ▸ 02 模板名称  必填 ★主干                                 │
│     输入框（选中定义后自动预填定义名）+ 字数计数            │
│ ─────────────────────────────────────────────────────    │
│ ▸ 参数配置（有参数才渲染；无参数显示一句说明）              │
│     下限 / 上限 / 参数步长 / 显示格式 / 全部选项            │
│     预览摘要条（单行 + 「展开全部」）                       │
│ ▸ 可用运算符  必填 ★主干                                  │
│     已启用 11 / 共 11  [全选][清空]                        │
│     分组：比较 / 区间 / 集合 / 空值                        │
│ ▸ 值域配置（可选）                                        │
│     段卡（下限 / 上限 / 该段步长 / 复制 / 删除）+ 行内校验   │
│     ＋ 添加分段  ·  共 N 个值（可展开）                     │
│ ─────────────────────────────────────────────────────    │
│ ▸ 备注与状态（可选，默认折叠）                              │
│     说明（字数计数）+ 状态开关 + 停用影响说明               │
│ ▸ 规则条件呈现（只读预览，默认折叠）                        │
└──────────────────────────────────────────────────────────┘
┌ Footer（固定）───────────────────────────────────────────┐
│ ● 有未保存的修改 / 已恢复草稿 [清空]      [放弃修改] [保存模板] │
└──────────────────────────────────────────────────────────┘
```

**关键决策**

1. **去掉数字编号，改用「图标 + 语义标题 + 层级线」**：解决 A1（条件渲染导致编号漂移）与 H2（实心方块抢注意力）。主干区标题 `--fs-14/600`，可选项区标题 `--fs-13/600` + 灰字「可选」徽标 → 解决 A2。
2. **决策先行**：把「引用指标定义」提到「名称」之前，因为参数配置/运算符/值域/单位全部由它驱动（`onTemplateMetricChange` 决定后续可选项）。这是纯展示顺序调整，不触碰逻辑。
3. **继承信息独立成「只读卡」**：带锁图标 + `tpl.inheritedHint`，与可编辑字段用底色区分 → 解决 A4、A5。
4. **可选项收进「可选」语义层**：显示格式、全部选项、值域配置、备注与状态、预览。解决 A2 且首屏更短。
5. **配置预览改为只读折叠区**，四步加步骤标签，明确「这是呈现效果，不是配置项」→ 解决 B7。

## 5. 校验与错误提示规格

### 5.1 规则表（字段级，替代现有 4 条 Toast）

| 字段 | 规则 | 触发 | 文案（中文，动词化） | 处理 |
|---|---|---|---|---|
| 引用指标定义 | 必填 | blur / submit | 「先选择要引用的指标定义」 | 阻断 |
| 模板名称 | trim 非空 | blur / submit | 「请填写模板名称」 | 阻断 |
| 模板名称 | ≤ 40 字符 | input | 「名称不超过 40 个字符」（超长时截断 + 计数变红） | 阻断 |
| 可用运算符 | 至少 1 个 | change / submit | 「至少启用 1 个运算符，否则规则里无法配置这个指标」 | 阻断 |
| 参数下限 | 必填（有参数时） | blur | 「请填写参数范围下限」 | 阻断 |
| 参数上限 | > 下限 | blur | 「上限要大于下限」 | 阻断 |
| 参数步长 | > 0；离散型必须为整数 | blur | 「步长要大于 0」/「离散参数的步长必须是整数」 | 阻断 |
| 显示前缀 / 后缀 | 各 ≤ 8 字符 | input | 「前缀不超过 8 个字符」 | 阻断 |
| 值域段 · 下限 | 必填 | blur | 「请填写这一段的起始值」 | **不阻断**（见 5.3） |
| 值域段 · 上限 | > 下限 | blur | 「上限要大于下限，否则这一段不会生成可选值」 | **不阻断** |
| 值域段 · 步长 | 空 或 > 0 | blur | 「步长要大于 0」 | **不阻断** |

### 5.2 呈现规格（R-221 / S-32）

1. **就地**：错误紧贴字段下方，`图标(alert-circle) + 文字` 双通道，`红 = --c-error`，字段边框同时转 `--c-error`（颜色不是唯一通道）。
2. **可容纳**：修正 C3 —— 移除 `margin-bottom: 0 !important` 与 `feedback-wrapper { min-height: 0 !important }`，让 `n-form-item` 的错误区有正常高度；错误插入在字段下方，因表单位于唯一的滚动容器内，位移只影响容器内部，不引起整页跳动。
3. **汇总条**：提交时若存在 N 个错误，表单顶部插入 `n-alert(type=error)`「还有 N 项需要补充」+ 错误字段锚点列表；点击锚点 `scrollIntoView({block:'center'})` 并聚焦该控件。
4. **首错聚焦**：提交时自动滚动并聚焦第一个错误字段（`aria-invalid` + `aria-describedby` 指向错误文案）。运算符区聚焦「全选」按钮而非隐藏的 checkbox，保证焦点环可见。
5. **失焦即校验、输入即消错**：`blur` 时校验；已有错误的字段在 `input` 时重新校验并即时清除，避免「改完了还红着」。
6. **主按钮不禁用**：未满足必填时「保存模板」保持可点，旁边显示「还需补充 N 项」。理由——禁用主按钮会让用户无法得知原因（R-204 要求文案说明后果）；禁用于「保存中」与「无权限」两种确定状态。

### 5.3 业务边界声明（重要）

- 值域段的无效段**不阻断保存**，维持现有行为：后端无该层校验，`buildDomainItems()` 本就跳过无效段。
- 但**必须消除静默**：无效段就地标红 + 提交成功后 Toast 明确告知
  「模板已保存；有 2 段配置不完整，这几段不会生成可选值」。
- 参数范围 `min >= max` 时（D4），预览条改为占位说明「上限需大于下限才能生成预览」，而非整块消失。
- 其它校验均为**新增的就地提示**，不改变可保存的数据集合：现有 4 条 Toast 校验（名称/定义/运算符）原本就阻断提交，只是改为字段级呈现。
- **不做**的服务端交互变更：无重名校验（未确认后端唯一约束，不擅自新增）、无 `paramEnums/paramAllowNull` 入口。
