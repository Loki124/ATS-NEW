# 校招管控（人员比例管控系统）需求说明文档

> 版本：v2.4 ｜ 文档日期：2026-08-23
> 适用范围：腾讯招聘 / 人才管理系统（ATS-NEW）校招管控模块
> 配套文档：《校招管控技术文档》

---

## 1. 背景与目标

校招过程中，企业为达成人才结构目标（如院校背景、专业方向、性别比例的合理分布），需要一套可对**人员比例**与**管控人数**进行**配置—核算—预警—录入拦截**的闭环管理系统。

系统目标：

1. **可视配置**：以「维度→指标」组织管控口径，每条规则独立配置适用范围与管控目标。
2. **实时核算**：基于人员主数据实时计算各指标的实际占比与人数缺口。
3. **分级预警**：按控制强度（硬约束 / 软约束 / 仅提示）对超标进行分级处置。
4. **录入前置校验**：在录入候选人环节，依据已配置规则预判是否超标并给出处置建议。
5. **批量与导入导出**：支持批量配置、Excel 导入导出，降低大规模规则维护成本。

## 2. 用户角色

| 角色 | 职责 | 典型操作 |
|---|---|---|
| 校招管理员 | 维护维度 / 指标库 / 规则 / 人员主数据 | 配置比例与人数目标、导入导出规则 |
| HR / 招聘专员 | 查看实时看板、录入候选人或人员 | 录入校验、确认录入 |
| 系统（自动化） | 实时计算与预警 | 占比核算、人数缺口核算、超标判定 |

> 权限：模块接口统一要求 `IsAuthenticated`（JWT 鉴权），写入操作记录操作人（created_by / updated_by）。

## 3. 核心概念与术语

| 术语 | 含义 |
|---|---|
| **维度** | 管控口径分组，如「院校标签」「专业标签」「性别」。可自由新增。 |
| **指标** | 维度下的具体分类，如 985 / 211 / 男 / 工学。指标须归属于某维度。 |
| **适用范围** | 规则的生效范围，由「部门(bu) · 职务(position) · 职级(level)」三者组合定义；三者全空 = **全局**。 |
| **管控规则** | 单一事实来源：一条规则 = 适用范围 + 维度 + 指标 + 规划年度 + 目标占比 + 控制强度 + 人数目标（年度 + 12 个月）。 |
| **目标占比** | 小数 0~1，表示「该指标实际占比的管控上限」（v2.4 起取消下限，以 target 为上限）。 |
| **控制强度** | 硬约束 / 软约束 / 仅提示，决定超标时的处置力度。 |
| **管控人数** | 指标的年度目标人数 + 12 个月度目标人数，直接承载于规则（v2.4 起取消独立人数表）。 |
| **计入核算** | 人员 `counted=true` 才计入比例分母与人数核算范围。 |
| **在途 Offer** | 命中指标且状态为「已 Offer」的人员（视为当前在途，占用未来名额）。 |
| **在途待入职** | 命中指标且状态为「已入职」且招聘月份 = 当前选中月的人员（视为本月计划到岗）。 |

## 4. 功能范围

模块包含 6 个功能页（前端 Tab）：

1. **实时看板（含人数规划）**
2. **规则配置**
3. **指标管理（维度 + 指标库）**
4. **录入校验**
5. （后台）**人员主数据**维护
6. （后台）规则 **导入 / 导出 / 模板**

### 4.1 实时看板（占比管控 + 人数达成合并视图）

**目标**：在一个页面内同时呈现「比例是否超标」与「人数是否达成」。

**KPI 卡片（5 张，单行）**

| 指标 | 说明 |
|---|---|
| 计入核算人数 | 全部 `counted=true` 的人员总数 |
| 管控规则数 | 当前规则条数 |
| 硬约束超标 | 状态≠正常且强度=硬约束的规则数 |
| 软/仅提示超标 | 状态≠正常且强度≠硬约束的规则数 |
| 本月总缺口 | 各规则「本月目标 − 本月实际」之和（仅计正数缺口） |

**合并数据表（mergedColumns）**，每行 = 一个「适用范围 · 维度 · 指标」组合：

- **占比管控**（来自实时看板）：实际/分母、占比、目标、占比状态、强度
- **人数达成**（来自人数规划，随年份/月份联动）：在职、在途 offer、在途待入职、年度目标、年度缺口、本月目标、本月实际、缺口、人数状态

**年份 / 月份选择器**：切换即刷新下方人数达成部分（比例核算与年份无关，始终基于全量人员）。

**占比状态**：实际占比 > 目标占比 + 容差(0.0001) → 高于上限；否则正常。
**人数状态**：本月实际 ≥ 本月目标 → 本月达标；否则缺口未达成；未设目标（目标为空）→ 未设目标。

> 当存在「同一适用范围+维度下目标占比之和 ≠ 100%」时，页面顶部给出黄色告警，提示前往规则配置补全。

### 4.2 规则配置

**目标**：维护管控规则（单一事实来源），支持单条增删改与批量配置，并提供 Excel 导入 / 导出 / 模板下载。

**列表字段**：适用范围、维度、指标、规划年度、占比(%)、年度目标、本月目标（当前月）、控制强度、操作（编辑 / 删除）。
> v2.4 起列表**不再展示「月度合计」列**，避免与年度目标冗余。

**单条规则编辑**：可设定适用范围、维度、指标、规划年度、目标占比(0~100%)、控制强度、年度目标人数、12 个月度目标。

**批量配置（居中弹窗）**：
- 选择维度 → 设定「年度总人数（管控人数）」与「规划年度」
- 勾选多个指标，分别设定「目标占比(%)」与「控制强度」
- 每条指标自动派生：年度目标人数 = round(年度总人数 × 目标占比)；12 个月度目标可手工填或「均分年度目标」
- **硬性约束**：同一「适用范围 + 维度 + 规划年度」下，所有指标的目标占比之和必须 = 100%

**导入 / 导出 / 模板**：

| 操作 | 说明 |
|---|---|
| 导出规则 | 将全部规则导出为 xlsx（列结构与模板一致） |
| 下载模板 | 下载含表头 + 示例行 + 填写说明的 xlsx 模板 |
| 导入规则 | 上传 xlsx，按「适用范围 + 维度 + 规划年度」分组解析校验，事务原子替换；返回成功条数与行级错误 |

**导入校验规则（行级 + 组级）**：
- 维度须为系统已有维度；指标须属于该维度
- 部门 / 职务 / 职级非法枚举拦截
- 目标占比(%) 须为 0~100 数值
- 控制强度须为 硬约束 / 软约束 / 仅提示
- 12 个月目标之和须 = 年度目标人数
- 同一「适用范围 + 维度 + 规划年度」组内，所有指标目标占比之和须 = 100%

### 4.3 指标管理（维度 + 指标库）

**目标**：维护可复用的维度与指标体系。

- **维度**：名称唯一，可启用 / 停用。
- **指标**：归属于某维度，名称在维度内唯一（`(dimension, name)` 唯一）。
- 前端提供「管理维度」与「新增指标」入口；指标删除需谨慎（规则引用时不可删）——当前由数据库外键级联处理。

### 4.4 录入校验

**目标**：在录入候选人为人员前，预判其是否会触发比例 / 人数超标。

**录入草案字段**：人员编码、姓名、部门、职务、职级、院校标签、性别、专业标签、招聘月份、状态。

**校验逻辑**：
- 将草案视为「额外一人」叠加到人员集合中
- 命中所有匹配规则（适用范围匹配 + 指标匹配）
- 计算每条规则的「模拟占比」与「本月模拟人数」
- 给出判定结论：
  - ❌ 阻断提交：命中硬约束超标
  - ⚠️ 允许提交但需关注：命中软/仅提示超标，或本月人数缺口
  - ✅ 通过：均未触发
- 「确认录入」将草案写入人员主数据（仅当未阻断时）

### 4.5 人员主数据（后台维护）

一行一人，字段：人员编码、姓名、部门、院校标签、性别、专业标签、招聘月份、状态、职务、职级、计入核算(counted)。
`counted=false` 的人员不计入任何核算（分母与人数均排除）。

## 5. 业务规则与边界约束

### 5.1 适用范围语义

- `bu / position / level` **三者全空 = 全局**（不限定）。
- 任一字段非空，则按字段值精确匹配人员；空字段表示「该维度不限」。
- 例：「部门=能电BG，职务空，职级空」= 仅约束能电BG 全部职务职级；「全空」= 约束全员。

### 5.2 占比 100% 加和约束

- 同一「适用范围 + 维度 + 规划年度」下，所有指标的 `target` 之和必须 = 1.0（100%）。
- 容差：0.0001（规避 2 位小数百分比的舍入毛刺）。
- **单条编辑**：仅拦截「超过 100%」（防溢出）；恰好 =100% 由批量端点保证完整加和。
- **批量 / 导入**：强校验「必须 = 100%」，否则整体拒绝（400）。

### 5.3 人数目标一致性

- 每条规则的 `annual_target`（年度目标人数）= round(年度总人数 × 目标占比)。
- `monthly_targets`（12 个月度目标）之和必须 = `annual_target`。
- 未传月度目标时，后端按年度目标 **均分到 12 个月**（余数前几个月各 +1）。
- 导入时若月度之和 ≠ 年度目标，行级报错。

### 5.4 管控上限语义（v2.4 取消上下限）

- 以 `target` 为占比管控上限：实际占比 > target + 容差 → 超标。
- 不再区分「低于下限」，避免过度约束。

### 5.5 唯一性

- 规则唯一键：`(bu, position, level, dimension, indicator, year)`。
- 维度名称唯一；指标 `(dimension, name)` 唯一；人员编码唯一。

## 6. 关键流程

### 6.1 配置到预警的闭环

```
维护维度/指标 → 批量或单条配置规则（含人数目标）
     ↓
实时看板自动核算（比例 + 人数）
     ↓
超标规则按强度分级标红 / 告警
```

### 6.2 录用录入校验前置

```
填写候选人为录入草案
     ↓
录入校验（模拟叠加 + 命中规则）
     ↓
❌ 阻断 / ⚠️ 关注 / ✅ 通过
     ↓
确认录入 → 写入人员主数据 → 实时看板数据更新
```

### 6.3 规则批量维护（Excel）

```
下载模板 → 按表头填数据（示例行参考）
     ↓
导入（解析 + 行级/组级校验）
     ↓
成功：按组事务替换；失败：返回错误明细，不落库
```

## 8. 非功能性要求

- **鉴权**：所有接口 `IsAuthenticated`（JWT）。
- **审计**：模型继承 `FullAuditModel`，记录 created_by / updated_by / 时间戳。
- **数据一致性**：导入 / 批量以事务（`transaction.atomic`）原子替换，避免半成功状态。
- **前端响应契约**：列表接口返回 `{success, data[], pagination}`；@action 返回 `{success, data}`；Decimal 字段以字符串传输，前端统一转 number。

## 9. 已知边界与待确认项

1. **在途待入职口径**：当前按「招聘月份 = 当前选中月且状态=已入职」近似。若未来有独立「到岗日期」字段，应改为「到岗日期 > 今天」。
2. **历史脏数据**：库中存在「月度目标之和 ≠ 年度目标」的存量规则时，导出文件再导入会失败；需先在数据侧归一化（dev 库已修复示例）。
3. **指标删除约束**：规则引用中的指标删除依赖外键级联，建议在 UI 层增加引用检查提示。
4. **prod 库数据修正**：prod 库若存在同类月度不一致数据，建议在迁移或初始化脚本中加归一化守卫。
