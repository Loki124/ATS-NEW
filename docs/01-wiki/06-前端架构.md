## 2. 路由与 RBAC 守卫

`src/router/index.ts`：

- 全部业务页面懒加载（`import()`）。
- 路由 meta：`requiresAuth`（需登录）、`roles`（角色白名单）。
- 守卫逻辑（L190-240）：
  1. `to.matched.some(r => r.meta?.requiresAuth)` → 未登录跳 `/login`；
  2. `meta.roles` 白名单校验，`SUPER_ADMIN` 始终放行；
  3. 无权限 → `/forbidden`。
- 主要路由组：dashboard、demands、announcements、positions、candidates（含 addCandidate 三步向导）、screenings、interviews、offers、onboardings、talent-pool、resumes、invitations、referral、notifications、settings/*（30+ 子页）、login、forbidden、404。

### 启动流程（`src/main.ts`）

```
createApp → 注册 Pinia / Router / NaiveUI
→ 恢复 theme store（brand 色 / 暗色模式）
→ 从 localStorage rehydrate user + token
→ 有 accessToken 则 await fetchMe()（服务端重校验用户）
→ mount('#app')
```

### 请求基础设施（`src/api/auth.ts`）

- axios 实例统一 base `/api/v1`；
- 请求拦截器注入 `Authorization: Bearer <access>`；
- 响应拦截器：401 → refresh token → 重放原请求；刷新期间的其他请求进入等待队列；refresh 失败 → logout；
- GET 去重：`utils/request-dedup.ts` 按 method+url 缓存 pending Promise。

## 6. 构建与工程化

### vite.config.ts 要点

- 端口来自 `src/config`（dev 5212），proxy：`/api/v1` 与 `/media` → `config.backend.url`（默认 `http://localhost:8000`）。
- 分包（`manualChunks`）：`vendor-rich-editor`（wangeditor）、`vendor-naive-ui`、`vendor-vue`（vue/pinia/router）、`vendor-icons`、`vendor-unocss`、src utils/api 独立 chunk。
- target ES2022。

### package.json scripts

| 命令 | 作用 |
|---|---|
| `npm run dev` | dev server :5212 |
| `npm run build` | `vue-tsc` 类型检查 + vite build → `dist/` |
| `npm test` | vitest（happy-dom） |
| `npm run lint` / `lint:ci` | ESLint 9（CI 硬门禁） |
| `npm run e2e` | Playwright |

### 主题系统

`stores/theme.ts` 持久化 brand 色/暗色模式；`App.vue` 将 `brandHex/brandHoverHex/brandPressedHex` 映射到 NaiveUI `themeOverrides`（primary、table、input、button、text、border 等全局字段）。

### 角色工具（`utils/role.ts`）

`ROLE_PRIORITY` 定义角色优先级；`deriveRoleType(roles)` 从后端角色列表推导主角色，简化 UI 与路由判断。
