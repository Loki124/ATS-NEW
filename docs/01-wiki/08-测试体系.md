### 2.4 CI 等价命令（隔离区已代码内化）

> **2026-10-08 更新**: 原 GitHub 仓库级 `QUARANTINE` 环境变量（承载 9 条 `--deselect`）**已废弃**。
> 那份名单不在代码库内、无法审计，9 条里已自愈的会被无限期静默跳过。现改为代码内 marker：
>
> - 隔离某用例：在其上加 `@pytest.mark.quarantine`，并把完整 nodeid 登记进
>   `apps/django/tests/test_quarantine_guard.py` 的 `QUARANTINED_TESTS` 列表（隔离区唯一真相源）。
> - CI 等价命令：`pytest -m "not quarantine"`（见 `.github/workflows/ci.yml` 的 test-backend job）。
> - 双向守卫：`tests/test_quarantine_guard.py` 会校验「挂了 marker 的用例是否都登记」「隔离项是否仍真的失败」——
>   自愈的用例若还挂着 marker，守卫测试**硬失败**，逼你解除隔离（防止单向守卫腐烂）。
> - 覆盖率门禁：CI 已加 `--cov=apps --cov-fail-under=70`（阈值见 `COV_MIN`），配套 `apps/django/.coveragerc`。

```bash
# CI 等价（隔离区排除 + 覆盖率门禁）
cd apps/django && .venv/bin/activate
pytest --tb=short -v --maxfail=10 -m "not quarantine" --cov=apps --cov-fail-under=70

# 本地只想跑单测（不统计覆盖率）
pytest -m "not quarantine" -q
```

## 6. 测试编写约定（从现有测试提炼）

1. **FSM 对象刷新必须重新 `get()`**——`refresh_from_db()` 会对 protected FSMField 赋值抛 `AttributeError`（各 test 文件均有 `_reload()` helper）。
2. **不可达状态测试**用 `queryset.update()` 直写库绕过 FSM 描述符。
3. **审计断言**需显式传 operator（BUG-6 后）。
4. **权限测试**：V2 用 raw SQL fixture 造角色，勿依赖 ORM 信号。
