## 0. 一句话结论

目标站是一个 **25 视图 / 5 角色** 的校招生全生命周期系统。其中
**「人员管理 / 轮岗安排 / 轮岗资源 / 数据统计 / 批次规则」有真实业务数据支撑**（源自《校招生轮岗管理.xlsx》878 人 + 《基地轮岗资源盘点》直播间台账），

## 2. 系统总览

### 2.1 技术形态

- **前端**：零框架原生 JS（ES5），字符串拼 HTML + `onclick` 事件委托；`localStorage` 持久化（键 `campus_hr_db_v22`），列宽偏好键 `campus_hr_colw_v1`，会话键 `campus_hr_user` / `campus_hr_token`。

### 4.1 总览

#### `dashboard` 工作台
- **按角色渲染**五套工作台（`views1.js:33`）：
  - 校招生：当前轮岗部门 / 7月综合排名 / 必修课完成数 / 累计综合均分 四卡 + 当前轮岗卡片（部门·导师·起止·剩余天数）+ **待办提醒**（月度自评未上报 / 必修课未完成 / 双选志愿未填报）。
  - 班主任：分管校招生数 / 待核对月度数据 / 本月迟到人次 / 双选在招岗位 四卡 + **我的班主任考核排名摘要**（名次/班级累计均分/学生综合排名均值/最优维度）+ 最新排名 + 待核对数据表。
  - 导师：徒弟数 / 累计反馈记录 / 考核数据条目 / **本月待反馈徒弟数** + 我的徒弟表（详情 / 记录反馈）。
  - HRBP：分管范围 + 待定岗名单 + 定岗进度 + 人才市场。
  - 管理员：全校概览 + 异常清单 + 批次分布 + 定岗进度。
- **待办提醒是按数据缺口反推的**（`m8.status !== '已核对'` / 必修课 `progress < 100` / `!selFlowStarted(batch)`），不是静态待办表。

- 列：校招生 / 工号 / 届数·班级 / 校招批次 / 学校·专业 / 当前轮岗 / 导师 / 班主任 / 标签 / 累计均分 / 操作。
- 筛选：搜索（姓名·工号·学校，工号支持原始号 `8740` 与展示号 `0008740` 两种写法）/ 届数 / 批次 / 班级 / 轮岗部门。
- 新增·维护弹窗字段：姓名、性别、毕业院校、专业、学历、届数、校招批次、班级、班主任、入职日期、联系电话、状态（轮岗中/待定岗/已定岗/已离职）、**标签**（多选 chip）。

#### `assessment` 轮岗考核 **[空]**（`views2.js:167`）

#### `feedback` 反馈记录（`views2.js:755`）
- 4 卡：总数 / 处理中 / 已解决·已闭环 / 含证据记录。
- 页签：全部 / 问题·情况记录 / 导师带教反馈；搜索姓名·内容·分类。
- 列：日期 / 校招生 / 记录人 / 类型 / 描述 / 处理方式 / 状态 / 证据 / 操作（详情、办结）。
- 状态机：`处理中` → `已解决` / `已闭环`；mentor 可见范围 = 自己带的徒弟。

#### `selection` 定岗双选（`views2.js:1178`）
- 页签：岗位池 / 需求审核 / 志愿推送 / 竞价大厅 / 人才市场 / 双选进度 / 绩效展示。
- **岗位开放判定顺序**（`views2.js:799`）：审核状态 → 开放开关 → 发布范围（按意向部门/届数）→ 面向届数/班级 → 窗口期。
- 发布范围三档：`all` 全部 / `batch` 按届数 / `intentDept` 按学生意向部门。
- **双选撮合状态机**（`views2.js:1152`）：
  ① 校招生填报 N 个志愿（默认 2，可按批次覆盖）
  ② 撮合启动后**第一志愿推送至岗位所属业务BP**
  ③ BP 录取 → 后续志愿自动释放；BP 放弃 → 下一志愿自动推送
  ④ 两志愿均未被选 → 进入**人才市场**，全员 BP 可选
  ⑤ 仍未被选 → 班主任/管理员**指定分配**
  ⑥ 管理员发布双选结果

## 7. 补齐方案建议

### 方案 A（P0 优先，推荐）
按 P0 四项落地：批次规则引擎（后端模型 + API + 前端页）、异常/反馈记录、轮岗资源测算口径、待分配确认闭环。
- **收益**：全部有真实数据可验证，与本仓既有模块（campus_control / campus_rotation）无缝衔接，不引入空壳功能。
- **代价**：4 个子功能，估 3–5 人日。

### 方案 B（P0 + P1）
在 A 之上追加轮岗考核全套（月度数据 + 模板 + 多维排名 + 班主任排名）、试用期、月报、考勤。
- **收益**：补上目标站「考核与定岗」主干，与档案详情里现在返回空数组的「轮岗期月度考核明细 / 日报及评价」接上（见 S5-53 留白 N-01）。
- **代价**：约 8–12 人日，且需要业务侧确认考核模板维度与权重。

### 方案 C（全域移植）
在 B 之上追加课程/考试/论坛/活动/双选/结算。
- **收益**：功能面与目标站对齐。
- **代价**：约 20–30 人日；且目标站这些板块**本身无真实数据**，等于照着空壳做设计，有返工风险。
