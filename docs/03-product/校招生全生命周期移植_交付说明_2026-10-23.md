## 4. 影响面（如实告知）

### 4.1 人员主数据从 56 → 934

导入 878 名历史校招生后，`campus_control.Person` 由 56 条增至 934 条。

**连带影响**：本仓 **28 条全局管控规则**（`ControlRule.bu` 为空 = 适用全部部门）的样本量随之从 56 变为 934，
性别/院校/专业比例类规则的**结论会变化**。这是「导入全部真实校招生主数据」这一决策的必然结果，
不是缺陷；如需保持管控结论不变，应对导入数据设置 `counted=False`（不计入核算）——
**本次未擅自设置**（导入的是真实在职人员，`counted=True` 更贴近事实），是否调整由业务侧决定。

### 4.2 部门枚举扩容

`campus_control.constants.DEPTS` 由 4 档扩为 7 档（补 `能人BG` / `能智BG` / `能本BG`）。
依据：源数据 878 人中 139 人落在这三个真实存在的 BG；归入「综合BG」= 事实错误。
既有 4 档顺序**未变**，既有管控规则的目标 BU **不受影响**；新增 BG 暂无专属规则。

### 4.3 新增 195 个不可登录账号

名册导入创建的 `core.User` 密码不可用 —— 只用于「人 - 档案」关联与数据隔离，不构成可登录账号。

### 5.6 过程中的环境问题（如实记录，非代码缺陷）

- **测试库授权（真正的根因，先于「库脏」）**：本机 MySQL 8 已移除 `automatic_grants`，
  `ats_dev` 账号**只对少数几个库有 ALL 授权**（`ats_dev` / `ats_test` / `test_ats_test` /
  `test_ats_t03_ci` / 若干历史排查库），**新建测试库不会被自动授权**。
  ⇒ 用 `DB_NAME=<新库名>` 造测试库会在 setup 阶段报
  `SELECT command denied to user 'ats_dev'@'localhost' for table 'django_migrations'`，
  表现成「整轮用例全 error（149 errors）」，看起来像代码炸了，实则**一条用例都没跑到**。
  ⇒ **可用解法**：`DB_NAME=ats_test`（Django 会把测试库命名为 `test_ats_test`，该库有授权）→
  `DB_NAME=ats_test pytest ... -q -p no:randomly` ⇒ **149 passed**。
  ⇒ 另注：本机 `ats_dev` 无 GRANT OPTION，**无法自行给新测试库授权**；
  且 MySQL 的库级授权在 `DROP DATABASE` 后仍保留授权行，但库需要重建。
- **共享测试库被并行施工弄脏**：并行会话用 `--no-migrations` 跑过（建表但不写 `django_migrations`），
  导致 `test_ats_test` 残留表且缺迁移记录 → `--create-db` 也会在 migrate 时撞
  `Table 'django_celery_beat_crontabschedule' already exists`。
  **处置**：显式 `DROP DATABASE test_ats_test` 让 pytest 重建（授权行仍在，重建后可用）。
  ⇒ 教训：**并发跑 pytest 必须各用各的测试库名**（仓库 pytest.ini 固定 `--reuse-db`，不隔离），
  且新建库前先确认 `SHOW GRANTS` 里有没有它。
- **导入撞唯一约束**：另一个会话在并行导入同一批名册 → `Duplicate entry '谭定刚' for key 'core_user.username'`。
  **处置**：导入命令改为并发安全（建号前复查 username；撞 1062 复用已有行；人员取号在事务内加锁）。
- **工号二次补零**：反馈/待分配导入把**已是 8 位**的 `Person.employee_id` 又补了一次零（`25025008`）
  → 49 条反馈全部「找不到校招生」。**处置**：直接取库里的 8 位工号，不再补零。

### 6.3 两个「静默失效」类缺陷（值得单列）

1. **「学习成长」维度被算成全体均值** —— 单测全绿、页面能渲染、排名也能出，但**每个人的学习成长值相同**
   ⇒ 综合排名的 30% 权重项是常数。**这类缺陷静态门禁零信号**，只有逐字段对照契约 + 逐算法对照逆向清单才能发现。
2. **restore 越权** —— 列表接口的隔离是对的（`get_queryset` 收窄），但 `restore` 动作换了 queryset 源
   ⇒ **同一个 ViewSet 的两条路径隔离口径不一致**。「隔离写在 `get_queryset` 里」是不够的，
   必须同时提供 `scope_queryset` 钩子 —— 这一点已写进 `campus_control/visibility.py` 与三 app 的注释。
