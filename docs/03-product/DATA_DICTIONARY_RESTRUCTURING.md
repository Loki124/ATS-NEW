## 1. 重组前现状

| 数据 | 旧位置 | 旧角色 |
|------|--------|--------|
| 币种 / 行业 / 学历 / 学位 / 语言 等 | `apps/code_table`（码表库） | 标准只读 |
| 业务码表（招聘渠道 / 简历来源 等） | `apps/code_table`（码表库） | 业务可维护 |
| 系统级枚举（阶段类型等） | `apps/dictionary`（数据字典） | 系统固定 |

### 1.1 痛点
- 「标准 vs 业务」混在同一库，难统一管理。
- 数据字典承载了「系统固定值」（阶段类型），与「业务可配置值」语义冲突。
- 多个菜单入口散落（码表 / 数据字典 / 系统级），用户找数据要 3 跳。

## 2. 重组后结构

```
基础数据（顶级菜单）
├─ 静态数据（cm/dict）
│  ├─ 码表库（标准只读，apps/code_table）
│  │  └─ 币种 / 行业 / 学历 / 学位 / 语言 等
│  └─ 数据字典（业务可配置，apps/dictionary）
│     ├─ 招聘渠道（19 项）
│     ├─ 简历来源（10 项）
│     └─ ...
└─ 动态数据
   └─ 字段定义 / 自定义选项 / ...
```

### 2.1 数据字典分层

| 层级 | 例 | 维护方式 |
|------|----|----------|
| **标准码表**（只读） | 币种 / 行业 / 学历 / 学位 / 语言 | 迁移预置 `get_or_create`，UI 灰显 |
| **业务码表**（可维护） | 招聘渠道 / 简历来源 / 婚姻状态 / 政治面貌 | 数据字典 UI 增删改 |

### 2.2 系统级枚举走「系统内置」（兵哥 2026-09-20 定调）

- 阶段类型 / 起止阶段 / 任何"系统固定且不可由用户增删"的枚举。
- 详见 `docs/06-runbook/ENGINEERING_RULES.md` §7。
- 实战：阶段类型不再进 DictionaryItem，改 `StageType` 枚举 + 迁移 0012 预置。
- 详见 `docs/05-campus-control/STAGE_TYPE_SYSTEM.md`。

## 6. 与「系统内置」的边界（最重要）

> 🔴 数据字典（`apps/dictionary`）只承接「业务可配置」的枚举，不承接系统固定值。
> 🔴 系统级固定枚举一律走代码 `TextChoices` + 迁移预置。

### 6.1 反例（已修）
- 阶段类型原本进 DictionaryItem → 改 `StageType` 枚举 + 迁移 0012 预置 + 字典项 0013 软删退出。

### 6.2 决策法门
**问：这条枚举是「业务可配置」还是「系统固定」？**
- 业务可配置（HR 可增删改）：数据字典。
- 系统固定（不可由用户增删）：代码枚举 + 迁移预置。
- 不确定：默认走「业务可配置」，后续如发现实际不可改再迁。
