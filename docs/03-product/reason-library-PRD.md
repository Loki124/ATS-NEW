## 1. 产品概述

### 1.1 一句话定位

> **原因库是 ATS 的「人才归因配置中枢」**——把「为什么淘汰这个候选人」「为什么取消这次面试」这类业务判断依据，从散落在各个业务页面的前端写死文案，收敛为一个**统一维护、配置即生效、可追溯可回退**的原因体系。

### 1.2 产品结构

```
┌─────────────────────────────────────────────────────────────┐
│  原因标签池 (reason_tag)                                      │
│  全局唯一的原因词汇表：系统预置 53 条 + HR 自建               │
└───────────────┬─────────────────────────────────────────────┘
                │ 挂载
┌───────────────▼─────────────────────────────────────────────┐
│  场景规则 (scene_rule)                                        │
│  一棵 ≤4 层的分类树 + 每分类挂载若干原因标签                  │
│  + 版本快照（每次变更留痕，可回滚）                          │
└───────────────┬─────────────────────────────────────────────┘
                │ 绑定「在哪个业务节点、对哪类招聘生效」
┌───────────────▼─────────────────────────────────────────────┐
│  业务归因场景 (scene × recruit_type)                          │
│  简历筛选不通过 / 取消面试 / 放入人才库 / 淘汰 / 标记失败 / 邀约标注 │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 要解决的问题

| # | 现状痛点 | 造成的业务后果 |
|---|---|---|
| P-1 | 归因原因写死在前端代码里 | 改一句文案要发版，业务方无法自助调整 |
| P-2 | 同一原因在不同业务节点重复维护、措辞不一致 | 数据口径分裂，管理层看不懂汇总归因 |
| P-3 | 缺少统一的归因选项，不同节点选项数随意 | 业务方随手选，归因数据无法用于分析 |
| P-4 | 配置变更无留痕，误操作无法恢复 | HR 不敢改，改错只能提研发工单 |
| P-5 | 一个节点被多条规则覆盖，优先级不明 | 同一场景归因结果不可预期 |

### 1.4 当前交付状态（诚实评估）

| 侧 | 状态 | 说明 |
|---|---|---|
| **配置侧** | ✅ 已交付 | 标签池、规则 CRUD、三步向导、场景绑定、版本快照与回滚、生效查询 API 全部可用 |
| **业务端消费** | ⬜ **未接入** | `GET /active/?scene=` 接口与前端 `getActiveRule()` 已就绪，但简历筛选 / 淘汰 / 取消面试等业务页面**尚未调用**，归因弹窗未在实际流程中生效 |

> ⚠️ **这是本模块当前最大的产品缺口**：配置侧做得再好，业务端不取用则价值为零。已列为 P0 遗留项（§6.2 P0-6）。

## 2. 目标用户

### 2.1 用户角色画像

原因库服务两类本质不同的用户：**配置者**（少数）与**使用者**（多数）。产品设计必须同时服务好两者，但侧重点不同。

| 角色 | 系统角色码 | 人群规模 | 在原因库中的身份 | 核心诉求 |
|---|---|---|---|---|
| **HRBP / 招聘负责人** | `HRBP` | 数十人 | **主要配置者** | 快速搭建符合本部门归因口径的原因体系；调整时不用求人 |
| **HR / 招聘专员** | `HR` | 数百人 | **次要配置者 + 日常使用者** | 维护日常新增的原因；标注候选人时快速选到合适的项 |
| **用人部门负责人 / 面试官** | `INTERVIEWER` 等 | 数千人 | **纯使用者** | 归因选项要好懂、好选，不要被无关选项干扰 |
| **系统管理员** | `SUPER_ADMIN` / `ADMIN` | 个位数 | **规则守护者** | 维护系统预置词表；防止误删导致全局配置损坏 |
| **数据 / BI 消费方** | 系统 | — | **数据消费者** | 归因字段口径稳定、可跨场景聚合 |

### 2.3 典型用户旅程

**旅程 A：HRBP 首次搭建某业务线的归因体系（首次配置，约 15 分钟）**

```
进入「设置 → 原因库」
  → 切到「原因标签」页签，发现系统预置标签不够用
      → 新建自定义标签（如「岗位已关闭」「薪资不匹配」）
  → 切到「场景规则」页签，点击「新建规则」
      → Step1 搭分类树：学历要求 / 专业要求 / 经验要求
      → Step2 给末级分类挂标签
      → Step3 配置应用范围：场景「筛选不通过」× 类型「社会招聘」，并预览效果
      → 保存（自动生成 v1 版本快照）
  → 期望：业务端「简历筛选」页面立即出现这组归因选项
```

**旅程 B：HR 日常新增一个归因原因（高频，约 1 分钟）**

```
「原因标签」页签 → 搜索确认不存在同名标签 → 新建标签（填名称 + 提示语）
  → 到规则向导 Step2 的标签选择器里勾选它
  → 保存
  → 期望：该标签立刻出现在业务端选择弹窗里
```

**旅程 C：口径调整，想下线一个规则（低频）**

```
「场景规则」页签 → 找到规则 → 先在「配置规则」中解除场景绑定
  → 关闭启用开关
  → 期望：业务端不再出现该规则的归因选项；配置仍保留可随时恢复
  → ❌ 不再提供删除入口（详见 §13.3）
```

**旅程 D：配置被改坏，回退（异常兜底）**

```
打开规则 → 「历史版本」 → 查看变更字段与操作人
  → 「回滚到此版本」→ 确认
  → 期望：配置回到历史状态，且本次回滚本身也被记录为一个新版本
```

## 3. 核心使用场景

### 3.1 六大业务归因场景

原因库服务于招聘全链路的六个「需要给候选人打标签」的业务节点：

| # | 场景标识 | 业务含义 | 典型归因选项示例 |
|---|---|---|---|
| 1 | `筛选不通过` | 简历初筛被拒 | 学历不符 / 专业不符 / 经验不符 / 岗位已关闭 |
| 2 | `取消面试` | 已约面试后取消 | 候选人时间冲突 / 薪资不匹配 / 岗位冻结 / 找到更优人选 |
| 3 | `放入人才库` | 暂时不合适但留作储备 | 经验不足 / 行业不符 / 学历不符 |
| 4 | `淘汰` | 面试后淘汰 | 能力不匹配 / 沟通表达差 / 稳定性差 / 薪资期望过高 |
| 5 | `标记失败` | 流程执行失败 | 到面未到 / 联系方式失效 / 候选人拒绝 |
| 6 | `邀约标注` | 邀约环节标注 | 时间不合适 / 意向岗位不符 / 薪资不达标 |

**两个正交维度**：每个场景还可按招聘类型区分（`社会招聘` / `校园招聘`），使规则的应用范围可以细到「校园招聘的取消面试」这一粒度。

### 3.2 核心场景剧本（User Story）

| ID | 作为 | 我想要 | 以便 | 验收要点 |
|---|---|---|---|---|
| **US-1** | HRBP | 为「校园招聘的简历筛选」单独配置一套原因体系 | 不影响社招口径 | (场景,类型) 组合独立绑定，互不干扰 |
| **US-2** | HR | 在标签池里新增一条原因，几分钟内让业务端可用 | 不必提研发工单 | 保存后生效查询立即命中，无发版 |
| **US-3** | 使用者（面试官） | 打开选择弹窗只看到与当前业务相关的分类和选项 | 不被几十个无关选项干扰 | 生效优先级：显式绑定 > 预置默认规则 |
| **US-4** | HRBP | 把误配的规则下线 | 立即止损 | 停用即时生效，配置不丢失 |
| **US-5** | HRBP | 误操作后一键回到昨天的配置 | 不敢改的心结被解决 | 版本快照完整，回滚可再回滚 |
| **US-6** | HR | 把一套成熟规则复制一份改成新业务线用 | 不从零搭 | 副本接管原场景绑定，独立可编辑 |
| **US-7** | HRBP | 把本部门配置导出，在测试环境验证后再导入 | 环境间迁移 | JSON 导入导出闭环 |
| **US-8** | 超级管理员 | 保证系统预置词表不被业务方改坏 | 全局口径可控 | 系统标签/规则仅超管可改，不可删 |

### 3.3 场景 → 规则的生效规则

```
业务端请求「场景 S」
      │
      ├─ 有显式绑定该场景(及类型)的规则？ ──是──► 取 updated_at 最新的那条
      │                                              （显式绑定 > 预置默认）
      └─ 否 ──► 回落「预置默认规则」（全局仅一条，覆盖所有场景 × 类型）
                 └─ 也没有 ──► 返回空（业务端不展示归因选择）
```

> 该优先级规则保证了：**任何时候业务端都能拿到一组可用的归因选项，不会因为运营漏配而卡住主流程**。

## 4. 产品价值主张

### 4.1 价值主张陈述

| 面向 | 价值主张 |
|---|---|
| **对 HRBP / HR** | 「归因体系你说了算」——不用排研发、不用等发版，配置保存即刻在业务端生效 |
| **对使用者（面试官 / 业务方）** | 「只给你该选的选项」——按业务场景与招聘类型精准下发归因范围，不必在几十个选项里翻找 |
| **对管理者** | 「口径统一、可追溯」——跨场景归因数据可聚合，配置变更全程留痕，可回退可审计 |
| **对系统 / 研发** | 「配置与代码解耦」——文案与规则调整不再产生发版需求，降低研发负荷与线上风险 |

### 4.2 价值量化

| 指标 | 改造前 | 改造后（目标） |
|---|---|---|
| 新增一个归因原因的上线耗时 | 提工单 → 研发改代码 → 测试 → 发版，**按天计** | 页面自助配置，**按分钟计** |
| 同一原因跨场景一致性 | 靠人工同步，易漂移 | 标签池单一来源，天然一致 |
| 配置误操作恢复成本 | 不可恢复，需研发捞数据 | 一键回滚到任意历史版本 |
| 归因数据可分析性 | 文案不统一，难以聚合 | 标签 ID 化，BI 可直接按标签聚合 |
| 规则变更风险 | 硬删除，级联丢失分类与历史 | 只增不删 + 版本可回滚，风险趋零 |

### 4.3 竞争性差异（相对通用做法）

| 维度 | 通用做法 | 原因库 |
|---|---|---|
| 归因粒度 | 单一场景维度 | **场景 × 招聘类型**二维，粒度更细 |
| 变更生效 | 跟随发版 | 配置保存即时生效（缓存主动失效） |
| 变更追溯 | 无 | 每次语义变更自动落版本快照 |
| 配置安全 | 可随意删除 | **只增不删**，误操作不可能造成数据丢失 |
| 兜底策略 | 未配置则报错/空白 | 预置默认规则兜底，业务流程永不中断 |

## 7. 验收标准

| 原则 | 说明 |

| 可判定 | 每条 AC 必须能通过自动化测试或明确的人工步骤判定，避免「体验良好」式描述 |
| 双端覆盖 | 涉及数据的 AC 必须同时验证后端行为与前端呈现 |
| 失败可见 | 任何失败路径必须有明确用户可见反馈，禁止静默失败 |

## 9. 核心业务规则

| 规则 | 内容 |
|---|---|
| BR-1 生效优先级 | 显式绑定 > 预置默认规则；多条显式绑定取最近更新者 |
| BR-2 唯一归属 | 同一 (场景, 招聘类型) 组合全局仅属一条规则 |
| BR-3 兜底不断流 | 无任何显式绑定时回落预置默认规则；再无则返回空，业务端不展示归因选择 |
| BR-4 分类层级 | 分类树最多 4 层；仅末级分类可挂载标签 |
| BR-5 标签不重复挂载 | 同一标签不可跨分类重复挂载 |
| BR-6 标签全局唯一 | 标签名唯一（含已软删记录，不复用） |
| BR-7 系统预置保护 | 系统预置标签与规则仅超管可改，不可停用、不可删除 |
| BR-8 引用中不可停用 | 被场景引用的规则必须先解除绑定才能停用 |
| BR-9 版本单调递增 | 每次语义变更版本号 +1 并落一条快照，快照不可修改 |
| BR-10 **只增不删** | **场景规则不提供删除能力；下线统一走停用，误操作不可能造成数据丢失** |
| BR-11 预置默认规则唯一 | 全局仅允许存在一条预置默认规则，覆盖全部场景 × 类型 |

## 10. 界面交互要求

### 10.1 布局与滚动

| 要求 | 说明 |
|---|---|
| 区域滚动 | 数据列表页禁止整页滚动；工具栏、统计条固定，滚动仅发生在表格区域 |
| 表头固定 | 表格滚动时表头保持可见 |
| 分页固定 | 分页器固定在表格底部，不随数据滚动 |
| 弹窗滚动 | 仅内容区滚动，标题与操作栏固定 |
| 响应式 | <768px 单列 / 768–1024px 两列 / >1024px 3–4 列限宽；320px 不得横向溢出 |

### 10.2 交互状态完整性

每个数据视图必须覆盖完整状态机：**首次引导 / 骨架加载 / 有数据 / 空态 / 搜索无结果 / 筛选无结果 / 部分失败 / 全部失败 / 离线 / 无权限**。

- 列表加载失败：错误横幅 + 内联「重试」按钮，保留上一次成功数据
- 异步提交期间按钮 `loading` + `disabled`，防止重复提交
- 开关类操作使用乐观更新，失败自动回滚并提示

### 10.3 文案与反馈

| 场景 | 要求 |
|---|---|
| 按钮文案 | 「动词 + 宾语」，中文 2–6 字；禁用「提交 / 确定 / OK」 |
| 人称 | 统一使用「你」 |
| 时间 | 相对时间（3 分钟前）+ hover 显示绝对时间 |
| 加载文案 | 具体化，如「正在保存规则配置…」，不用笼统「加载中…」 |
| 数字 | 使用 `tabular-nums` 防抖动 |
| 语言 | 默认简体中文，用户可见文案使用简体中文；中英语言包 key 严格一一对应 |
| i18n 约束 | 禁止「某 key 恰为另一 key 前缀」的写法（会导致文案被对象节点覆盖而回显 key 原文） |

### 10.4 破坏性操作分级

| 级别 | 操作 | 处理方式 |
|---|---|---|
| 可逆 | 启停标签 / 启停规则 | 直接执行 + 乐观更新，**禁止**确认弹窗 |
| 中等 | 删除分类、向导内移除标签挂载 | 确认弹窗 + 说明具体后果与影响范围 |
| 高 | CSV / JSON 导入覆盖 | 确认弹窗 + 影响预览 |
| 不可逆 | 回滚到历史版本 | 确认框 + 影响预览，且可通过再次回滚回退 |

### 10.5 无障碍

- 所有交互元素可 Tab 访问，焦点顺序与视觉顺序一致，`focus-visible` 有可见轮廓
- 触控目标 ≥ 44×44px（图标按钮视觉 28–32px，命中区用伪元素扩展）
- 错误信息不得仅靠颜色表达，须「图标 + 文字」双通道
- 动态长文本截断并提供 title 或展开查看完整内容

## 12. 异常处理规则

### 12.1 错误三段式

所有用户可见错误必须包含：**① 发生了什么（人话）→ ② 用户数据是否安全 → ③ 至少一个可点击的恢复动作**。技术错误码折叠在「详情」中并支持一键复制，禁止以「抱歉」开头。

> 示例：没连上服务器，你刚才的修改没有丢（草稿已存在本地）。 [重试] [复制错误信息]

### 12.2 业务错误码

| 错误码 | HTTP | 触发场景 | 用户可见文案（zh-CN） |
|---|---|---|---|
| `40000` | 400 | 通用校验失败 | 后端返回的校验说明 |
| `40001` | 400 | 标签同名（含软删记录） | 该标签名已存在（含已删除记录） |
| `40002` | 400 | 导入文件格式非法 | 导入文件格式错误，请检查列名与编码 |
| `40010` | 400 | 规则名重复 | 该规则名已存在 |
| `40011` | 400 | 规则 JSON 导入格式非法 | JSON 导入格式非法 |
| `40030` | 400 | 分类层级超过 4 | 分类层级最多 4 级 |
| `40300` | 403 | 非管理员执行写操作 | 无权限执行此操作 |
| `40301` | 403 | 改 / 停用 / 删系统标签 | 系统预置标签不可修改或停用 |
| `40310` | 403 | 改 / 停用 / 回滚系统规则 | 系统预置规则不可停用或回滚 |
| `40401` / `40410` | 404 | 标签 / 规则不存在 | 标签 / 规则不存在 |
| `40901` | 409 | 删除被引用的标签 | 该标签已被规则引用，不可删除 |
| `40902` | 409 | 同一标签跨分类重复挂载 | 该标签已归属其它分类，不可重复挂载 |
| `40910` | 409 | 停用被场景引用的规则 | 该规则已被场景引用，不可停用 |
| **`40911`** | **409** | **删除已配置内容的规则** | **规则删除功能已下线，该规则已配置内容，请改用「停用」使其不再生效** |
| `40920` | 409 | (场景,类型) 组合被他规则占用 | 该场景已被其他规则占用 |
| `41200` | 412 | 乐观锁冲突（多人协作模式） | 数据已被他人修改，请刷新后再试 |
| `50000` | 500 | 服务端异常 | 服务开小差了，请稍后重试 |

### 12.3 边界与容错

| 场景 | 处理 |
|---|---|
| 列表加载失败 | 错误横幅 + 重试按钮，保留上一次成功数据 |
| 快速切换筛选 | latest-wins 令牌，过期响应丢弃 |
| 搜索输入 | 300ms 防抖 |
| 统计数字 | 基于全量数据计算，不受分页影响 |
| 保存失败（新建） | 自动回滚空规则头，可直接重试 |
| 保存失败（编辑） | 停留当前步骤，保留已填内容 |
| 关闭向导（有未保存改动） | 二次确认，明确提示将丢失内容 |
| 缓存失效 | 保存 / 停用 / 回滚 / 绑定变更后立即失效，保证实时生效 |
| 长文本 | 省略号截断 + title 悬浮查看完整内容 |

## 13. 风险与依赖

### 13.1 依赖关系

| 依赖 | 类型 | 风险 |
|---|---|---|
| 业务端六个归因页面的改造排期 | **强依赖** | 排期不确定将直接导致 P0-6 延期，模块价值无法兑现 |
| 权限体系（角色三档判定） | 内部依赖 | 原因库未接入 V2 权限码，未来权限体系演进时需同步改造 |
| 缓存中间件 | 基础设施 | 缓存失效逻辑失效会导致「配置不生效」的静默故障 |

### 13.2 主要风险

| 风险 | 等级 | 应对 |
|---|---|---|
| 业务端接入长期排不上，配置侧成为空转能力 | **高** | 建议将 P0-6 纳入同一迭代周期交付，最小可用即可（单场景先跑通） |
| 归因数据积累后 BI 未同步口径 | 中 | 同步数据字典，明确「停用规则不计入生效归因」的口径 |
| 规则长期只增不删，数量膨胀 | 中 | 推动 P2-2 归档语义，定期治理 |
| 多人协作时并发覆盖 | 低 | 已预留乐观锁能力，开启开关即可生效 |

### 13.3 已下线能力的影响评估：删除功能

> 决策：**Q-A6**（2026-10-10）场景规则删除功能下线，规则改为「只增不删」。

**决策背景**

| 风险 | 说明 |
|---|---|
| R-1 级联误删不可恢复 | 删除规则会 CASCADE 连带删除分类树、标签分配、场景绑定与全部版本快照，属硬删除，无任何恢复途径 |
| R-2 误删正在生效的配置 | 场景绑定随规则释放，业务端瞬间失去归因选项，该组合可能被他人抢占，历史配置无法找回 |
| R-3 与版本体系自相矛盾 | 模块已具备版本快照与回滚能力，却保留了「一删了之」的旁路，削弱版本体系价值 |

**变更范围**

| 层次 | 变更 |
|---|---|
| 前端 UI | 移除列表操作列删除按钮；删除确认弹窗组件整体下线；操作列 240px → 120px |
| 前端 API | `deleteRule()` → `discardDraftRule()`，语义收敛为「空规则草稿回滚」 |
| 前端 文案 | 下线 4 条删除专用文案；错误码文案去除「删除」语义并新增 40911 |
| 死代码 | 删除无引用的遗留组件 |
| 后端 | `DELETE /rules/{id}/` 收敛为**仅允许删除空规则**；系统规则 403；非空规则 40911；后台禁用删除权限 |
| 测试 | 删除用例改为「已配置规则删除被拒且数据完好」，新增「空规则可回滚」 |

**影响评估**

| 维度 | 影响 | 等级 |
|---|---|---|
| 用户操作习惯 | 不再能删除误建规则，改用停用 | 低（误建场景罕见，停用后可筛选定位） |
| 数据完整性 | **正向**：不再存在硬删除导致配置丢失 | 低 |
| 业务端 | **无影响**：生效逻辑只读取 `enabled=true` 的绑定 | 无 |
| 统计口径 | 停用规则仍计入总数但不再计入生效归因，需 BI 侧按 `enabled` 过滤 | 中 |
| 可追溯性 | **正向**：配置永久留存 + 版本回滚可复现任意历史状态 | 低 |

**唯一保留的技术通道**：向导「新建 → 保存失败」需清理刚创建的空规则头。该通道经双重收敛——前端仅此一个调用点，后端强制「只能删没有任何分类的空规则」，**在产品语义上不可能删除任何已配置的业务规则**。

**替代方案对照**

| 需求 | 原方案 | 替代方案 |
|---|---|---|
| 规则不再需要生效 | 删除 | **停用**（列表开关） |
| 规则建错了 | 删除 | 停用 + 名称加「（已废弃）」后缀 |
| 清理列表噪音 | 删除 | 状态筛选器筛出停用项 |
| 需要找回历史配置 | 无法找回 | **版本回滚** |
| 规则内容重构 | 删除重建 | **复制副本**后编辑副本 |
| 环境间迁移 | 手工重建 | **JSON 导入 / 导出** |
