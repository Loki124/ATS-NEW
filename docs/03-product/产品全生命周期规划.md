# 招聘管理系统（ATS）全生命周期产品规划

> 版本：v1.0　|　范围：需求分析 → 职位发布 → 简历筛选 → 面试安排 → 录用管理 → 入职跟进
> 配套交付：产品架构图（前端门户 / 后端服务 / 数据中台 / 第三方集成四层）
> 说明：本文规划基于 ATS-NEW 现有 33 个后端业务模块与前端页面结构梳理，模块命名尽可能对齐真实系统，便于研发直接落地。

---

## 1. 执行摘要

招聘管理系统（ATS）是连接「业务用人需求」与「人才到岗产出」的核心平台。本规划将招聘业务拆解为 **6 个生命周期阶段**，明确每阶段的核心功能模块、用户角色与业务流程，并给出支撑这 6 阶段运行的 **四层技术架构**（前端门户、后端服务、数据中台、第三方集成）与系统交互关系。

**北极星指标**：**单位时间有效到岗人数（Time-to-Qualified-Hire）**——
在目标周期内，通过本系统完成「需求→offer→入职」闭环且通过试用期的人数，按平均招聘周期归一化。

**三大业务目标**
1. 缩短端到端招聘周期（从需求生效到入职），目标下降 30%。
2. 提升简历→面试转化质量，降低用人经理返工率。
3. 沉淀企业人才资产（人才库复用率 ≥ 25%）。

## 2. 全生命周期总览

```
需求分析 ──▶ 职位发布 ──▶ 简历筛选 ──▶ 面试安排 ──▶ 录用管理 ──▶ 入职跟进
  demand      position      resume       interview      offer        onboarding
  process     channel       candidate    invitation     mou          application
  analytics   referral      screening     automation     approval     gdpr
  entry_      campus_       duplicate_   time_limit     audit        notification
  condition   control       check                       notification  integration
                │                                                      │
                └──────────── 人才库沉淀（talent_pool）双向回流 ────────┘
```

每一阶段产出「移交物」进入下一阶段，并贯穿 **core / field_acl / audit / notification / automation / analytics / integration** 等平台级能力。

---

## 3. 各阶段详细规划

> 每一阶段均包含：**目标 / 核心功能模块 / 用户角色 / 业务流程 / 关键规则与状态机**。

### 阶段 1 · 需求分析（Talent Demand & Workforce Planning）

**目标**：把业务用人诉求转化为可发布、可追踪的招聘需求，并完成编制校验与审批。

**核心功能模块**
| 模块 | 职责 |
|------|------|
| `demand` 招聘需求管理 | 需求提报、编制占用、需求版本、需求看板 |
| `process` 招聘流程引擎 | 需求审批流、流程模板、节点配置 |
| `analytics` 编制与人力分析 | 编制余量、HC 预测、招聘漏斗基线 |
| `dictionary` 数据字典 | 职级/序列/部门/成本中心主数据 |
| `entry_condition` 录用条件 | 学历/经验/薪资区间等录用门槛定义 |

**用户角色**：HRBP（提报）、用人部门负责人 Hiring Manager（确认）、招聘负责人（统筹）、编制管理员/财务（编制校验）。

**业务流程**
1. HRBP 或用人经理在 `demand` 提报需求（岗位/职级/编制/紧急度）。
2. `analytics` 实时校验部门编制余量，超编则阻断或转特批。
3. `process` 按岗位级别路由审批流（直属→招聘负责人→财务/编制）。
4. 审批通过后需求置为「已生效」，自动触发阶段 2 职位创建。
5. 需求看板持续追踪「在招/已招满/已关闭」。

**关键状态机**：草稿 → 待审批 → 审批中 → 已生效 / 已驳回 / 已关闭。

---

### 阶段 2 · 职位发布（Job Posting & Distribution）

**目标**：将已生效需求快速转化为多渠道职位，并接入内推与校招专项管控。

**核心功能模块**
| 模块 | 职责 |
|------|------|
| `position` 职位管理 | 职位创建/编辑、JD 模板、职位状态 |
| `channel` 发布渠道 | 渠道配置、一键多平台发布、回流聚合 |
| `referral` 内推管理 | 内推入口、奖励规则、内推进度 |
| `campus_control` 校招管控 | 校招专项流程、宣讲会、批次管控 |
| `announcement` 招聘公告 | 招聘制度/公告对外展示 |
| `integration` 渠道对接 | 猎聘/BOSS/智联/LinkedIn/校招平台 API |

**用户角色**：招聘专员（发布）、用人经理（JD 确认）、内推员工（推荐）、候选人（被动触达）。

**业务流程**
1. 需求生效后在 `position` 生成职位草稿，套用 JD 模板。
2. 选择发布渠道，`integration` 调用各平台 API 批量发布。
3. 开启 `referral` 内推，生成内推码/海报。
4. 校招岗位走 `campus_control` 专项批次与宣讲会管控。
5. 各渠道投递经 `integration` 回流至阶段 3 简历池。

**关键状态机**：草稿 → 待发布 → 发布中 → 已发布 / 已下架 / 招满关闭。

---

### 阶段 3 · 简历筛选（Sourcing & Screening）

**目标**：汇聚全渠道简历，解析入库、查重去噪、初筛评级，并沉淀人才库。

**核心功能模块**
| 模块 | 职责 |
|------|------|
| `scraped_resume` 渠道爬取 | 第三方简历抓取与清洗 |
| `resume_flow` 简历解析流转 | 解析、结构化、流转、版本 |
| `candidate` 候选人主档 | 候选人 360 档案、联系方式、附件 |
| `duplicate_check` 查重去重 | 跨渠道重复识别、合并 |
| `screening` 智能筛选 | 规则/AI 初筛、评分、淘汰 |
| `talent_pool` 人才库 | 人才分层、标签、主动召回 |
| `dynamic_field` 动态字段 | 自定义评测维度/打分卡 |

**用户角色**：招聘专员（初筛）、用人经理（复筛）、AI 初筛引擎、候选人（完善简历）。

**业务流程**
1. 多渠道投递 + `scraped_resume` 爬取 → 统一进入 `resume_flow`。
2. `resume_flow` 解析为结构化档案，写入 `candidate` 主档。
3. `duplicate_check` 识别跨渠道重复，合并为单一候选人。
4. `screening` 按职位要求规则/AI 模型初筛，给出评分与推荐等级。
5. 未入围但优质简历沉淀 `talent_pool`，支持后续主动召回。
6. 通过初筛的候选人进入阶段 4 面试池。

**关键状态机**：待解析 → 已入库 → 初筛中 → 推荐 / 待定 / 淘汰（淘汰可回流人才库）。

---

### 阶段 4 · 面试安排（Interview Scheduling）

**目标**：高效编排面试轮次，协同面试官与候选人时间，并自动化回收评价。

**核心功能模块**
| 模块 | 职责 |
|------|------|
| `interview` 面试管理 | 轮次、面试官、评价表、晋级 |
| `invitation` 面试邀请 | 候选人与面试官双向邀约 |
| `automation` 自动编排 | 时间协调、提醒、超时升级 |
| `time_limit` 时限/SLA | 各环节时效管控、超时预警 |
| `integration` 日程/视频 | 日历（钉钉/企微/Outlook）、视频面试对接 |

**用户角色**：招聘协调员（排期）、面试官（评价）、候选人（确认时间）。

**业务流程**
1. 候选人进入面试池，`interview` 创建轮次与面试官名单。
2. `invitation` 向候选人与面试官发送邀约，`automation` 协调空闲时间。
3. `integration` 写入日历并生成视频面试链接。
4. 面试后 `interview` 回收结构化评价表（含 `dynamic_field` 打分卡）。
5. `time_limit` 监控评价时效，超时自动提醒/升级。
6. 汇总评价 → 决策晋级 / 淘汰 / 待定。

**关键状态机**：待安排 → 已邀约 → 已确认 → 已完成 / 改期 / 爽约 → 已评价 → 晋级 / 淘汰。

---

### 阶段 5 · 录用管理（Offer Management）

**目标**：把通过终面的候选人转化为正式录用，完成审批、发放、确认与背调签约。

**核心功能模块**
| 模块 | 职责 |
|------|------|
| `offer` 录用管理 | Offer 生成、薪酬方案、状态 |
| `mou` 录用意向/审批 | 审批流、法律条款 |
| `audit` 合规审计 | 录用决策留痕、合规校验 |
| `notification` 消息中心 | Offer 发放、确认提醒 |
| `integration` 背调/电子签 | 第三方背调、e签宝/法大大 |

**用户角色**：招聘负责人（发起）、用人经理（确认）、HR（薪酬）、法务（条款）、候选人（确认）、背调机构。

**业务流程**
1. 终面通过 → `offer` 生成 Offer（岗位/薪资/入职日），套用 `entry_condition` 门槛校验。
2. `mou` + `process` 完成薪酬与编制审批。
3. `notification` 向候选人发放 Offer，等待确认。
4. 候选人确认后触发 `integration` 背景调查 + 电子签。
5. `audit` 全程留痕，录用生效，移交阶段 6。

**关键状态机**：待生成 → 审批中 → 待发放 → 已发放 → 待确认 → 已确认 / 已拒 / 已撤销。

---

### 阶段 6 · 入职跟进（Onboarding）

**目标**：完成从「已确认 Offer」到「顺利转正」的闭环，沉淀新员工与组织数据。

**核心功能模块**
| 模块 | 职责 |
|------|------|
| `onboarding` 入职跟进 | 入职计划、任务清单、导师分配 |
| `application` 入职手续 | 信息收集、资料提交、合同 |
| `gdpr` 隐私合规 | 个人信息授权、数据最小化 |
| `notification` 消息中心 | 节点提醒、待办推送 |
| `integration` HRIS/OA | 入转调离、组织架构、账号开通 |

**用户角色**：HR（统筹）、IT（账号/设备）、部门导师（带教）、新人（自助）。

**业务流程**
1. Offer 确认后 `onboarding` 自动生成入职计划与任务清单。
2. `application` 收集新人信息、签署合同，`gdpr` 完成授权同意。
3. `integration` 同步 HRIS/OA 开通账号、IM、邮箱、门禁。
4. 入职后导师带教 + 培训，`onboarding` 跟踪任务完成度。
5. 试用期节点预警，`notification` 推送转正待办。
6. 转正完成 → 人才主数据回写 `candidate`/`talent_pool`，闭环结束。

**关键状态机**：待入职 → 入职中 → 试用期 → 已转正 / 未通过。

## 4. 用户角色与权限矩阵（RACI）

| 角色 | 需求分析 | 职位发布 | 简历筛选 | 面试安排 | 录用管理 | 入职跟进 |
|------|---------|---------|---------|---------|---------|---------|
| HRBP | R | C | C | C | C | I |
| 用人经理 | A | R | R | R | A | C |
| 招聘专员/协调员 | C | R | R | R | C | C |
| 招聘负责人 | A | A | A | A | R | A |
| 内推员工 | I | R | I | I | I | I |
| 候选人 | I | I | R | R | R | R |
| HR/IT/法务 | I | I | I | I | R | R |
| 平台（`core`/`field_acl`/`audit`） | 贯穿全部阶段的认证、字段级权限与审计留痕 | | | | | |

> R=负责执行　A=最终决策　C=被咨询　I=被通知

## 5. 四层系统架构与交互关系

### 5.1 层级总览
1. **前端门户层**：候选人门户、HR 招聘工作台、管理后台、移动端/小程序。
2. **后端服务层**：按 6 生命周期阶段分组的 33 个业务微服务 + 7 个平台级服务。
3. **数据中台层**：人才主数据、简历/画像、招聘分析集市、标签与画像引擎、数据治理。
4. **第三方集成层**：招聘渠道、日历、视频面试、背调、电子签、消息通道、HRIS/OA、薪酬。

### 5.2 交互关系（调用链）
- 前端门户 → 后端服务：所有操作经统一 API 网关（`core` 鉴权 + `field_acl` 字段级鉴权）。
- 后端服务 ↔ 数据中台：`candidate`/`talent_pool`/`resume_flow` 写主数据；`analytics` 读集市做编制预测与漏斗分析。
- 后端服务 ↔ 第三方集成：`channel`/`integration` 双向同步渠道简历；`invitation`/`interview` 调日历与视频；`offer` 调背调与电子签；`onboarding` 调 HRIS/OA。
- 平台级服务（`notification`/`automation`/`audit`/`process`）横切全部阶段，提供消息、自动化、审计、流程能力。

## 6. 指标体系

| 类型 | 指标 | 目标 |
|------|------|------|
| 北极星 | 有效到岗人数 / 平均周期 | 周期 ↓30% |
| 驱动（领先） | 简历→面试转化率、面试→Offer 转化率、渠道简历质量分 | 转化 ↑15% |
| 健康（滞后） | 人才库复用率、录用接受率、试用期通过率、面试官评价时效达标率 | 复用率 ≥25% |

---

## 7. 非目标与边界（Non-Goals）

1. **不包含薪酬核算与发薪**：薪酬仅做 Offer 方案与 HRIS 对接，工资计算由薪酬系统负责。
2. **不包含绩效考核**：试用期跟进仅做任务清单，KPI/绩效由绩效系统负责。
3. **不替代 EHR 主系统**：组织/编制主数据以 HRIS 为准，ATS 做消费与回写。
4. **不内置视频面试能力**：通过 `integration` 对接第三方，不自研音视频。
5. **AI 初筛为辅助决策**：最终筛选与录用决策责任在用人经理，系统不自动淘汰且无人工复核。
