## 2. E1｜插件盲区：改一处，暴露 79 处

### 盲区的确切机制

```js
// 旧实现
v = v.replace(VAR_RE, '').replace(NEUTRAL_KW, '');   // VAR_RE = /var\([^)]*\)/g
```

`VAR_RE` 把**整个** `var(...)` 抹掉 → `var(--ink, #1e293b)` 里的 fallback `#1e293b` 一起消失 → 永远测不到。
这正是 AGENTS.md 里那句「token 是唯一真源」最容易被绕过的地方：**把字面值复制进 fallback，就等于把硬编码藏进了令牌语法里**。

### 修法

```js
// 只剥 `var(--token` 前缀, fallback 保留在串里继续查
const VAR_PREFIX_RE = /var\(\s*--[\w-]+\s*/g;
v = v.replace(VAR_PREFIX_RE, ' ').replace(NEUTRAL_KW, '');
```

### 存量 88 处的三类改法

| 类 | 数量 | 例子 | 改法 |
|---|---|---|---|
| A 项目令牌 + 冗余 fallback | 62 | `var(--ink, #1e293b)` | **去掉 fallback** → `var(--ink)`（令牌一定存在，渲染不变；顺带消灭"字面值副本"） |
| B Naive UI 主题变量 | 10 | `var(--n-border-color, #d9d9d9)` | **映射到项目令牌** → `var(--border-hairline)`（项目令牌随暗色模式一起变，Naive 变量不跟） |
| C 纯 hex/rgba | 9 | `color: #333` | **逐条映射**到语义令牌；遮罩/叠加层用 `color-mix(in srgb, var(--c-error) 45%, transparent)` 这类令牌派生式 |

B 类的映射表：`--n-border-color`→`--border-hairline`、`--n-text-color-3`→`--ink-faint`、
`--n-text-color`→`--ink`、`--n-color-disabled`→`--g1`（tokens.css 注释里就是"最浅填充：disabled 输入框底"）。
C 类的映射表：`#333`→`--ink`、`#bbb`→`--ink-faint`、`#666`→`--ink-soft`、
`rgba(207,68,68,.45)`→`color-mix(in srgb, var(--c-error) 45%, transparent)`、
`rgba(0,0,0,.42)`（遮罩）→`color-mix(in srgb, black 42%, transparent)`。

### 翻硬门禁 + 反向验证

- `.stylelintrc.json`：`defaultSeverity` `warning` → **`error`**；
- CI 步骤改名 `Style lint (X-04/X-05/X-13/X-20 hard gate)`；
- **反向验证**：往 `ErrorState.vue` 注入 `color: var(--ink, #1e293b)` → `npm run lint:style` **exit 2**（CI 阻断）→ 还原后 exit 0。

### 残留（未做，已在计划卡记录）

`src/` 仍有 488 处 hex/rgba，但**其中 253 处在令牌真源/生成产物**（`styles/tokens.css` 210、`brand-tokens.css` 34、`brand-tokens.gen.ts` 9 —— **不能改**），其余是运行时主题值（`App.vue` 的 naive-ui `themeOverrides`、`ThemeSettings.vue` 的品牌色编辑器）与玻璃拟态样式。
当前门禁口径只覆盖 **color 类属性**，不覆盖 `box-shadow` / 背景图等 → 建议**单独立卡：扩展门禁覆盖面**，而不是本轮硬改 488 处（其中大半根本不该改）。

## 3. E2｜14 处抽屉回改居中弹窗（R-224）

### 统一后的形态

```vue
<n-modal
  v-model:show="x"
  preset="card"
  :title="t('...')"
  :style="{ width: '640px', maxWidth: '95vw' }"
  :content-style="{ height: 'min(640px, calc(88vh - 180px))', overflowY: 'auto' }"
  :mask-closable="false"
  :bordered="false"
>
  ...内容区...
  <template #footer>...操作区...</template>
</n-modal>
```

### 三个必须处理的细节

1. **`#footer` 自动归位**：原本嵌在 `<n-drawer-content>` 里的底部操作区，去掉 content 包裹后
   **自动成为 n-modal 的直接子节点** —— 正好落在 R-224 要求的「操作区用 `#footer` 插槽承载」。
2. **`#header` 里的动作按钮要下沉**：`DemandList.vue` 的「提交审批 / 编辑」原本塞在抽屉抬头里，
   按 R-224「操作区不与标题区混排」**移到了 `#footer`**（抬头只留需求编号/名称/状态标签）。
3. **失效的样式与导入要清**：`Layout.vue` 的 `.n-drawer-body-content-wrapper{padding:0}`
   随结构失效 → 改挂 `.n-card__content{padding:0}` 保持"菜单贴边"视觉；
   4 个文件里已无用的 `NDrawer` / `NDrawerContent` naive-ui 导入一并清理（否则 eslint 报未用导入）。

### 验证

- 全仓 `grep -rn "<n-drawer|n-drawer-content" src/` → **0 处**（仅剩注释里的一处提及）；
- `ScheduleDayDrawer.test.ts`（组件级测试，teleport 到 body）→ **2 passed**（改弹窗后仍通过）；
- `vue-tsc` / `eslint` / `stylelint` 全绿。

### 诚实说明

**逐页目视未做** —— 本地无浏览器运行时（见 §7）。14 处是机械转换（属性映射 + footer 归位），
但**视觉与交互**（如 `Layout.vue` 移动端侧栏从左滑改成居中弹窗）**需人工过一遍**。

## 6. E5 / E6｜两个常驻守卫

### E5：emoji 守卫 `web/app/scripts/scan_emoji.mjs`

**只扫顶层 `<template>` 且排除 HTML 注释** —— 注释里的 ⚠️/🔴 是给开发者的踩坑标记
（如 `/* ⚠️ 22:20 兵哥反馈 top 横排布局 4 个问题 */`），不属 X-02 管辖范围；
一并报出来会让守卫变噪音，最终被无视。
实测模板层 emoji **0 处**（exit 0，可直接进 CI）。

> 踩坑记录：`ResumeCard.vue` 与 `Step1Single.vue` 是**同一段错误提示 UI 的两份副本**，
> 计划卡只列了 `ResumeCard.vue` → 按卡做会漏一处（靠扫描器兜住了）。

### E6：滚动契约守卫 `web/app/scripts/scan_scroll_contract.mjs`

报出「`.page-body` + `flex-height` 表格」的双滚动候选页。**这类回归没有编译期信号**
（lint / typecheck 都发现不了），只能靠静态约定 + 守卫兜住。实测 **0 处**。

### E6 的计划卡改法需要修正（重要）

计划卡原写「`SettingsLayout.vue:502` 去掉 `!important`、改 `overflow:hidden`」——
**直接删会立刻重演"设置页全部不可滚"**：

- 布局层那条 `!important` 是 2026-09-13 为根治「34 个设置页全部不可滚」（兵哥反馈"做出来的页面全部不能滚动"）而加的；
- 那些页**自己**就声明了 `.page-body{overflow-y:auto}`（与布局层同值）→ 删掉布局层的，
  页面仍能滚；但**表格页**若失去布局层的 flex/height 约束，滚动视口就没了。

**实际做法（契约显式化 + 双轨）**：

- 布局层保留 `.page-body` 强制滚动 = **表单/详情页**的唯一解，并在布局注释里写清两条轨道与判定口径
  （**页面内有 flex-height 表格 → 必须用 `.data-body`**）；
- **实际迁移 14 个双滚动页**（`.page-body` + `flex-height` 表格 → 外层也滚 = 双滚动条）：
  `DepartmentManagement` / `DynamicStrategy` / `JobLevelManagement` / `MouManagement` /
  `PositionTitleManagement` / `RecruitmentProcess` / `RecruitmentRound` / `RecruitmentStage` /
  `UserDirectory` / `CompanySettings` / `RuleEngine` / `reason-library/rules` /
  `reason-library/tags` / `ui-templates/demos/ListDemo`
  → 滚动容器改 `.data-body` + `overflow-y:hidden`（真实滚动只在 `.table-wrap` 内的表格体，
  工具条/分页器固定）。迁移是纯机械动作（类名 + 样式块 + overflow 语义），不碰业务逻辑；
- `glass.css` 补 `.settings-scroll .data-body > .page-header{margin-bottom:0}`
  （原规则只认 `.page-body`，迁移后页头会多出全局 margin）。
