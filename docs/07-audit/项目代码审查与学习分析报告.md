## 0. 摘要（TL;DR）

ATS-NEW 是一个面向招聘场景的 **Applicant Tracking System**，采用前后端分离 monorepo 架构。后端为单一 Django 工程 + 46 个业务 app，前端为 Vue 3 单页应用。系统规模庞大：**后端 939 个 API 端点、133 张业务表、172 个迁移文件、1344 个 pytest 用例**；**前端 ~298 个源文件（133 个 .ts + 165 个 .vue）、132 个 vitest 用例**。

**整体评价**：架构方向健康且工程纪律严格（默认拒绝权限、fail-closed 设计、生产启动强校验、双写桥隔离）。**最值得学习**的是其分层规则引擎、双系统硬分区 scope 控制、fail-soft 与 fail-closed 的精细分层。

**主要风险**（按修复优先级）：
1. 🔴 密码策略在注册/改密 API 路径被完全绕过（未调用 `validate_password`）。
2. 🔴 背调供应商回调异常被吞，仍返回 HTTP 200 + SUCCESS 审计（数据不一致）。
3. 🟠 指标引擎/候选人快照大量 `except Exception: pass` 无日志（"假绿"风险）。
4. 🟠 候选人快照 N+1 查询、多处列表接口关闭服务端分页。
5. 🟡 前端 401 刷新逻辑双份实现、`.mjs`/`.ts` 双份工具、Top 巨型页面（MetricsWorkspace 2960 行）无单测。

## 5. 值得学习的设计模式与最佳实践

### 5.1 fail-closed 与 fail-soft 的精细分层（最值得借鉴）
- **默认拒绝**：`IsAuthenticatedDenyByDefault`（`core/permissions.py:20`）——未声明资源级权限的端点默认拒绝。
- **解密 fail-closed**：`STRICT_DECRYPT`（prod=True）解密失败抛 `DecryptionError` 而非静默返回密文（`common/encryption.py:101-132`）。
- **scope 异常 fail-closed**：4 层堆栈解析异常兜底到 `SELF`（`scope_resolver.py:43-65`）。
- **双写桥 fail-soft**：镜像异常仅记日志，绝不影响现网 legacy 行为（`rule_engine/bridge.py:1-13`）。
> 学习点：**把"失败时系统应该变严格还是变宽容"作为一等设计决策**，按组件性质分别处理，而非一概 try/except。

### 5.2 双系统硬分区（scope_filter 唯一真相源）
`recruit_type`（social/campus）由 `RecruitTypeMiddleware` 注入 request（`core/middleware.py:65-88`），在 `scope_filter_q` 中以 `Q(recruit_type=...)` **先于行级 scope 以 AND 叠加，对超管也生效**（`scope_resolver.py:447,461-491`）。学习点：**跨系统的数据隔离在单一入口强制，而非散落各处校验。**

### 5.3 分层规则引擎 + 双写桥（演进式架构）
6 类 legacy 规则通过 `bridge` 幂等镜像到统一 `rule_engine` 表，`RULE_ENGINE_DISPATCH` 默认关，双写不影响现网。学习点：**在不打断现网的前提下，用"读镜像 + 开关委托"平滑迁移到统一引擎**，避免一次性大重写风险。

### 5.4 统一条件求值底座（禁止再造）
`process/services/expression_service.py` 被 `rule_engine` 复用为唯一表达式求值底座（`rule_engine/services.py:21`）。学习点：**核心能力只实现一次，下游复用，避免多套求值逻辑漂移。**

### 5.5 生产启动强校验（fail-fast 配置）
`prod.py:_validate_production_config()`（`prod.py:16-82`）在 import 阶段即校验 SECRET_KEY/DEBUG/ALLOWED_HOSTS/CORS/DB/Redis/`PII_HASH_SALT`/独立 `ENCRYPTION_KEY`，并禁止 `LocMemCache` 静默 fallback（`prod.py:179-191`）。学习点：**把"部署错误"在启动期暴露，而非运行时随机爆雷。**

### 5.6 安全工程细节
- **PII 双读哈希**：`hash_candidates_for_search` 生成 v1+v2 两种哈希，`Q(id_card_hash__in=[...])` 双读，支持 salt 轮换无中断（`candidate/services.py:254`）。
- **IDOR 防护**：SSE 评分流校验 `task_id` 归属当前用户或超管（`add_candidate/sse.py:84-102`）。
- **密钥隔离**：`ENCRYPTION_KEY` 强制独立于 `INTEGRATION_FERNET_KEY`（`prod.py:119-125`），避免集成签名密钥泄露即解密 PII。
- **XSS 收敛**：`v-html` 仅 `SafeHtml.vue`，经白名单消毒 + `javascript:`/`data:` 协议拦截 + 外链 `rel="noopener noreferrer"`。

### 5.7 前端工程化亮点
- **统一 HTTP 客户端**：`utils/request.ts` 注入 `Authorization`+`X-Recruit-Type`、信封归一、401 自动刷新重试。
- **Pinia 启动水合门闸**：`stores/user.ts` 用 `ensureReady()` 幂等 hydrate，`main.ts` 在 `mount` 前 `await`，解决 RBAC 误判。
- **路由+元素双层 RBAC**：`routeGuard` 修正 Vue Router 不继承父 meta 的坑（`router/index.ts:266`），元素级用 `v-permission` 指令。
- **composable 复用**：`useTablePagination` 统一分页外观、`useRoleDataPerm` 封装数据权限表达式。

### 5.8 文档与质量纪律
- 版本 `==` 精确锁定且与实装对齐（消除"假绿"）。
- `technical.md` 数字均经运行时内省（端点数、表数、迁移数），并诚实列出已知风险修复表（R1-R11/BUG-1~7/T01.1）。

### 6.1 重复代码（高优先修复）
- **401 刷新重试逻辑双份**：`utils/request.ts:75-153` 与 `api/auth.ts:19-155` 各自实现 `isRefreshing`/`refreshSubscribers`/`onTokenRefreshed` 等（各命中 19 处）。**建议**：抽出共享 `api` 单例，让 `auth.ts` 复用。
- **`.mjs` 与 `.ts` 双份工具**：`debounce.mjs↔debounce.ts`、`request-dedup.mjs↔request-dedup.ts`（`.mjs` 仅被 `.test.mjs` 引用）。**建议**：合并，改逻辑只需一处。

### 6.2 巨型文件（维护风险 Top）
| 文件 | 行数 |
|---|---|
| `pages/settings/MetricsWorkspace.vue` | 2960 |

### 6.3 i18n 落地不完整
全部 111 个 `pages/*.vue` 含中文硬编码，但 `useI18n/t()` 仅覆盖 6 个命名空间（reasonLibrary/dataPerm/appUi/language/metrics/resumeParser）。基础设施已就绪，用户可见文案多数仍为硬编码中文。

### 6.4 其他
- 角色字面量散落：`router/index.ts` 中 `meta.roles` 硬编码出现 27 处。**建议**：抽取为常量。

- 全局 `console.warn/error` 散落较多，缺统一错误映射层。

## 8. 结论

ATS-NEW 是一个**架构成熟度高于平均**的大型招聘系统：前后端分离清晰、权限与安全的 fail-closed 设计扎实、生产配置强校验、规则引擎采用"双写桥 + 开关委托"的演进式迁移路径，这些都是可直接借鉴的工程实践。

主要短板集中在**"fail-soft 与可观测性失衡"**（指标/快照静默吞错导致假绿）、**安全细节遗漏**（密码策略/回调 200/密钥 fail-open）、以及**前端重复实现与巨型页面缺乏测试**。按本报告第 7 节优先级推进，可在不破坏现网的前提下显著提升系统可靠性与可维护性。
