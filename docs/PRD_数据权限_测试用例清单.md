### 2.1 P0-1 兼容式 fail-closed（存量保存不被误伤）

**背景**：P0-1 把"保存期缺 `write` 字段则后端拒收"从静默清空改为 fail-closed。**最大回归风险**是：库里现存 11 条规则无一条 WRITE，若一刀切强校验，管理员"只想改读范围"会被拒。故采用兼容式：仅"历史存在过 WRITE 或前端显式提交 `write`"时才强校验；存量首轮补 `write:{mode:'none'}` 默认值。

| 用例 | 场景 | Given | When | Then |
|---|---|---|---|---|
| TC-P0-1-04 | 存量无 WRITE 角色改读范围 | 角色 R 在 `data_permission_rules` 有 1 条 ROW+READ 规则、`write` 历史从无 | 管理员仅修改读范围表达式并保存（前端未带 `write`） | ① 保存成功 ② 读范围变更保持 ③ 后端为 R 补 `write:{mode:'none'}` 默认行（不误删、不报 400）④ 重开 R：读范围=新值、写范围默认"无权限" |
| TC-P0-1-05 | 历史有 WRITE 角色漏传 write | 角色 R2 曾配置过写范围（`data_permission_rules` 存在 WRITE 行） | 前端因缺陷未提交 `write` 即保存 | ① 后端返回 4xx ② R2 原有 WRITE 行内容不变 ③ 前端显式提示"写范围未提交，已阻止保存" |
| TC-P0-1-02 | 全新角色明确保存无写 | 新建角色 N，本次明确只配读范围 | 保存 payload 缺 `write` 字段 | ① 4xx ② 库中 N 无任何脏 WRITE 行 ③（同 TC-P0-1-04 的差异）N 为新建无历史 WRITE，按 TC-P0-1-05 逻辑也应拒收——**验证实现是否对"新建角色"也补默认值而非拒收**，二者须一致且文档化 |

**QA 判定红线**：TC-P0-1-04 MUST 通过且不得触发 TC-P0-1-05 的拒收；若 TC-P0-1-04 报 400，即一刀切回归，判 Fail。

### 2.2 字段 ACL 矩阵批量（P0-2）

### 2.3 指标模板快照失效语义（M7 / M13 / M6）
