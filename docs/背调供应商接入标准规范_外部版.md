# 背调供应商接入标准规范

> 版本：v1.0.1 ｜ 适用对象：接入本平台的背调服务供应商
> 用途：供应商技术对接合同附件与联调验收依据。供应商须完全遵循本规范方可上线。

---

## 1. 文档说明

### 1.1 适用范围
本规范定义平台与背调供应商之间的全部接口交互，覆盖：
- **订单创建 / 订单取消**（平台调用供应商）
- **订单状态异步回调**（供应商主动推送至平台）
- **接入支撑**（能力声明、沙箱/生产环境、健康检查）

### 1.2 术语表

| 术语 | 说明 |
|------|------|
| 平台 | 本招聘系统（调用方） |
| 供应商（贵方） | 背调服务供应方（被调用方） |
| 候选人 | 被背调的求职者 |
| 委托人 / 经办人 | 发起背调的 HR / 招聘方联系人 |
| 合作凭证 | `appId` + `appKey`，平台分配给贵方的身份标识 |
| 签名 sign | 用于校验请求来源与完整性的 HMAC 值 |
| 订单号 number | 平台生成的背调订单唯一编号，贯穿全链路 |

### 1.3 接口清单（务必看清方向）

| 接口 | 调用方向 | 方法 | 路径 | 责任方 |
|------|----------|------|------|--------|
| 创建订单 | 平台 → 供应商 | POST | `/api/v1/background-check/orders` | **供应商实现** |
| 取消订单 | 平台 → 供应商 | POST | `/api/v1/background-check/orders/cancel` | **供应商实现** |
| 套餐查询 | 平台 → 供应商 | GET | `/api/v1/background-check/products` | **供应商实现** |
| 订单状态回调 | 供应商 → 平台 | POST | 平台提供的 `callbackUrl` | **供应商调用** |

> 供应商需**实现**前两个接口（接收平台请求），并**主动调用**第三个（向平台推送状态）。

---

## 2. 接口协议与认证方式

### 2.1 传输协议
- 强制 **HTTPS**，TLS ≥ 1.2，禁止明文 HTTP。
- 数据格式：`application/json; charset=utf-8`，UTF-8 编码。
- 字段命名统一 **camelCase**。

### 2.2 版本与路径
- 所有路径以 `/api/v1/` 开头；破坏性变更升 `v2`，旧版本保留 ≥ 90 天过渡期。

### 2.3 环境隔离
贵方需提供两套 Base URL，凭合作凭证区分，**禁止**同一凭证混用环境：

| 环境 | 用途 | 数据 |
|------|------|------|
| 沙箱 Sandbox | 联调、回归 | 全为虚构测试数据 |
| 生产 Production | 真实业务 | 真实 PII |

### 2.4 双向认证

#### 2.4.1 平台 → 供应商（贵方验证平台）
平台在请求头携带：
```
X-App-Id: {appId}
X-Timestamp: {毫秒时间戳}
X-App-Sign: {签名}
```
贵方使用本地保存的 `appKey` 校验签名（算法见 §2.5）。`appKey` 仅用于验签，**不得**出现在响应体或日志。

#### 2.4.2 供应商 → 平台（平台验证贵方）
贵方推送状态回调时，须在请求体携带 `sign` 字段，平台按 §6.2 验签。

#### 2.5 签名算法（HMAC-SHA256，统一）
```
待签字符串 = 排序后的业务参数(key=value&连接) + "&timestamp=" + 时间戳
签名       = HMAC-SHA256(待签字符串, appKey)   // 输出十六进制小写
```
- 业务参数：请求体 JSON 的业务字段（不含 `sign`、`X-*` 头）。
- `null` / 空字符串字段不参与签名。
- 时间戳允许误差 ±5 分钟，超出视为重放攻击，拒绝。

## 3. 字段命名与数据结构定义

### 3.1 通用约定
- 字段名 camelCase（如 `candidateName`、`operatorPhone`）。
- 时间戳类（如 `completionTime`）→ **Unix 毫秒 Long**。
- 日期类（如 `expectEntryTime`）→ **`yyyy-MM-dd` 字符串**。
- 枚举类 → **Integer**。
- 文件类 → **`List<String>`**，元素为已上传文件的 URL 或文件标识。

### 3.2 创建订单（平台 → 供应商）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| requestId | String | 是 | 平台生成的幂等请求号（UUID），用于去重 |
| productToken | String | 是 | 套餐唯一标识 |
| candidateName | String | 是 | 候选人姓名 |
| phone | String | 是 | 候选人手机号 |
| email | String | 否 | 候选人邮箱 |
| idCard | String | 否 | 候选人身份证号（PII，见 §7） |
| contactCandidate | Integer | 否 | 是否可联系候选人：1=可联系（默认），0=不可 |
| job | String | 否 | 应聘职位 |
| operatorName | String | 是 | 委托人/经办人姓名 |
| operatorPhone | String | 是 | 委托人手机号 |
| operatorEmail | String | 否 | 委托人邮箱 |
| authWay | Integer | 否 | 授权方式：1=线上电子授权，2=线下授权书上传，3=候选人App/小程序授权 |
| authFiles | List<String> | 否 | 授权文件 URL 列表 |
| educationFiles | List<String> | 否 | 学历证件 URL 列表 |
| resumeFiles | List<String> | 否 | 简历附件 URL 列表 |
| skillFiles | List<String> | 否 | 专业证书附件 URL 列表 |
| remark | String | 否 | 备注信息 |
| callbackUrl | String | 否 | 回调地址（指定则平台接收至此，否则用默认地址） |
| expectEntryTime | String(yyyy-MM-dd) | 否 | 预计入职日期 |

**响应（贵方返回）：**
```json
{ "code": 0, "message": "success", "data": { "number": "BG202608250001" }, "requestId": "req-7f3a9c2e", "timestamp": 1724563200123 }
```

### 3.3 取消订单（平台 → 供应商）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| requestId | String | 是 | 幂等请求号 |
| number | String | 是 | 背调订单编号 |

**响应（贵方返回）：**
```json
{ "code": 0, "message": "success", "data": { "number": "BG202608250001", "cancelled": true }, "requestId": "req-xxxx", "timestamp": 1724563200123 }
```

### 3.4 套餐查询（平台 → 供应商）
平台查询贵方提供的可下单套餐列表，用于下单前获取 `productToken`、价格、交付周期与背调项目。

**请求（GET，认证头同 §2.4.1）**
```
GET /api/v1/background-check/products?productToken=pkg_edu_001&page=1&pageSize=20
```
| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| productToken | Query | String | 否 | 指定套餐标识；传则只返回该套餐，不传返回全部 |
| page | Query | Integer | 否 | 页码，默认 1 |
| pageSize | Query | Integer | 否 | 每页条数，默认 20 |

**响应 data（套餐列表，分页结构见 §4.3）**

| 字段 | 类型 | 说明 |
|------|------|------|
| productToken | String | 套餐唯一标识 |
| productName | String | 套餐名称 |
| price | Integer | 套餐价格（单位：分，人民币；如 29900 表示 ¥299.00） |
| deliverDays | Integer | 套餐交付天数（SLA） |
| projectName | String | 背调项目，多个以「；」分隔，例如：身份验证；负面社会安全记录；个人涉诉记录 |
| remark | String | 套餐备注 |

**响应示例**
```json
{
  "code": 0, "message": "success",
  "data": {
    "list": [
      { "productToken": "pkg_edu_001", "productName": "标准学历背调", "price": 29900, "deliverDays": 3, "projectName": "身份验证；学历验证；负面社会安全记录", "remark": "适用于校招基础岗" }
    ],
    "pagination": { "page": 1, "pageSize": 20, "total": 1 }
  },
  "requestId": "req-xxxx", "timestamp": 1724563200123
}
```

### 3.5 订单状态回调（供应商 → 平台）
贵方在订单状态变更时，主动 POST 至平台 `callbackUrl`，请求体：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| sign | String | 是 | 回调签名（§6.2） |
| number | String | 是 | 订单号 |
| status | Integer | 是 | 订单状态（§3.6） |
| statusName | String | 是 | 订单状态名称（与 status 对应） |
| riskLevel | Integer | 否 | 风险等级（§3.6；未完成可空或 9） |
| reportUrl | String | 否 | 报告地址（完成后必填） |
| completionTime | Long(毫秒) | 否 | 完成时间时间戳 |

### 3.6 枚举值定义

**订单状态 status**
| 值 | 名称 | 说明 |
|----|------|------|
| 0 | 已受理/已下单 | 贵方已接单 |
| 1 | 已完成 | 背调完成，报告可下载 |
| 2 | 待授权 | 等待候选人授权 |
| 3 | 背调中 | 进行中 |
| 4 | 授权过期 | 候选人授权超时未处理 |
| 5 | 待支付 | 等待费用支付 |
| 6 | 已取消 | 订单取消 |
| 7 | 阶段报告 | 阶段性报告产出（非最终） |
| 8 | 授权撤销 | 候选人撤销授权 |

**风险等级 riskLevel**
| 值 | 名称 |
|----|------|
| 1 | 低风险 |
| 2 | 中风险 |
| 3 | 高风险 |
| 4 | 无风险 |
| 9 | 未评级 |

**授权方式 authWay**
| 值 | 名称 |
|----|------|
| 1 | 线上电子授权 |
| 2 | 线下授权书上传 |
| 3 | 候选人 App/小程序授权 |

## 4. 请求与响应格式

### 4.1 统一请求
业务字段 + 公共头（§2.4.1）。示例（创建订单）：
```json
POST /api/v1/background-check/orders
Headers:
  X-App-Id: sp_abc123
  X-Timestamp: 1724563200000
  X-App-Sign: 9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08
Content-Type: application/json

{
  "requestId": "req-7f3a9c2e",
  "productToken": "pkg_edu_001",
  "candidateName": "张三",
  "phone": "13800001111",
  "operatorName": "李四",
  "operatorPhone": "13900002222",
  "authWay": 1,
  "callbackUrl": "https://ats.example.com/api/v1/background-check/callback"
}
```

### 4.2 统一响应信封（所有接口）
```json
{
  "code": 0,
  "message": "success",
  "data": { "number": "BG202608250001" },
  "requestId": "req-7f3a9c2e",
  "timestamp": 1724563200123
}
```
- `code=0` 成功；`code≠0` 失败，`message` 描述原因，`data` 可空。
- 同一 `requestId` 重复请求返回首次结果，不产生副作用（幂等）。

### 4.3 分页（列表类接口预留）
```
Query: page=1&pageSize=20
返回: { "list": [...], "pagination": { "page":1, "pageSize":20, "total":135 } }
```

## 5. 状态码与错误处理

### 5.1 HTTP 状态码
| HTTP | 含义 | 处理 |
|------|------|------|
| 200 | 已处理（业务结果看 `code`） | 读取 `code` |
| 400 | 参数校验失败 | 返回 `code=400xx`，平台修正后重试 |
| 401 | 认证失败 | 检查 `appId`/`appKey`/`sign` |
| 403 | 无权限（套餐/环境不匹配） | 联系平台 |
| 404 | 接口/资源不存在 | 检查路径与版本 |
| 409 | 冲突（订单已存在/已取消） | 平台做幂等处理 |
| 429 | 限流 | 按 `Retry-After` 退避重试 |
| 500 | 内部错误 | 平台告警，可重试 |
| 503 | 服务不可用/维护 | 平台降级，稍后重试 |

### 5.2 业务错误码 code
| code | 含义 |
|------|------|
| 0 | 成功 |
| 40001 | 缺少必填字段 |
| 40002 | 字段格式非法（手机号/身份证校验失败） |
| 40003 | 套餐不存在或无权限 |
| 40101 | appId 无效 |
| 40102 | 签名校验失败 |
| 40103 | 时间戳超时（重放） |
| 40401 | 订单号不存在 |
| 40901 | 订单状态不允许该操作 |
| 50001 | 内部异常 |

### 5.3 原则
- 参数错误立即返回 4xx + 具体 `code`，不静默。
- 内部 5xx 必须返回明确 `message`，禁止以"成功"掩盖失败。
- 重复请求（同 `requestId`）返回首次结果，无副作用。

## 6. 回调与异步通知规范

### 6.1 触发与投递
- 订单状态变更时，贵方**主动 POST** 至平台 `callbackUrl`（或平台默认地址）。
- 回调为**异步、至少一次投递（at-least-once）**，平台按 §6.3 做幂等。
- 每次状态变更均推送（含阶段报告 status=7）。

### 6.2 回调签名校验（强制）
```
待签串 = "number=" + number + "&status=" + status + "&timestamp=" + ts
sign   = HMAC-SHA256(待签串, appKey)   // 十六进制小写
```
- 平台用 `appKey` 重算并比对 `sign`，不一致拒绝（401）并审计。
- `timestamp` 纳入待签并校验 ±5 分钟防重放。

### 6.3 幂等与重试
- 平台以 `(number, status, completionTime)` 做幂等键，重复推送返回 200 不重复处理。
- 贵方侧：平台返回 **2xx 视为成功**；非 2xx 按**指数退避**重试（建议 1s/5s/30s/5m，最多 6 次）。
- 重试期间贵方须保留通知，避免丢失。

### 6.4 超时与兜底
- 平台回调接口 P99 < 1s；超时贵方按重试策略处理。
- 若回调长期失败，贵方在订单详情接口仍应提供最新状态，供平台**主动轮询兜底**。

## 7. 数据安全性要求

### 7.1 传输安全
- 全链路 HTTPS TLS≥1.2，HSTS 开启。
- 签名防篡改、防重放（§2.5 / §6.2）。

### 7.2 PII 与敏感字段
- 身份证 `idCard`、手机号 `phone` 属 PII，**传输加密 + 存储加密（AES-256）**。
- 数据库存储 PII 须脱敏（如身份证展示 `110***********1234`）。
- 日志、监控中**禁止打印明文 PII**；确需排查用令牌化 ID 代替。

### 7.3 存储与留存
- 报告、授权书等文件加密存储，访问需鉴权，留存期限按合同/法定期限。
- 候选人撤回授权（status=8）后，按约定删除/封存相关 PII 与报告。

### 7.4 权限与审计
- 合作凭证按供应商隔离，最小权限；`appKey` 定期轮换（建议 90 天）。
- 订单创建、取消、回调、报告访问**留审计日志**（谁/何时/操作/结果）。
- 供应商仅可访问本合作账号下数据，跨租户隔离。

### 7.5 合规
- 满足《个人信息保护法》与候选人**授权前置**要求；无授权（status=2 未解决）不得开展实质背调。
- 候选人有权查询、更正、删除其背调数据。

## 8. 接入流程与扩展约定

### 8.1 版本管理
- 路径版本 `/api/v1/`；破坏性变更升 `v2`，旧版本 ≥ 90 天过渡。
- 枚举新增取值须向后兼容，未知值旧实现应忽略。

### 8.2 能力声明（接入时提交）
贵方接入时提交能力清单，平台据此路由与校验：

| 能力项 | 说明 |
|--------|------|
| 支持套餐 productToken 列表 | 决定可下单范围 |
| 支持授权方式 authWay 子集 | 决定授权流程分支 |
| 是否支持主动回调 | 否则平台走轮询兜底 |
| 支持字段子集 | 如不支持 `educationFiles` 则下单时平台忽略 |
| 报告格式 | PDF / JSON / 在线地址 |

### 8.3 环境与联调
- 必须提供沙箱环境，数据全虚构，可自由触发各 status 回调用于联调。
- 联调须通过自动化用例：创建→各状态回调→取消→幂等→签名失败→超时重试。

### 8.4 健康检查
- 贵方提供 `GET /api/v1/health`，返回 `{ "status": "up", "timestamp": ... }`。
- 平台定时探活，异常自动降级（暂停新单下发，保留存量处理）。

### 8.5 供应商接入 Checklist（上线前逐项确认）
1. [ ] 签署数据与安全合规附录（§7）
2. [ ] 分配 `appId` / `appKey`，配置沙箱 + 生产 Base URL
3. [ ] 提交能力声明清单（§8.2）
4. [ ] 实现创建订单 / 取消订单接口，并完成签名验签
5. [ ] 实现订单状态回调（含 `sign` 签名）
6. [ ] 提供 `health` 端点并接入探活
7. [ ] 安全评审：PII 加密、日志脱敏、审计、密钥轮换
8. [ ] 沙箱联调通过自动化用例 → 灰度 1 个真实订单验证 → 全量

---

*本规范为 v1.0.1 基线，后续经接入实践迭代修订。如有歧义，以平台最新发布版本为准。*
