# 07 - 部署与运行

## 1. 前置依赖

| 依赖 | 版本 | 用途 |
|---|---|---|
| Python | 3.14+（项目 .venv 为 3.14.6） | 后端运行时 |
| Node.js | 20+（npm，**不要用 pnpm**，仓库锁定 package-lock.json） | 前端构建 |
| MySQL | 8（生产）/ SQLite（dev/test 兜底） | 数据库 |
| Redis | 7 | Celery broker + 缓存 + Channels layer + 限流 |

## 2. 一行启动（Docker 全栈）

```bash
make up     # docker compose -f ops/docker-compose.yml up -d
make down   # 停止
make logs   # 跟随日志
make status # git status + 前后端健康检查
```

### ops/docker-compose.yml 服务编排

| 服务 | 镜像/构建 | 端口 | 依赖 | 卷 |
|---|---|---|---|---|
| `mysql` | mysql:8.0 | 3306 | — | `mysql_data` |
| `redis` | redis:7-alpine（持久化 + 内存策略） | 6379 | — | `redis_data` |
| `backend` | build `../apps/django`（gunicorn WSGI） | 8000 | mysql + redis（健康检查） | — |
| `nginx` | nginx（挂前端 dist） | **宿主 9908** → 容器 80 | backend | nginx 配置 |

网络：`ats-network`（内部 DNS：`mysql` / `redis` / `backend`）。

> Makefile 注释口径：容器内 backend 由 gunicorn 承担（曾用 5125 对外），nginx 暴露 9908；本地开发则后端 8000、前端 5212。

### 前端独立镜像（`web/app/Dockerfile`）

```
node:18-alpine → npm install → npm run build → dist 复制到 nginx:alpine /usr/share/nginx/html → expose 80
```

`web/app/nginx.conf`：SPA `try_files` 回退 index.html；`/api/` 反代 `http://backend:8000/api/`（透传 Host / Real-IP / X-Forwarded-For / X-Forwarded-Proto）。

## 3. 手动启动（本地开发）

### 3.1 后端（终端 1）

```bash
cd apps/django
source .venv/bin/activate            # 首次: python3 -m venv .venv
pip install -r requirements.txt

cp .env.example .env                  # 编辑关键变量（见 §4）

python manage.py migrate
python manage.py loaddata seeds/07_demo_user.json   # 可选: admin/admin123
python manage.py collectstatic --noinput

python manage.py runserver 0.0.0.0:8000             # 开发模式
# 或 gunicorn:
python -m gunicorn config.wsgi:application --bind 127.0.0.1:8000 --workers 2
```

可选异步组件（需要 Redis）：

```bash
celery -A celery_app worker -Q celery,time_limit,automation,notification,analytics,application,gdpr,invitation,talent_pool
celery -A celery_app beat          # django-celery-beat DatabaseScheduler
daphne config.asgi:application     # WebSocket（Channels）
```

### 3.2 前端（终端 2）

```bash
cd web/app
npm install
npm run dev       # http://localhost:5212（proxy /api/v1 → :8000）
npm run build     # vue-tsc + vite build → dist/
npm test          # vitest
```

## 5. 配置环境矩阵

| 环境 | 模块 | 要点 |
|---|---|---|
| dev | `config/settings/dev.py` | DEBUG=True、CORS 全开、CSRF/限流关闭、SQLite 兜底、可挂 debug_toolbar |
| prod | `config/settings/prod.py` | 启动强校验（secret/DEBUG/hosts/DB）、HTTPS 安全头、Sentry、Redis 强制、生产日志 |
| test | `config/settings/test.py` | SQLite、弱密码哈希、限流关、Celery eager、locmem 邮件、测试加密 key |

> `config/wsgi.py` / `config/asgi.py` 显式 `DJANGO_SETTINGS_MODULE=config.settings.prod`——不会回落 dev（R3 修复）。

| 阶段 | 内容 |

## 7. 运维要点（摘自 RUNBOOK）

- **紧急回滚**：R1 migration 崩溃、BUG 系列均有对应回滚命令（`RUNBOOK.md` §6）；V2 schema 异常可回退 `*_v1_backup` 4 表。
- **pytest FK/no such column 报错**：多为 V2 schema 缺失，见 `tests/conftest.py` 的 `_ensure_v2_schema_on_sqlite()`。
- **API 403**：优先查 V2 权限（角色未授 / scope 过滤）；日志出现 `no such column: user_roles.role_code` 即 V2 schema 问题。
- **健康检查路径**：`/health/`（不是 `/api/v1/health/`）。

### 8.3 基础设施依赖

```
MySQL 8 ── 业务数据（78+ 表）
Redis 7 ─┬─ Celery broker（db 1）/ result（db 2）
          ├─ 缓存 + 限流（db 0）
          └─ Channels layer
Cloudflare Tunnel ── 公网 HTTPS 接入（ats.lokisong.cloud）
Sentry / Prometheus ── 可观测
Affinda SaaS ── 简历解析（V2 add-candidate）
```

### 8.4 模块间依赖（后端）

- `application` → `candidate`（撤回联动 CandidateService）、`process`（阶段解析）、`talent_pool`（软拒入池）
- `offer` → `application`（状态联动）、`onboarding`（接受后建入职）
- `automation` / `time_limit` → `application`（自动推进/超时归档，Celery 驱动）
- `add_candidate` → `candidate`（建档）、Affinda（外部）
- 所有业务 app → `common`（FullAuditModel/工具）+ `core`（User/权限）
- `notification` 被各域异步调用（Celery `notification` 队列）
