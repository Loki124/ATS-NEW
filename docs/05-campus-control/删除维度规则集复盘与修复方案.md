# 删除维度规则集复盘与修复方案
> 最后更新：2026-09-07（依据 git 最后提交）

> 版本：v1.0 ｜ 日期：2026-08-26 ｜ 关联模块：校招管控 / 规则配置 / 维度规则集编辑面
> 关联代码：
> - 前端：`/web/app/src/pages/settings/CampusControl.vue`（`dimEditor*` 计算属性、`saveDimRuleSet`、`toggleDimRowDelete`）
> - 后端：`/apps/django/apps/campus_control/views.py`（`ControlDimensionViewSet.set_rules`）
> - 测试：`/apps/django/apps/campus_control/tests/test_calc.py`

## 1. 问题现象

在「维度规则集」编辑面中，当用户把某个适用范围（如「部门=能电BG」）+ 维度（如「专业标签」）+ 年度下的**全部指标规则**都标记为删除后：

- 底部加和提示：**占比之和 0.0% · 人数加和 0 / 1731 人**
- 状态提示：「⚠ 占比 ≠ 100%」「⚠ 人数加和异常」
- 底部告警：「已标记删除 2 个指标，剩余指标占比之和须重平衡至 100% 后方可保存」
- **保存按钮被禁用**，无法保存，删除操作实质上被阻塞。

截图中「专业标签 / 能电BG / 2026」下仅有「其他（60%）」「工学（40%）」两条规则，用户把两条全部标记删除后，剩余规则数为 0，系统仍要求「占比之和 = 100%」，导致死锁。

---

## 2. 复现路径

1. 进入「校招管控 → 规则配置」
2. 找到任意一个已有规则的「适用范围 + 维度 + 年度」组合（如截图中的「专业标签 / 能电BG / 2026」）
3. 点击该组合下**任意一条规则**的「删除」按钮
   - 前端调用 `openDimensionEditor(rule, { preDelete: r.indicator })`
   - 进入「维度规则集编辑面」，并标记该指标为「待删」
4. 在编辑面中，继续把**该组合下剩余的所有指标**也标记为「待删」
5. 此时：
   - `dimEditorPendingDeleteCount === dimEditor.rows.length`
   - `dimEditorSumPct = 0`
   - `dimEditorSumOk = false`
   - `dimEditorTotalOk = false`
   - 保存按钮被禁用，无法清空规则集

---

## 3. 原始需求回顾

根据《校招管控需求说明文档 v2.5》：

> **5.2 占比 100% 加和约束**
> - 同一「适用范围 + 维度 + 规划年度」下，所有指标的 `target` 之和必须 = 1.0（100%）。
> - 容差：0.0001（规避 2 位小数百分比的舍入毛刺）。
> - 单条编辑：仅拦截「超过 100%」（防溢出）；恰好 =100% 由批量端点保证完整加和。
> - 批量 / 导入：强校验「必须 = 100%」，否则整体拒绝（400）。

该约束的核心目的是：**占比是对同一核算分母的完整划分，缺失或不完整会导致比例管控失去意义**。这是一个合理的业务约束。

**但原始需求并未明确**：当用户需要「清空某适用范围下的全部规则」时，应如何处理。当前系统默认套用「批量编辑」的强校验，把「清空」也当作「占比不完整」拦截，这是实现层面的缺陷。

## 4. 当前实现逻辑

### 4.1 前端校验逻辑（CampusControl.vue）

```ts
// 仅统计未标记删除行的占比之和
const dimEditorSumPct = computed(() =>
  dimEditor.rows.reduce((s, r) => s + (r.pendingDelete ? 0 : (r.targetPct || 0)), 0),
)
const dimEditorSumOk = computed(() => Math.abs(dimEditorSumPct.value - 100) < 0.05)

// 仅统计未删除行的年度人数加和
const dimEditorActiveAnnualSum = computed(() =>
  dimEditor.rows.reduce((s, r) => s + (r.pendingDelete ? 0 : Math.round(r.annualTarget || 0)), 0),
)
const dimEditorTotalOk = computed(() => dimEditorActiveAnnualSum.value === Math.round(dimEditor.totalTarget || 0))
```

保存时校验：

```ts
async function saveDimRuleSet() {
  const validRows = dimEditor.rows.filter((r) => !r.pendingDelete && r.targetPct != null)
  if (validRows.length === 0) { message.warning('请至少保留一个指标并设置占比'); return }
  if (!dimEditorSumOk.value) { message.warning(`占比之和须 = 100%...`); return }
  if (!dimEditorTotalOk.value) { message.warning(`各指标年度人数加和...须等于维度年度管控人数...`); return }
  // ...
}
```

**关键问题**：`validRows.length === 0` 被作为错误拦截，没有区分「误操作」和「主动清空规则集」。

### 4.2 后端接口逻辑（views.py::set_rules）

```python
if not isinstance(rules_in, list):
    return Response(..., status=400)
# ... 逐项校验 target ...
if abs(total - Decimal('1')) > Decimal('0.0001'):
    return Response({'detail': '该适用范围下此维度指标目标占比之和须为 100%...'}, status=400)
# 原子替换：先删除旧规则，再重建
ControlRule.objects.filter(bu=bu, ..., dimension=dimension, year=year).delete()
for ... in prepared:
    ControlRule.objects.create(...)
```

**关键问题**：
- 当 `rules_in = []` 时，`total = 0`，会触发「占比之和 ≠ 100%」错误 400。
- 接口语义是「原子替换」，但设计上没有为「替换为空」预留路径。

### 4.3 规则列表删除入口

```ts
h(NButton, { onClick: () => openDimensionEditor(r, { preDelete: r.indicator }) }, { default: () => '删除' })
```

列表页每行规则的「删除」按钮，并不是直接调用删除 API，而是进入「维度规则集编辑面」并预标记删除。这意味着：

- 删除 1 条规则时，必须保证剩余规则占比之和 = 100%（合理，强制重平衡）。
- 删除全部规则时，也套用同一流程，但此时无「剩余规则」可供重平衡，流程死锁。

## 5. 缺陷分析

### 5.1 设计层面：缺失「清空规则集」的独立语义

当前系统把「删除单条规则」和「清空全部规则」都映射到同一个「维度规则集编辑 + 重平衡」流程。前者合理，后者无解。

**正确的语义应区分**：

| 操作类型 | 语义 | 是否要求剩余规则 =100% |
|---------|------|------------------------|
| 删除部分指标 | 在保留的规则集中重新分配占比 | 是 |
| 清空全部规则 | 删除该（适用范围 + 维度 + 年度）下的整个规则集 | 否 |

### 5.2 校验层面：校验规则未考虑空集的合法性

- 前端 `validRows.length === 0` 直接报错，没有给「清空」开绿灯。
- 后端 `set_rules` 对空 `rules` 数组也按「占比 ≠ 100%」拒绝。

### 5.3 交互层面：删除路径过度耦合编辑面

列表页删除单条规则时，强制进入编辑面，增加了操作步长。对于「删除全部」这种批量操作，用户需要在编辑面里逐个点「删除」再保存，本身就不够直接。

### 5.4 文案层面：全删场景提示错误

截图底部提示：「已标记删除 2 个指标，剩余指标占比之和须重平衡至 100% 后方可保存」。当剩余指标为 0 时，「重平衡至 100%」是一个不可能的诉求，属于文案误导。

---

## 6. 修复方案

### 推荐方案：前后端协同支持「清空规则集」

#### 6.1 产品语义重新定义

- **部分删除**：保留的指标占比之和必须 = 100%，人数加和必须 = 维度年度管控人数。
- **全部删除（清空）**：允许保存，效果是删除该（适用范围 + 维度 + 年度）下所有规则。
- **清空后状态**：该组合下无规则，实时看板不再展示该组合，人员主数据不受影响。

#### 6.2 前端修改（CampusControl.vue）

1. **新增「全部标记删除」判断**：

```ts
const dimEditorAllPendingDelete = computed(() =>
  dimEditor.rows.length > 0 && dimEditor.rows.every((r) => r.pendingDelete)
)
```

2. **调整 `dimEditorSumOk` 在「全删」场景下通过**：

```ts
const dimEditorSumOk = computed(() =>
  dimEditorAllPendingDelete.value || Math.abs(dimEditorSumPct.value - 100) < 0.05
)
```

3. **调整 `dimEditorTotalOk` 在「全删」场景下通过**：

```ts
const dimEditorTotalOk = computed(() =>
  dimEditorAllPendingDelete.value || dimEditorActiveAnnualSum.value === Math.round(dimEditor.totalTarget || 0)
)
```

4. **保存校验增加「清空」分支**：

```ts
async function saveDimRuleSet() {
  if (!dimEditor.dimensionId) { message.warning('请选择维度'); return }

  const activeRows = dimEditor.rows.filter((r) => !r.pendingDelete)
  const validRows = activeRows.filter((r) => r.targetPct != null)

  // 清空场景：全部待删
  if (activeRows.length === 0) {
    await dialog.warning({
      title: '清空规则集确认',
      content: `保存后将删除「${formatScopeLabel(_currentEffectiveScope())}」下的全部规则，是否继续？`,
      positiveText: '确认清空',
      negativeText: '取消',
      onPositiveClick: () => doSaveDimensionRuleSet([]),
    })
    return
  }

  if (validRows.length === 0) { message.warning('请至少保留一个指标并设置占比'); return }
  if (!dimEditorSumOk.value) { message.warning(...); return }
  if (!dimEditorTotalOk.value) { message.warning(...); return }

  // 月度校验 ...
  await doSaveDimensionRuleSet(validRows.map(...))
}
```

5. **「全删」场景下文案提示替换**：

```html
<n-alert v-if="dimEditor.mode === 'edit' && dimEditorAllPendingDelete" type="warning" :show-icon="true">
  已标记删除全部指标，保存后将清空该适用范围下的规则集。
</n-alert>
<n-alert v-else-if="dimEditor.mode === 'edit' && dimEditorHasPendingDelete" type="warning" :show-icon="true">
  已标记删除 {{ dimEditorPendingDeleteCount }} 个指标，剩余指标占比之和须重平衡至 100% 后方可保存。
</n-alert>
```

#### 6.3 后端修改（views.py::set_rules）

1. **允许空 `rules_in` 表示清空**：

```python
if not isinstance(rules_in, list):
    return Response({'success': False, 'detail': 'rules 须为数组'}, status=400)

# 空数组 = 清空该 scope 下的规则集
if len(rules_in) == 0:
    # 重定位：先删原 scope
    if relocate:
        ControlRule.objects.filter(
            bu=obu, position=opos, level=olev, dimension=dimension, year=oyear
        ).delete()
    # 删除当前 scope 规则
    ControlRule.objects.filter(
        bu=bu, position=position, level=level, dimension=dimension, year=year
    ).delete()
    return Response({'success': True, 'data': {'saved': 0}})
```

2. **空数组场景下跳过占比之和校验与互斥守卫**：
   - 清空操作是「删除」语义，不是「新建全局规则」语义，因此不应触发「全局 vs 指定范围」互斥守卫。
   - 例如：清空全局规则时，不应因为有指定范围规则而拦截；清空指定范围规则时，也不应删除全局规则。

3. **保留非空规则集的原子替换语义不变**：非空时仍强制校验占比之和 = 100%。

#### 6.4 可选：规则列表页增加「清空」快捷入口

在规则配置列表页，每个「适用范围 + 维度 + 年度」组合旁增加「清空」按钮，直接调用清空逻辑，无需进入编辑面。这能显著缩短「删除全部规则」的操作路径。

### 备选方案

#### 方案 B：独立「清空」API（不修改 `set_rules` 语义）

- 新增 `DELETE /api/v1/campus/dimensions/{id}/rules/?bu=&position=&level=&year=` 接口，专门用于清空某 scope 下的规则。
- 前端「清空」按钮调用该 API，不走 `set_rules`。
- 列表页删除单条仍走 `set_rules`（强制重平衡）。

**优点**：`set_rules` 的「原子替换 + 100% 强校验」语义保持纯净，改动范围小。
**缺点**：需要新增 API 和前端调用点，无法解决「编辑面内用户把全部行标记删除」的场景。

#### 方案 C：删除后自动重分配占比

- 当用户标记删除某指标时，自动把该指标占比按剩余指标目标占比重新分配，保证始终 100%。

**缺点**：自动修改用户未意图修改的指标目标，容易引发「误删导致其他指标目标被篡改」的投诉，不建议采用。

## 7. 数据一致性保证

采用推荐方案后，需确保以下一致性：

| 一致性项 | 保证方式 |
|---------|---------|
| 清空后该 scope 下无规则 | `ControlRule.objects.filter(...).delete()` |
| 不影响其他 scope 规则 | 删除条件精确到 `bu/position/level/dimension/year` |
| 不影响全局 vs 指定范围互斥 | 清空操作跳过 `_scope_mutex_guard` |
| 不影响人员主数据 | 规则表与人员表独立，删除规则不级联 |
| 不影响实时看板其他数据 | 看板按实际规则计算，无规则即不展示 |
| 重定位场景下原 scope 规则被删除 | 同事务内先删原 scope，再删当前 scope |

## 9. 决策建议

**建议执行「推荐方案」**：

1. 前端在编辑面内识别「全部标记删除」场景，放开占比/人数校验，允许保存。
2. 后端 `set_rules` 支持空 `rules` 数组，按「清空规则集」处理，并跳过全局/指定范围互斥守卫。
3. 文案在全删场景下替换为「保存后将清空该适用范围下的规则集」。
4. （可选增强）规则列表页增加「清空」快捷入口。

**不做方案 C（自动重分配）**，因为会改变用户未意图修改的数据，违背产品可控性原则。

**实施优先级**：P0。当前用户已无法删除某个 scope 下的全部规则，属于阻塞性交互缺陷。
