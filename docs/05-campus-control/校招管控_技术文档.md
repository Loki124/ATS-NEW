## 2. 后端架构

```
campus_control/
├── models.py        # 4 张模型：维度/指标/规则/人员
├── serializers.py   # DRF 序列化器 + 字段校验
├── views.py         # ViewSet + @action（ratio/plan/validate/batch/with-targets/export/template/import）
├── calc.py          # 计算引擎（占比/人数/KPI/录入模拟/加和校验）
├── constants.py     # 枚举常量 + 月份工具
├── io_xlsx.py       # Excel 导入导出/模板
├── urls.py          # DefaultRouter 注册
└── sample_data.py   # 种子数据
```

### 2.1 数据流

```
Person(主数据) ─┐
                ├─→ calc.py(纯函数) ─→ views @action ─→ 前端 ratio/plan/validate
ControlRule ────┘        ↑依赖
                   constants(枚举/容差)
```

设计原则：**calc.py 为纯函数**，输入「人员 dict 列表 + 规则 dict 列表」，输出核算结果；视图层只负责 ORM 取数、序列化、鉴权、事务，不写业务算法。

## 3. 数据模型

### 3.1 ControlDimension（维度）

| 字段 | 类型 | 说明 |
|---|---|---|
| name | CharField(16) unique | 维度名称 |
| code | CharField(16) | 编码（可选） |
| is_active | Boolean | 启用 |

### 3.2 ControlIndicator（指标）

| 字段 | 类型 | 说明 |
|---|---|---|
| dimension | FK → ControlDimension | 所属维度（CASCADE） |
| name | CharField(32) | 指标名称 |
| is_active | Boolean | 启用 |

唯一：`(dimension, name)`。

### 3.3 ControlRule（管控规则 — 单一事实来源）

| 字段 | 类型 | 说明 |
|---|---|---|
| bu / position / level | CharField | 适用范围（全空=全局） |
| dimension | FK | 维度 |
| indicator | FK | 指标 |
| year | Integer | 规划年度 |
| target | Decimal(6,4) | 目标占比（0~1，管控上限） |
| strength | CharField | 控制强度 |
| annual_target | Integer | 年度目标人数 |
| monthly_targets | JSONField | 长度 12 的数组（1月..12月） |

唯一：`(bu, position, level, dimension, indicator, year)`。
模型继承 `FullAuditModel`（审计）+ `UUIDModel`（nanoid 主键）；**硬删**。

### 3.4 Person（人员主数据）

| 字段 | 类型 | 说明 |
|---|---|---|
| code | CharField(32) unique | 人员编码 |
| name | CharField(64) | 姓名 |
| bu / school / sex / major | CharField | 部门 / 院校标签 / 性别 / 专业标签 |
| month | CharField(8) | 招聘月份（如 "8月"） |
| status | CharField | 已入职 / 已Offer / 候选池 |
| position / level | CharField | 职务 / 职级（用于命中适用范围） |
| counted | Boolean | 是否计入核算（默认 true） |

## 4. API 契约

基址：`/api/v1/campus/`。鉴权：`Authorization: Bearer <JWT>`。

### 4.1 资源端点（DefaultRouter）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/dimensions/` | 维度列表 / 新建 |
| GET/PUT/DELETE | `/dimensions/{id}/` | 维度详情 / 更新 / 删除 |
| GET/POST | `/indicators/` | 指标列表（`?dimension=` 过滤）/ 新建 |
| GET/PUT/DELETE | `/indicators/{id}/` | 指标详情 / 更新 / 删除 |
| GET/POST | `/rules/` | 规则列表（`?bu=&position=&level=` 过滤）/ 新建 |
| GET/PUT/DELETE | `/rules/{id}/` | 规则详情 / 更新 / 删除 |
| GET/POST/DELETE | `/persons/` | 人员主数据 CRUD |

### 4.2 自定义 Action（ControlRuleViewSet）

| 方法 | 路径 | 入参 | 返回 | 说明 |
|---|---|---|---|---|
| GET | `/rules/ratio/` | — | `{total, rows[], sumChecks[]}` | 实时看板占比核算（全量） |
| GET | `/rules/plan/` | `year, month` | `{rows[], kpi, year}` | 人数规划（按年/月）〔本期已移除〕 |
| POST | `/rules/validate/` | draft + `?year=` | `{verdict, checks[]}` | 录入校验模拟 |
| POST | `/rules/batch/` | `{bu,position,level,dimension,year,rules[]}` | `{saved}` | 批量保存（100% 硬校验，原子替换） |
| POST | `/rules/with-targets/` | `{bu,position,level,dimension,year,totalTarget,rules[]}` | `{saved,totalTarget,year}` | 批量配置规则+人数目标 |
| GET | `/rules/export/` | — | xlsx 文件流 | 导出全部规则 |
| GET | `/rules/template/` | — | xlsx 文件流 | 下载导入模板 |
| POST | `/rules/import/` | `file`(multipart) | `{groups, savedRules, errors[]}` | 导入 xlsx |

### 4.3 响应信封约定

- 列表（GET 集合）：`{ success, data:[...], pagination:{total,...} }`
- 单对象（POST/PUT）：裸 camelCase 对象
- @action：`{ success, data }`（失败 `{ success:false, detail }` 或 400）
- 删除：204
- **Decimal(target) 以字符串传输**，前端 `ruleToNum` 统一转 number

### 4.4 校验语义汇总

| 校验点 | 位置 | 行为 |
|---|---|---|
| 适用范围枚举 | serializer `_validate_scope_fields` | 非空时须在枚举内，归一空串 |
| 指标归属维度 | serializer / views | indicator.dimension_id == dimension.id |
| target 0~1 | serializer | 否则 400 |
| 唯一组合 | serializer / 模型 unique_together | 冲突 400 |
| 单条占比 ≤100% | serializer | 超 100% 拦截（防溢出） |
| 批量/导入 100% 加和 | views / io_xlsx | ≠100% 整体拒绝 |
| 月度之和=年度 | views `_normalize_monthly_targets` / io_xlsx | 不等则行级错误 |

## 5. 计算引擎（calc.py）

### 5.1 核心函数

| 函数 | 输入 | 输出 | 说明 |
|---|---|---|---|
| `rule_matches(p, rule)` | 人员, 规则 | bool | 适用范围匹配（空字段=不限） |
| `persons_for_rule` | 人员, 规则 | list | 命中范围且 `counted=true` |
| `count(persons, filters)` | 人员, 过滤条件 | int | 计数 |
| `ratio_of(rule, persons)` | 规则, 人员 | Decimal | 实际占比 = 命中指标数 / 适用范围计入人数 |
| `ratio_status(ratio, rule)` | 占比, 规则 | 正常/高于上限 | `ratio > target + RATIO_TOL` |
| `compute_ratio` | 人员, 规则 | `{total, rows[]}` | 实时看板主体 |
| `compute_count` | 人员, 规则, year, month | `CountRow[]` | 人数规划 + 在途 offer/待入职〔本期已移除〕 |
| `kpi` | 人员, 规则, year, month | KPI dict | 超标计数（本月总缺口部分已随人数规划移除） |
| `simulate` | draft, 规则, 人员, year, month | `{verdict, checks[]}` | 录入校验模拟 |
| `check_dimension_sums` | 规则, scope, year | `{dimension, sum, ok}[]` | 100% 加和校验 |

### 5.2 维度→人员字段映射

```python
维度 == '院校标签' → 人员.school
维度 == '专业标签' → 人员.major
维度 == '性别'     → 人员.sex
```

### 5.3 容差常量

```python
SUM_TOLERANCE = Decimal('0.0001')   # 100% 加和容差
RATIO_TOL      = Decimal('0.0001')   # 占比超标判定容差（吸收浮点毛刺）
```

### 5.4 在途统计口径（compute_count）

- `pendingOffer` = 命中指标且 `status='已Offer'`
- `pendingEntry` = 命中指标且 `status='已入职'` 且 `month=当前选中月`
- `annual_gap` = `max(annualTarget - onjob - pendingOffer - pendingEntry, 0)`

> 在途待入职为近似口径，详见需求文档 §9.1。

## 6. 导入 / 导出（io_xlsx.py）

### 6.1 列结构（模板 / 导出 / 导入共用）

| 列 | 字段 | 说明 |
|---|---|---|
| A | 维度 | dimension name |
| B | 指标 | indicator name |
| C | 部门 | bu（空=全局） |
| D | 职务 | position（空=不限） |
| E | 职级 | level（空=不限） |
| F | 规划年度 | year int |
| G | 目标占比(%) | 0~100，写库 ÷100 |
| H | 控制强度 | 硬约束/软约束/仅提示 |
| I | 年度目标人数 | int |
| J~U | 1月~12月目标 | 12 列 int |

### 6.2 模板生成

`build_template_workbook()`：说明区（填写说明）+ 表头行 + 1 行示例（院校标签·985，全局，2026，占比60%，年度100，月度均分）。返回 `(workbook, header_row)`。

### 6.3 导出

`build_export_workbook(rules)`：遍历 `_rule_to_dict` 结果，写入全部规则（按适用范围+维度+指标+年度排序），冻结首行，靛紫表头。

### 6.4 导入解析

`parse_import_workbook(file)`：

1. 自动定位含「维度」「指标」的表头行（兼容模板说明区偏移）。
2. 逐行基础校验（维度/指标/枚举/占比/强度/月度=年度）。
3. 按 `(bu, position, level, dimension, year)` 分组聚合。
4. 组级 100% 加和校验。
5. 返回 `(groups[], errors[])`。

视图 `import_xlsx` 对每个组调用 `_import_group`（事务原子替换旧规则 → 重建），返回 `{groups, saved_rules, errors}`。

## 7. 前端结构

### 7.1 页面

`web/app/src/pages/settings/CampusControl.vue`（单文件组件，1352 行）：

- **实时看板 Tab**：年份/月份选择器 + 5 张 KPI 卡 + `mergedColumns` 合并表（ratio 左连接 plan）+ 信息告警。
- **规则配置 Tab**：工具栏（维度筛选 + 导出/模板/导入/批量配置按钮）+ `ruleColumns` 表。
- **指标管理 Tab**：维度筛选 + 维度管理抽屉 + 指标新增/编辑。
- **录入校验 Tab**：草案表单 + 「校验判定」+ 结论与明细表 + 「确认录入」。
- 弹窗/抽屉：批量配置（`n-modal` 居中弹窗）、规则编辑抽屉、导入预览抽屉、维度管理抽屉。

### 7.2 API 封装

`web/app/src/api/campusControl.ts`：

- 常量导出：`DEPTS / SCHOOLS / MAJORS / SEXES / DIMS / STRENGTH / STATUS / POSITIONS / LEVELS / ALL_MONTHS`
- 类型：`ControlDimension / ControlIndicator / ControlRule / Person / RatioRow / PlanRow / Kpi / ValidationResult / RuleInput / BatchConfigPayload / RuleImportResult` 等
- 函数：`list/create/update/delete` × 维度/指标/规则/人员；`getRatio / getPlan / validateDraft / batchConfigRules / exportRules / downloadRuleTemplate / importRules`

### 7.3 合并表拼装

`mergedRows`（computed）：以 `ratioData.rows` 为主，按 `(bu|position|level|dimension|indicator)` 左连接 `planData.rows`；补齐 plan-only 行。两个接口的 `status` 语义不同（占比状态 vs 人数状态），分别映射为 `ratioStatus` / `countStatus`。

### 7.4 后端接口契约不变原则

实时看板（占比）在前端展示层渲染；原「占比 + 人数规划」融合设计已调整为仅占比，人数规划模块本期移除，`/rules/plan/` 接口契约相应废弃。后端 `/rules/ratio/` 契约保持不变。

## 8. 关键实现要点

1. **事务原子替换**：批量 / 导入以 `(适用范围, 维度, 年度)` 为单位 `delete()` + `bulk_create()`，避免半成功。
2. **Decimal 精度**：target 存 Decimal(6,4)；占比运算全程 Decimal，避免浮点误差。
3. **纯函数计算**：calc.py 不依赖 ORM，便于单元测试（`tests/` 目录）。
4. **枚举单一来源**：后端 `constants.py` 与前端 `campusControl.ts` 各维护一份枚举，需人工同步（建议后续抽取为共享常量或接口下发）。
5. **Excel 零重依赖**：仅依赖 openpyxl（已在环境内置），无需 pandas/xlsxwriter。

## 10. 已知技术债与改进项

1. **枚举双源同步**：前后端各维护一份枚举常量，易漂移；建议接口下发或代码生成。
2. **在途待入职口径**：依赖「招聘月份=当前月」近似，待独立到岗日期字段后修正。
3. **月度不一致脏数据**：prod 库若存在「月度之和≠年度目标」，导入会失败；建议在数据迁移加归一化守卫。
4. **指标删除约束**：规则引用中指标删除走外键级联，UI 未做引用检查提示。
5. **批量配置 UI 交互**：月度目标面板在指标较多时较长，可后续优化为折叠/分页。
