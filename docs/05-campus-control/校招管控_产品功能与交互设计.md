# 校招管控（campus_control）· 产品功能与交互设计

> 目的：基于兵哥提出的核心模型（维度+指标+部门+职务+职级+月度目标 组合成校验规则，校验时按候选人预计入职月份查占编数据判断是否触达管控线），先校准模型，再给出产品功能架构与页面交互设计。

> 配套文档：`校招管控_全局功能交互与校验分析.md`（实现层）、`删除维度规则集复盘与修复方案.md`（D1 修复）。

## 一、模型校准：认可，但需精确化 4 点

**结论：认可。** 兵哥的模型与 `calc.simulate` 的实际实现完全一致——规则由「适用范围 + 维度 + 指标 + 年度」唯一确定，校验时把候选人当作「在途待入职」叠加进占编，按**候选人的预计入职月份**与该月目标比对，判断是否触达管控线。

但代码实现比口头模型多了 4 个精确约束，产品设计前必须对齐：

| # | 精确化点                            | 代码事实                                                                                                                                                                                                         | 产品含义                                                                                                                                |
| - | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| ① | **规则唯一键含「年度」**                  | `ControlRule` 唯一键 `(bu,position,level,dimension,indicator,year)`；`simulate` 内 `if r.get('year') != year: continue`（`calc.py:246`）                                                                            | 月度目标挂在「某年度」下，跨年不共用。模型里"月度目标"是 **12 个值的数组**（每月 1 个），不是单一月度目标                                                                         |
| ② | **一条规则 = 一个指标**，不是"维度一条规则含全部指标" | 每个 (dimension, indicator) 在该 (scope, year) 下各生成 1 条 `ControlRule`，承载各自的 `target`(占比上限) + `monthly_targets[12]`                                                                                               | "维度+指标+…组合成一条规则"准确，但要强调：**维度下每个指标独立成规**，12 月目标挂在该指标规则上                                                                              |
| ③ | **占比与人数双语义，校验只看人数**             | 规则同时有 `target`(0~1 占比上限) 与 `monthly_targets`(人数)；`simulate` 注释明确"占比不再参与校验，仅用于规则配置时把规划人数按占比拆到各月"（`calc.py:239`）；触线判定 = `month_actual >= month_target`（`calc.py:261-264`）                                      | "触达管控线"**严格指人数达到月度目标**。占比**不参与录入校验**（M3 不出现占比判定线）；占比的作用是在规则配置时把规划人数按占比拆到各维度/指标、再拆到月度任务——即"占比只用于拆解月度任务"。看板的占比视图也仅作"月度任务拆解完成度"参考，非管控线 |
| ④ | **"占编数据"的范围与归属口径**              | `month_actual` = 统计 `sim = persons + [候选人]` 中「`counted=true` 且 status∈{在职,在途Offer,在途待入职}」且 `核算月份 == 候选人月份` 且命中规则 scope+指标 的人数（`calc.py:244-258`）；核算月份：在职按实际入职、在途按预计入职（`_accounting_month`，`calc.py:100-124`） | 占编 = 该规则该月**已分配名额**（含历史在途/在职），候选人按**预计入职月份**归属；不是某张静态"占编表"，而是实时计数                                                                   |

> 一句话校准后的模型：**规则 = (年度, 维度, 指标, 部门, 职务, 职级) → 12 个月度人数配额（含占比上限）；录入校验时，把候选人按预计入职月份并入该范围的占编计数，任一层级"本月实际 ≥ 本月目标"即触达管控线（阻断/警告）。**

> **模型更新（2026-08-27 规则配置规格）**：规则配置改为「单行规则 = 一个(维度,指标,部门,职务,职级,生效年度)组合」的扁平列表，每条规则带独立**规则编号 G+4 位流水号**与**启用状态**；原「维度规则集（多指标聚合 + 占比100%加和 + 范围重定位）」模型废弃。占比不再作为 UI 字段（与"占比只用于拆解月度任务"一致，月度拆解目标即为其落地形态）；「全局/指定范围互斥」由「6 字段组合唯一（统一校验逻辑）」自然取代。详见 §4.3。

## 二、产品定位与价值（Why / 非目标）

### 2.1 解决什么

校招是强计划、强管控场景：HR 按「院校/专业/性别等维度 × 组织（部门/职务/职级）」预设配额，在**录入候选人那一刻**实时拦截超配额，避免某类人群占比/人数失控（如某 BG 某专业 9 月已招满，再录即违规）。

### 2.2 非目标（Non-goals）

- ❌ 不是薪酬 / 绩效系统；
- ❌ 不是社招通用管控（校招强计划性，社招弱配额）；
- ❌ 不是人才库 / 简历解析系统（占编数据源来自 `Person`，但是是独立主数据）；
- ❌ 不做「人数规划」模块（本期已砍，仅保留实时看板占比）。
- ❌ 不对候选人 / 外部开放：录入校验（M3）是**内部运营工具**，仅系统运营人员使用。

### 2.3 三类用户与核心诉求

| 角色                        | 核心动作         | 诉求                                               |
| ------------------------- | ------------ | ------------------------------------------------ |
| **系统运营人员 / 校招 HR（高频，内部）** | 录入候选人、看是否触线  | 录入时**一眼看到**加这个人会超哪条线，能否提交；**M3 为内部运营工具，不对候选人开放** |
| **校招负责人（中频）**             | 设/调配额规则、监控达成 | 规则好建好改；统一校验保证同(维度,指标,部门,职务,职级,年)组合不重复；占比仅用于月度拆解 |
| **数据/合规（低频）**             | 查人员占编、审计     | 人员可溯、删除可恢复、规则变更有记录                               |

## 三、功能架构（What）

按用户故事拆 5 个模块，对应现有 8 功能域（见全局分析文档 §2），重新以产品视角归并：

| 模块                                | 对应功能域 | 核心能力                                             | 用户故事（节选）                                                    |
| --------------------------------- | ----- | ------------------------------------------------ | ----------------------------------------------------------- |
| **M1 维度与指标管理**                    | A + B | 自由建维度（院校标签/专业标签/性别…）、维度下挂指标（985/男/工学…）、启停        | 作为校招负责人，我希望建「院校标签」维度并挂 985/211/普通 指标，以便按院校设配额               |
| **M2 管控规则配置（核心）**                 | C     | 规则**扁平列表**（每条=一个 6 字段组合），含规则编号/启用状态；列表→详情查看与编辑；复制/停用/删除/启用；新增与编辑执行「统一校验逻辑」（6 字段组合唯一） | 作为校招负责人，我希望在列表里一眼看到全部配额规则、点开任一条看月度拆解，并能复制/停用/删除，以便灵活管理 |
| **M3 录入校验（moment of truth，内部运营）** | F     | 填候选人属性 → 实时命中规则 → 占编进度可视化 → 三态判定（阻断/警告/通过）→ 确认录入 | 作为系统运营人员，我希望录入时实时看到「该月占编 X/目标 Y、是否触线」，以便决定是否提交（**不对候选人开放**） |
| **M4 实时看板**                       | D     | 占比达成监控、加和告警、混合范围告警                               | 作为负责人，我希望一眼看全局各维度实际占比 vs 上限，以便及时发现超标                        |
| **M5 人员主数据**                      | G     | 占编数据源：人员增删改、counted 开关、核算月份字段                    | 作为 HR，我希望维护候选人占编信息（预计入职月份等），以便校验口径准确                        |

> **范围边界**：M3 是产品的「价值交付面」（日常最高频），M2 是「管控底座」，M4 是「监控面」。产品资源应优先保证 M3 的交互清晰度。

```
├─ 规则配置        （列表+详情，核心管理）
├─ 录入校验        （内部运营工具，仅系统运营人员）
└─ 基础设置
   ├─ 维度管理
   ├─ 指标管理
   └─ 人员数据
```

> 改「指标管理 / 规则配置 / 实时看板 / 录入校验 / 人员数据」5 Tab 为上述 4 页，把维度/指标/人员收进「基础设置」二级。**模块默认首页 = 实时看板（概览先行）**，用户再导航到规则配置（管理配额）或录入校验（运营操作）。

### 4.2 M3 录入校验页（核心交互，重点设计 · 内部运营工具，仅系统运营人员使用）

**布局：左表单 · 右实时占编面板**

```
┌─────────────────────────────┬──────────────────────────────────────────┐
│ 候选人信息                    │ 实时占编校验                                │
│ ─────────────────────────    │ ─────────────────────────────────────────  │
│ 部门  [能电BG        ▼]      │ 总判定：🔴 阻断提交（1 条规则已触线）        │
│ 职务  [            ▼]        │                                            │
│ 职级  [            ▼]        │ 命中规则（按预计入职月份 9月 比对）：        │
│ 院校  [985          ▼]        │ ┌────────────────────────────────────────┐ │
│ 专业  [工学          ▼]        │ │ 院校标签 · 985                           │ │
│ 性别  [男           ▼]        │ │ 范围：能电BG / 2026                      │ │
│ 预计入职月份 [9月    ▼]        │ │ 占编 12 / 目标 12   [████████████] 100% │ │
│ 状态  [在途待入职    ▼]        │ │ 🔴 本月已达标，不可再加（阻断）           │ │
│ 编码* [__________]  姓名* [__]│ ├────────────────────────────────────────┤ │
│                              │ │ 性别 · 男                               │ │
│ [ 校验判定 ]  [ 确认录入为人员 ]│ │ 占编 8 / 目标 10   [████████░░] 80%    │ │
│                              │ │ 🟡 未达配额，可提交（警告）              │ │
│                              │ └────────────────────────────────────────┘ │
└─────────────────────────────┴──────────────────────────────────────────┘
```

**交互要点**

1. **实时性**：填完「部门/职务/职级/院校/专业/性别/预计入职月份」6 个属性后即触发 `validateDraft(year, draft)`，无需点「校验判定」也能看到右面板（保留「校验判定」按钮供显式确认）；改动任一属性即时重算。
2. **占编进度条**：每条命中规则显示「占编 X / 目标 Y」+ 进度条 + 状态徽标。
   - 🟢 绿：X < Y 且剩余名额充足（建议剩余 > 总目标 20%）→ 通过；
   - 🟡 黄：X < Y 但剩余名额 ≤ 阈值（接近满）→ 警告，可提交；
   - 🔴 红：X ≥ Y → 阻断，确认录入按钮禁用。
3. **预计入职月份是比对锚点**：右面板标题明示"按预计入职月份 X月 比对"，让 HR 理解为什么比的是那个月。
4. **三态判定**：顶部总判定 = 任一红→阻断；否则任一黄→警告；否则通过（`calc.py:280` 的 `VERDICT_BLOCK/WARN/PASS`）。
5. **确认录入**：🔴 时按钮 `disabled` 并 tooltip「存在阻断规则」；🟡 时可点，提交时二次确认「将录入一条触线候选人」；🟢 直接提交（`canConfirmEntry` 口径见全局分析 §3.5）。
6. **混合范围不会命中**：适用范围恒为具体「部门+职务+职级」（部门空=全局组合），同一(维度,指标,部门,职务,职级,年)组合唯一（统一校验逻辑，见 §4.3.3），故 M3 右面板**不会出现混合范围分组**；若录入属性命中到冲突存量数据（存量迁移期），顶部 banner 显式提示"存在范围冲突，请联系负责人清理"，而非静默计入。

### 4.3 M2 管控规则配置页（列表 + 详情，核心管理）

> 模型变更：规则配置由「维度规则集（多指标聚合 + 占比 100% 加和 + 范围重定位）」改为**扁平列表**——每条规则 = 一个「维度 + 指标 + 部门 + 职务 + 职级 + 生效年度」组合，独立带规则编号与启用状态。原「占比视图/人数视图分 Tab」「范围重定位」「清空规则集」交互废弃；D1 自然消解、D7 由统一校验取代（见 §4.3.3 / §5）。

#### 4.3.1 规则列表页（展示所有规则）

- **规则组合项**（一条规则 = 一个组合）：维度 + 指标 + 部门 + 职务 + 职级 + 生效年度。
- **列表字段**：规则编号(G+4 位流水号) · 维度 · 指标 · 适用范围 · 生效年度 · 年度目标 · 控制强度 · 启用状态 · 操作(复制 / 停用或启用 / 删除)。
- **适用范围** = 部门 + 职务 + 职级（以「/」拼接展示；部门为空显示「全局」）。
- **点击行为**：点击当前行任意位置或规则编号 → 打开该规则**详情页**（4.3.2）。
- **筛选区（建议）**：维度 / 指标 / 部门 / 职务 / 职级 / 生效年度 / 启用状态，便于规则量增长后检索。
- **操作列**：
  - **复制**：生成一条「未启用」副本（新规则编号，其余字段同原规则）。
  - **停用 / 启用**：切换启用状态；停用后创建 Offer 时该校验立即失效（见 4.3.4）。
  - **删除**：二次确认后**硬删**（产品决策豁免项目 P0 软删规范，见 §5 D4）；删除后该校验立即失效。

#### 4.3.3 统一校验逻辑（核心约束）

- **规则集定义**：维度 + 指标 + 部门 + 职务 + 职级 + 生效年度 六字段共同构成**一个规则集**；同一规则集**只允许存在一条规则**（启用或停用均占用该组合；硬删除后该组合释放，可重建）。
- **校验时机**：
  - **新增**：保存时查重，命中即拦截「该规则集已存在规则 Gxxxx，不可重复创建」。
  - **编辑**：保存时若任一组合字段被改导致与另一条（非自身）规则冲突 → 拦截。
  - **启用**（复制副本 / 停用后重新启用）：启用动作本身执行统一校验；若 combo 已被其他规则（含停用）占用 → 拦截，提示先处理占用规则。
- **取代旧「全局/指定互斥」**：适用范围恒为具体「部门+职务+职级」，部门为空即「全局」组合——无法出现"同指标既全局又指定"的冲突态，原 D7 由此消解。

#### 4.3.4 状态 × 创建 Offer 校验生效关系

| 动作         | 对创建 Offer 校验的影响                | 实现要点                                       |
| ------------ | ------------------------------------- | ---------------------------------------------- |
| 停用规则     | 立即失效（不参与 `simulate` 占编计数） | `simulate` 过滤 `enabled=True`                 |
| 删除规则（硬删） | 立即失效（行物理移除，`simulate` 自然不可见） | 仅统计 `enabled=True` 且存在的行；硬删除豁免软删规范（见 §5 D4） |
| 复制规则     | 副本默认未启用 → 不参与校验，直到启用   | `enabled` 默认 False                           |
| 启用规则     | 执行统一校验，通过后才生效             | 启用前查重                                     |
| 编辑规则     | 不改启用状态；若改组合字段触发统一校验 | 保存时校验                                     |

#### 4.3.5 字段与数据模型映射（新增 / 调整）

| 字段            | 类型           | 说明                                                                                       |
| --------------- | -------------- | ------------------------------------------------------------------------------------------ |
| rule_no         | 字符(G+4 位)   | 新增时生成（序号自增），不可编辑；复制生成新号                                             |
| dimension / indicator / bu / position / level / year | 维/指/组织/年 | 6 字段组成唯一规则集（即现有唯一键）                                                       |
| annual_target   | 整数           | 年度目标（人数）                                                                           |
| monthly_targets | JSON[12]       | 月度拆解目标，和须 = annual_target（保存校验）                                             |
| strength        | 硬约束 / 软提示 | 控制强度                                                                                   |
| handle_mode     | 阻断 / 警告 / 仅提示 | 处理方式（触线时系统行为，映射 M3 三态：阻断→🔴、警告→🟡、仅提示→🟢）              |
| enabled         | 布尔           | 启用状态，新增默认 True；复制默认 False                                                    |
| target（占比）  | 浮点           | **UI 不展示**；保留为内部/可选规划字段（占比只用于拆解月度任务，月度拆解目标即其落地形态） |

### 4.4 M4 实时看板页

- **KPI 卡片（4 张）**：计入核算人数 / 管控规则数 / 硬约束超标数 / 软提示超标数（砍掉"本月总缺口"，人数规划已移除）。
- **占比表（月度任务拆解视图）**：维度·指标·范围 / 实际占比 / 目标上限 / 状态(正常/高于上限) / 强度。状态=实际 > 目标+容差 → 高于上限（红）。**说明**：占比不参与录入校验，此表仅作"月度任务拆解完成度"参考——规划人数是否按占比合理拆到各维度/指标。
- **加和告警**：`sumChecks` 对任意 (scope,维度,年) 占比之和≠100% 提示（占比拆解完整性校验）。
- ~~**混合范围告警**~~：已移除——适用范围恒为具体「部门+职务+职级」，同一 6 字段组合唯一（见 §4.3.3）。

### 4.5 M5 基础设置（维度/指标/人员）

- **维度管理**：卡片/列表，启停开关；删除二次确认（**文案补全"将同时删除 N 条规则"**，解 D3）。
- **指标管理**：按维度分组列表；新增/编辑共用弹窗（维度编辑态锁定）；删除确认补全级联规则数（D3）。
- **人员数据**：占编数据源；counted 开关控制是否计入；预计/实际入职日期决定核算月份（校验口径地基）。

### 4.6 增删改交互（承接全局分析 §7）

维度/指标/人员三类实体的新增·编辑共用 `NModal`+`editingId`、删除走 `useDialog` 二次确认（详见全局分析 §7）；**规则**的交互按本规格 §4.3 改为「列表 + 详情」模型，与三类实体不同：
- **规则新增/编辑**：走详情页编辑态，保存时执行「统一校验逻辑」（6 字段组合唯一）；规则编号不可编辑。
- **规则复制**：生成未启用副本（新规则编号），不触发即时校验，待启用时校验。
- **规则停用/启用**：状态切换即时生效；停用/删除后创建 Offer 校验立即失效（见 §4.3.4）。
- **规则删除**：二次确认 + **硬删**（产品决策豁免软删规范，D4 已关闭）；删除即失效。
- **统一改进**：维度/指标删除确认文案补全级联规则数（解 D3）；配置/规则类实体**豁免项目 P0 软删**（硬删，由「停用」提供产品层可逆性），D4 已关闭。

## 五、与现有缺陷的衔接（产品层怎么解）

| 缺陷           | 产品层解法                                                               |
| ------------ | ------------------------------------------------------------------- |
| D1 删除规则集无法清空 | **本新模型下自然消解**：规则改为单行独立增删，不再有"清空规则集"概念；逐条删除即可（见 §4.3.1） |
| D3 隐式级联删规则   | 删除确认文案显式"将删除 N 条规则"，不让用户意外丢失配额                                      |
| D4 硬删违规规范    | **已决策豁免**：配置/规则类实体（Dimension/Indicator/Rule）采用硬删，不补 `deleted_at`；产品侧「停用」提供可逆性，删除为显式终态。Person（人员主数据）是否豁免待评估（见 §6） |
| D7 指定/全局范围冲突 | **由「6 字段组合唯一（统一校验逻辑）」取代**：适用范围恒为具体「部门+职务+职级」，部门空即"全局"组合，无法出现同指标既全局又指定；原静默清全局逻辑废弃（见 §4.3.3） |
| D5 录入跨年度     | 录入校验按 `year` 过滤规则（产品或文档明确"月度目标按年隔离"）                                |
| D6 人数加和仅前端约束 | 转为「月度拆解之和 = 年度目标」单规则一致性校验（前端 + 后端 `set_rules` 均校验）；原"同 scope 各指标人数加和"概念随扁平模型废弃 |

## 六、待确认事项（产品决策点）

> **已确认决策（✅）**
>
> - ✅ **混合范围互斥**：相同(维度,指标,年)下，全局与指定范围**不允许并存**（逻辑冲突）。产品改「互斥硬校验」——保存指定范围时若已存在同指标全局规则则拦截，反之亦然；不再静默互删（落地见 §4.3·5 / §5 D7）。
> - ✅ **占比不参与校验，只用于拆解月度任务**：M3 录入校验仅判人数；占比在 M4 看板中仅作"月度任务拆解完成度"参考，非管控线（见 §1·③ / §4.4）。
> - ✅ **录入校验为内部运营工具**：M3 不对候选人/外部开放，仅系统运营人员使用（见 §2.2 / §2.3 / §4.2）。
> - ✅ **警告阈值**：黄/绿分界取"剩余名额 ≤ 总目标 20%"，维持不变（见 §4.2·2）。
> - ✅ **规则配置改为扁平列表+详情模型**：每条规则=一个 6 字段组合，带规则编号(G+4位)与启用状态；统一校验逻辑（6 字段组合唯一）取代原全局/指定互斥与占比100%加和；复制默认未启用、启用时校验；停用/删除即时失效。详见 §4.3。
> - ✅ **默认首页 = 实时看板**：模块落地页展示占比/达成概览，用户再导航到规则配置或录入校验（见 §4.1 页面树）。
> - ✅ **软删豁免（D4 关闭）**：campus_control 配置/规则类实体（Dimension/Indicator/Rule）**豁免项目 P0 软删规范、采用硬删**——「停用」已提供产品层可逆性，删除为显式终态操作，规则属低风险配置数据，恢复可由「复制/新增」完成。Person（人员主数据，属核算快照）是否同样豁免另行评估（建议保留可追溯）。

> **未确认决策（仅 1 项待定）**
>
> 1. **Person（人员主数据）软删策略**：维度/指标/规则已确认硬删豁免，但 Person 是看板核算的历史快照，误删会影响历史达成数据。建议 Person 保留可追溯（软删或审计日志），是否随配置实体一并豁免，待拍板。

> 以上确认后，可据本设计直接落地前端页面（实时看板为首页 + 规则配置列表/详情为优先）+ 后端 D1 已自然消解、D4 已关闭。
