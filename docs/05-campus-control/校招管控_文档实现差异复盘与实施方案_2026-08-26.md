## 0. 结论速览

- **20 项差异**：A 类 4 项（文档声明已改、代码未同步）、B 类 8 项（文档定义、实现缺失/不一致）、C 类 7 项（分析文档 D1–D7 缺陷全部未修）、D 类 1 项（文档自相矛盾）。
- **最大裂缝 A1**：三份文档均声明「人数规划模块本期已移除」，但后端 `plan` 端点、`compute_count/kpi` 计算引擎、前端 `getPlan` 调用、KPI 第 5 张卡「本月总缺口」、年份/月份联动选择器**全部还在生产运行**。文档与实现出现了整整一个模块级别的分歧。
- **最隐蔽缺口 B4/B5**：08-26 动态维度改造后，「维度/指标/规则」全链路已动态化，但**人员侧无任何动态维度入口**（表单/序列化器/导入全缺）——身份证籍贯规则能导入、看板能显示，但人数恒为 0。且 legacy 三维度（院校/专业/性别）的人员下拉用前端写死常量，指标库新增指标人员永远填不了。
- **文档本身过时**：技术文档 v2.4（08-23）落后代码两轮大改（08-25 v2.7 录入校验、08-26 动态维度+指标 IO），至少 6 处描述与代码不符。

## 2. 分类详述

### 2.1 A1 · 人数规划「假移除」（最严重）

三份文档一致声明移除，但代码完整存活且深度耦合看板：

| 层 | 残留物 | 位置 |
|---|---|---|

| 后端 | `compute_count` + `kpi`（本月缺口计算） | calc.py:176-253 |
| 前端 | `getPlan` 调用 + `planData` 状态 | CampusControl.vue:817, 677-679 |
| 前端 | KPI 第 5 张卡「本月总缺口」 | :28 |
| 前端 | 年份/月份选择器（绑定 loadPlan）+「人数达成」提示 | :17-19 |
| API | `getPlan` 封装 + PlanResult 类型 | campusControl.ts |

矛盾根源推测：移除决策做出后只写了文档（§4.1「本期移除」、§7.3「契约废弃」），未排代码清理。两条收敛路径见 §3 G1。

### 2.2 B4+B5 · 维度体系「上半身动态、下半身写死」

08-26 动态维度改造（commit `4c06161`）打通了「维度管理 → 指标管理 → 规则导入 → 计算引擎」，但人员取值侧三道闸门全部关闭：

```
维度/指标/规则（动态 ✅）──→ 计算引擎（通用 ✅）──→ 人员取值（写死 ❌）
```

1. **人员表单**：personModal 只有固定 13 字段（:569-584），无动态维度区。
2. **PersonSerializer**：无 `dimensions` 读写字段（serializers.py:209-256）→ PersonDimensionValue 表建了但无写入通道。
3. **录入校验**：draft 固定字段（:1575+）→ `_draft_hits_rule` 按 `__dim__<名>` 取值永远 miss → 动态维度规则在校验中永不命中。
4. **人员导入**：端点不存在（今天拍板的「人员导入加籍贯列」方案即为此，未实施）。
5. **legacy 脱钩（B5）**：即便不动态维度，指标库对 legacy 三维度同样脱钩——人员下拉=前端常量+后端写死 choices 双重锁死。

### 2.3 B1 · 录入校验语义三方漂移

同一功能三种口径并存：
- 后端（v2.7 拍板版，正确）：本月实际 ≥ 本月目标 → ❌ 阻断；< 目标 → ⚠️；占比永不参与。
- 需求文档（v2.5 旧版）：硬约束超标 → 阻断。
- 前端文案（CampusControl.vue:133-134）：「命中硬约束超标，系统已阻断提交」——**用户看到的解释与真实判定逻辑不符**，会误导排障。

### 2.4 C 类 · D1–D7 欠账现状

分析文档已给出完整方案（D1 详案在同目录《删除维度规则集复盘与修复方案.md》），全部未动工。本次仅复核 D5 属实：`simulate()` 签名收 `year` 但函数体不使用（calc.py:270, 299 循环无 year 过滤）。
