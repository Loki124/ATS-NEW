# 校招管控（campus_control）模块 · 全局功能·交互·校验分析

> 分析范围：前端 `web/app/src/pages/settings/CampusControl.vue` + `api/campusControl.ts`；后端 `apps/django/apps/campus_control/`（models / serializers / views / calc / constants）。
> 目的：盘点模块全部功能交互、前端与后端校验逻辑、对应业务语义；并基于全局视角指出设计漏洞与方案缺陷（含此前复盘的「删除维度下多个指定范围指标」问题）。
> 代码基准：v2.7（录入校验只看人数）。

---

## 0. 速读结论

- **模块由 4 个领域实体 + 5 个前端 Tab + 8 类功能域** 组成，规则（ControlRule）是「占比 + 人数」的单一事实来源。
- **校验分三层**：前端交互校验（computed + 保存前拦截）、后端 serializer 字段校验、后端 view action 业务校验（占比 100% 硬校验 / 适用范围互斥 / 月度一致性）。
- **发现 7 处设计漏洞/缺陷**（D1–D7），其中 **D1（删除规则集无法清空）为最高优先级**，即此前复盘的「删除维度下包含多个指定范围指标」问题；D3/D4 为数据一致性风险，D5/D6 为语义/一致性隐患。
- 所有「批量替换」端点（set_rules / batch / with_targets / import）**都将「规则集非空 + 占比之和=100%」当作不变式**，导致「清空规则集」这一合法操作在所有入口都被拦截，这是 D1 的根因。
- **范围调整（本期）**：「人数规划」模块已移除，校招管控仅保留「实时看板（占比）」作为唯一统计展示出口；原 `compute_count` / `getPlan` / `kpi`（本月缺口部分）等人数规划相关实现待清理。

## 1. 模块定位与领域模型

### 1.1 四个领域实体

| 实体 | 说明 | 关键字段 | 删除方式 |
|------|------|----------|----------|
| `ControlDimension` 维度 | 院校标签/专业标签/性别，可自由新增 | name(unique), code, is_active | 硬删（CASCADE 指标+规则） |
| `ControlIndicator` 指标 | 维度的分类（985/男/工学…） | (dimension, name) unique, is_active | 硬删（CASCADE 规则） |
| `ControlRule` 规则（核心） | 单条「适用范围+维度+指标+年度」→ 占比上限 + 强度 + 年度人数 + 12 月人数 | (bu,position,level,dimension,indicator,year) unique；target(0~1)；annual_target；monthly_targets[12] | 硬删（**D4 已豁免软删**） |
| `Person` 人员主数据 | 一行一人，counted 控制是否计入核算 | code(unique)；bu/school/sex/major/month/status；position/level；counted | 硬删（**Person 软删策略待评估**，见 D4） |

### 1.2 关键关系与约束

- **适用范围语义**：`bu/position/level` 三者均空 = 「全局」；否则按部门/职务/职级过滤（均可空 = 不限）。
- **规则唯一键**：`(bu, position, level, dimension, indicator, year)`。
- **占比加和不变式**：同一 `(适用范围, 维度, 年度)` 下所有 indicator 的 `target` 之和必须 == 1.0（100%），由批量端点硬校验。
- **人数目标承载于规则**：各指标 `annual_target` + `monthly_targets[12]`（长度 12，和须等于 annual_target）。
- **核算口径**：Person 中 `counted=true` 且状态 ∈ `{在职, 在途Offer, 在途待入职}` 才计入分母；「在职」按实际入职日期、「在途」按预计入职日期归入核算月份（`calc._accounting_month`）。

### 3.3 C 规则配置（核心交互）

> 所有规则编辑都进入「维度规则集编辑面」（`dimEditor` 弹窗）。该面以「维度 + 适用范围 + 年度」为上下文，展示该维度**全部指标**，逐行编辑占比%/强度/年度/12 月，整体原子保存。

| 功能 | 交互入口 | 调用 API | 前端校验（保存按钮 `:disabled` 或保存前） | 后端校验（`set_rules`） | 功能说明 |
|------|----------|----------|----------|----------|----------|
| C1 新增规则 | 「+ 新增规则」→ 选维度/适用范围/年度 → 逐行设值 | `saveDimensionRuleSet` | 维度必选；至少 1 个有效指标（`validRows.length>0`） | 指标须属该维度；target 0~1；strength 合法；**占比之和==100%（容差 0.01%）**；annual/monthly 成对或都缺（缺则继承旧规则）；若都传则 `sum(monthly)==annual` | 为某(适用范围,维度,年度)建立/覆盖全部指标的占比与人数目标 |
| C2 编辑规则 | 规则列表「编辑」→ 锁定维度/年度，适用范围可改 | 同上 | 同上；适用范围变更标记 `scopeDirty` | 同上 + **适用范围互斥守卫** | 修改既有规则集 |
| C3 删除指标 | 规则列表「删除」→ `openDimensionEditor(r,{preDelete})` 标记 `pendingDelete` | 同上（保留其余行） | **删除全部→`validRows.length==0` 拦截**；删除部分→`dimEditorSumOk`（占比须=100%）必须成立 | 同 C1（仍强制占比==100%） | 从规则集移除某指标。**删除全部指标时无法保存（D1）** |
| C4 保存维度规则集 | 弹窗「保存」 | `PUT /dimensions/{id}/rules/` | ① 至少 1 指标 ② 占比==100% ③ 人数加和==维度总人数 ④ 每行 12 月之和==年度；任一不满足 `message.warning` 并 return | 事务内删旧+重建；100% 硬校验；互斥守卫 | 原子替换该(适用范围,维度,年度)全部规则 |
| C5 适用范围重定位 | 编辑态改适用范围/年度 | 同上（带 `original`） | 弹窗二次确认「迁移」 | `_scope_mutex_guard`：指定范围→删全局；全局→若存在指定范围则 400 拦截 | 把规则集从旧 scope 迁到新 scope（删旧建新） |
| C6 全局/指定互斥 | 保存前自动判定 | — | 保存全局且存在指定范围→`dialog.error` 拦截；保存指定且会清全局→`dialog.warning` 确认 | `_scope_mutex_guard` 非对称策略 | 防止同一(维度,年度)同时持有全局+指定范围导致**重复计入** |
| C7 导出规则 | 「导出规则」 | `exportRules` | 无 | 无 | 导出全部规则 xlsx |
| C8 导入规则 | 「导入规则」→ 选 xlsx | `importRules` | 文件类型 xlsx/xlsm | 按(适用范围,维度,年度)分组；每组独立事务；100% 校验 + 月度一致性；任一组失败整体回滚并返回错误 Excel | 批量覆盖写入规则 |

**维度规则集编辑面的 4 个前端 computed 校验（C 域核心）：**

| computed | 公式 | 校验含义 | 失败后果 |
|----------|------|----------|----------|
| `dimEditorSumOk` | `abs(占比之和% − 100) < 0.05` | 未删除指标占比之和须=100% | 保存按钮禁用 + 提示 |
| `dimEditorTotalOk` | `未删行年度人数加和 === round(维度总人数)` | 各指标年度人数加和须等于顶部「维度年度管控人数」 | 保存按钮禁用 + 提示（**后端不强制，见 D6**） |
| `dimEditorActiveAnnualSum` | 未删行 `annualTarget` 求和 | 实时展示人数加和 | 展示用 |
| `dimRowMonthlyOk(row)` | `sum(该12月) === 年度人数` | 单行月度之和须=年度 | 提示+保存拦截 |

## 4. 校验逻辑分层总览

### 4.1 前端校验（CampusControl.vue）
- **保存按钮禁用**：`saveDimRuleSet` 的 `:disabled="!dimEditorSumOk || !dimEditorTotalOk"`。
- **保存前拦截**（`saveDimRuleSet` 函数内 4 道 gate）：
  1. `validRows.length === 0` → 「请至少保留一个指标并设置占比」【D1 触发点】
  2. `!dimEditorSumOk` → 「占比之和须=100%」
  3. `!dimEditorTotalOk` → 「人数加和须等于维度总人数」
  4. `badMonths.length` → 「12 月之和 ≠ 年度人数」
- **互斥前置提示**：保存全局且存在指定范围 → `dialog.error` 直接拦截；保存指定且会清全局 → `dialog.warning` 确认。
- **表单级必填**：维度名/指标名/人员编码姓名非空（轻量 `message.warning`）。

### 4.2 后端校验
| 层 | 位置 | 校验内容 |
|----|------|----------|
| serializer | `ControlRuleSerializer.validate` | 适用范围枚举、维度/指标必填且指标∈维度、target 0~1、strength 合法、唯一键、(单条)超 100% 拦截 |
| view action | `set_rules` / `batch` / `with_targets` / `_import_group` | **占比之和==100%（容差 0.0001）**、指标∈维度、annual/monthly 成对、月度之和==annual、适用范围互斥守卫 |
| view action | `validate` | draft 必填字段(bu/school/sex/major)、year 整数 |
| view action | `_scope_mutex_guard` | 全局 vs 指定范围非对称互斥（指定→删全局；全局→存在指定则 400） |
| import | `importIndicators` / `import_xlsx` | 文件解析、维度存在、名称≤32、文件内不重复、mode 处理、错误 Excel 报告 |

### 4.3 计算引擎口径（calc.py）
- **占比状态**：`实际 > target + 0.0001` → 高于上限；否则正常（取消下限）。
- **人数状态**：`actual ≥ target` → 本月达标；`actual < target` → 缺口未达成；`target=0` → 未设目标。〔注：该口径原服务于「人数规划」模块，本期已移除；底层 `count_status` 函数仍被录入校验 `simulate` 复用，故保留。〕
- **录入 verdict**：任意命中规则「本月实际≥本月目标」→ 阻断；否则有「<目标」→ 警告；否则通过。
- **核算月份**：在职按实际入职日期、在途按预计入职日期，缺失回退 `month` 字段。

## 5. 设计漏洞与方案缺陷清单（D1–D7）

### D1【严重·最高优先级】删除规则集无法清空（即「删除维度下多个指定范围指标」）
- **现象**：在规则配置中删除某适用范围下的全部指标（无论 1 个还是多个指定范围指标）时，保存操作被拦截，无法完成。
- **复现路径**：规则列表「删除」→ 标记 `pendingDelete` → 继续删到 `validRows.length===0` → 保存按钮因 `!dimEditorSumOk`（占比和=0%）禁用；即便绕过前端，后端 `set_rules` 对空 `rules` 仍报「占比之和须=100%」400。
- **根因**：所有「批量替换」端点把「规则集非空 + 占比=100%」当作不变式，系统**没有「清空规则集」这一语义**。删除最后一条指标 = 清空，但代码视其为「非法的不完整规则集」。
- **影响**：用户无法删除某适用范围下的全部规则（只能留 1 条、改占比为 0%、或导入覆盖），体验阻断且不符合「删除」直觉。
- **修复方向（推荐）**：
  1. **前端**：`saveDimRuleSet` 识别「全部标记删除」→ 放开 4 道 gate 中占比/人数校验，文案改为「保存后将清空该(适用范围,维度,年度)下的规则集」并二次确认。
  2. **后端**：`set_rules`/`batch`/`with_targets`/`_import_group` 对**空 rules（或全删）**走「清空分支」——跳过 100% 校验、跳过互斥守卫、事务内 `delete` 旧规则集。
  3. **可选增强**：规则列表增加「清空规则集」快捷入口，缩短操作路径。
- **不建议**：自动把删除指标占比重分配给其余指标（篡改用户未意图修改的目标，违背可控性）。

### D2【一致性】单条规则 API 与批量端点校验语义不一致
- **现象**：`createRule`/`updateRule` 的 serializer 仅拦「超 100%」，允许留下 <100% 的规则集；而批量端点强制 =100%。
- **根因**：两套校验逻辑（serializer vs view action）独立演进，前端又只走批量入口，单条路径成「死代码 + 隐藏不一致」。
- **影响**：若未来接入单条编辑入口，可写入「缺 100%」的规则集，污染看板 `sumChecks` 与互斥判定。
- **建议**：要么在前端/文档明确弃用单条 API；要么强化 serializer 在单条场景下也提示「同组占比未达 100%」（不强制，但告警）。

### D3【数据一致性·隐式级联】删除指标/维度会静默级联删规则
- **现象**：`removeIndicator` 硬删指标（外键 CASCADE）会删除该指标名下**所有规则**；`removeDim` 同理级联删指标+规则。
- **根因**：模型 `on_delete=CASCADE`；UI 确认文案只提「删除指标/维度」，未提「同时删除其下 N 条规则」。
- **影响**：用户无意中删指标，关联的全部占比/人数目标悄无声息丢失，且看板/规划即时失准。
- **建议**：删除前二次确认文案明确「将同时删除该指标下的 N 条规则」；或改软删（置 `deleted_at` + 过滤），与 D4 合并处理。

### D4【与项目规范冲突】campus_control 全模型硬删

> **状态：已决策关闭（豁免）** —— 产品拍板（2026-08-27）：campus_control 配置/规则类实体（Dimension/Indicator/Rule）**豁免项目 P0 软删规范、采用硬删**，不补 `deleted_at`。

- **现象**：`ControlDimension/Indicator/Rule/Person` 均无 `deleted_at`，`perform_destroy` 直接 `instance.delete()`。
- **根因**：模块注释明确「删除采用硬删」，与项目 P0 软删规范冲突；但产品层已存在「停用」状态（可逆、校验失效但不丢数据）作为兜底，删除是显式终态，且规则/维度/指标属低风险配置数据。
- **影响（已可接受）**：配置/规则类误删可由「复制/新增」恢复，风险可控；**Person（人员主数据）是否同样豁免待评估**——人员是看板核算历史快照，误删影响历史达成数据，建议保留可追溯（软删或审计日志）。
- **结论**：Dimension/Indicator/Rule 维持硬删，D4 对这三类**关闭**；Person 软删策略单列待定。

### D5【语义严谨性】录入校验跨年度匹配
- **现象**：`simulate()` 遍历 `rules` 不按 `year` 过滤（validate action 传了 year 但内部未使用）；draft 也不含 year。
- **根因**：月度目标 `monthly_targets` 无年度区分，simulate 设计上「跨年共用」，但同一 indicator+scope 多年度规则会重复进入 checks。
- **影响**：若某(维度,指标,scope)存在多套年度规则，录入校验会重复计次、verdict 可能误判；且「规划年度」概念在录入侧缺位。
- **建议**：`simulate` 按传入 `year` 过滤 rules（或明确文档说明「月度目标故意跨年共用、录入校验忽略年度」）。

### D6【一致性】人数加和仅前端约束
- **〔范围澄清〕**：本项指**规则配置（C 域）保存时「各指标年度人数加和 == 维度总人数」的前端校验**，与已移除的「人数规划」看板模块是两回事；规则配置保留，故此缺陷仍有效（防止规则人数目标内部不齐）。
- **现象**：`dimEditorTotalOk`（各指标年度人数加和 == 维度总人数）是前端独有校验；后端 `set_rules`/`batch` 不强制「同 scope 维度年度 各指标 annual_target 之和」一致（`with_targets` 按 totalTarget 推导，不校验前端传值之和）。
- **根因**：人数加和约束只在前端实现，后端只校验「单行月度之和==年度」。
- **影响**：绕过前端直接调 API 可写入「人数加和不齐」的规则集，规则人数目标自相矛盾（占比看板不读人数加和，但人数目标是规则的一部分，不齐会导致规则数据不可信）。
- **建议**：后端 `set_rules` 补「同(scope,维度,年) 各指标 annual_target 之和 == 前端传 totalTarget（或某基准）」的一致性校验（按产品是否要求强一致决定严格度）。

### D7【互斥守卫边界】指定范围保存静默删全局 → 产品决策改为互斥硬校验

> **产品决策（2026-08-27 兵哥拍板）**：「相同(维度,指标,年)下不能既有全局又有指定，这是逻辑冲突」——**全局与指定范围互斥，不允许并存**。因此 D7 的解决方案从「静默删全局 + 提示」升级为**互斥硬校验：保存时若同(维度,指标,年)已存在另一种范围，直接拦截并提示，不再静默删数据**。
> **进一步（2026-08-27 规则配置规格）**：适用范围固定为具体「部门+职务+职级」（部门空=全局组合），由「维度+指标+部门+职务+职级+生效年度」六字段组合唯一（统一校验逻辑）自然取代全局/指定互斥，无需单独的互斥守卫。详见 `校招管控_产品功能与交互设计.md §4.3.3`。

- **现状（待改造）**：`_scope_mutex_guard` 在保存「指定范围」时**自动 `delete` 该维度年度的全局规则**（非对称互斥），前端虽有二次确认，但属静默数据变更。
- **根因**：非对称互斥策略（产品早前澄清「只删全局、其他指定范围不动」）。
- **影响**：用户确认「指定范围保存」即触发全局规则删除，若未细读提示可能误删——与「逻辑冲突不允许并存」的产品意图不符。
- **目标解法（已被新规格取代）**：最新规则配置规格将「适用范围」固定为具体「部门+职务+职级」，并以「维度+指标+部门+职务+职级+生效年度」六字段组合唯一（统一校验逻辑）取代全局/指定互斥——同一组合只允许一条规则，新增/编辑/启用均校验。原 `_scope_mutex_guard` 对称互斥与静默 `delete` 全局逻辑废弃。详见 `校招管控_产品功能与交互设计.md §4.3`。

## 7. 增删改交互方案（按实体）

> 本节把 §3 中分散在各功能域的「新增 / 编辑 / 删除」交互收敛为统一方案，明确 **触发入口 → 交互形态 → 字段与默认值 → 实时校验时机 → 二次确认 → 提交与反馈 → 失败回滚**。所有描述均对应 `CampusControl.vue` 真实实现（行号见括号内）。
> 四类实体的增删改共用同一套骨架：**弹窗（NModal preset=card）承载新增/编辑；`useDialog` 二次确认承载删除**。

### 7.1 统一交互骨架

| 要素 | 新增 / 编辑 | 删除 |
|------|-------------|------|
| 交互形态 | 居中 `NModal`（preset=card），标题按 `editingId` 动态显示「新增X / 编辑X」(`CampusControl.vue:541/555/569`) | 居中 `useDialog` 警告框（`dialog.warning`，positiveText=「删除」，negativeText=「取消」） |
| 数据载体 | `reactive` 表单对象（`dimModal/indicatorModal/personModal/dimEditor`），`open*Modal(x?)` 用入参回填、无入参则清空为默认值 | 直接拿列表行对象 `x` 调 `deleteX(x.id)` |
| 必填校验 | 保存函数内轻量 `message.warning` 拦截（名称/维度/编码姓名非空） | 仅二次确认，无额外前置校验 |
| 提交 | `createX` / `updateX`（`editingId` 决定），成功 `message.success('保存成功')` 并 `modal.show=false` | `deleteX` 成功后 `message.success('删除成功')` |
| 失败 | `catch → message.error(extractApiError(e,'保存失败'))`，**弹窗保持打开**便于修正 | `catch → message.error(extractApiError(e,'删除失败'))`，确认框已关闭 |
| 刷新 | `await loadX()` 重新拉取列表 | 删维度/指标后 `await Promise.all([loadDimensions(), loadIndicators()])`（维度级联刷新指标）；删人员仅 `loadPersons()` |
| 加载态 | `:loading` 绑定 `loading.*`，防重复提交 | 无独立 loading 标记（确认即调，依赖 API 响应） |

### 7.2 A 维度：新增 / 编辑 / 删除

**新增 / 编辑（共用 `dimModal`）**
1. 入口：指标管理 Tab →「管理维度」→「+ 新增维度」或维度列表「编辑」(`openDimModal`) (`CampusControl.vue:520-524/1520`)。
2. 弹窗字段：维度名称（required，placeholder「如 学历 / 院校标签」）、编码（optional，placeholder「如 education」）。
3. 编辑回填：`editingId` 非空时标题变「编辑维度」，名称/编码回填；保存走 `updateDimension(editingId,{name,code})` (`1529`)。
4. 校验：仅「名称非空」（`!name.trim()` → warning）；编码可空 (`1527`)。
5. 提交成功关闭弹窗并重载维度列表 (`1533`)。

**删除（`removeDim`）**
- 入口：维度列表「删除」(`924`) → `dialog.warning` 标题「删除维度」，正文「确认删除维度「X」？该维度下的指标将一并删除。」(`1538`)。
- 二次确认后 `deleteDimension(id)`，级联刷新维度+指标列表 (`1540`)。
- ⚠️ 文案仅提示「指标一并删除」，**未提示其下规则也会被 CASCADE 删除**（详见 D3）。

### 7.3 B 指标：新增 / 编辑 / 删除

**新增 / 编辑（共用 `indicatorModal`）**
1. 入口：指标管理 Tab「+ 新增指标」或列表「编辑」(`openIndicatorModal`) (`1548`)。
2. 弹窗字段：所属维度（`n-select`，编辑态 `:disabled` 锁定不可改）、指标名称（required）。
3. 默认值：新增时维度预填当前筛选维度 `indicatorDimFilter`；名称空 (`1550-1551`)。
4. 校验：维度必选 + 名称非空（`!dimensionId || !name.trim()` → warning）(`1555`)。
5. 提交：`editingId` 走 `updateIndicator` 仅传 name（维度 locked）；新增走 `createIndicator({dimension,name})` (`1557-1558`)。

**删除（`removeIndicator`）**
- 入口：指标列表「删除」(`902`) → `dialog.warning` 标题「删除指标」，正文「确认删除指标「X」？」(`1566`)。
- ⚠️ 文案**仅提指标本身，未提示其名下全部规则将被 CASCADE 删除**（D3）。

### 7.4 C 规则配置：新增 / 编辑 / 删除（核心，统一走「维度规则集编辑面」）

> **关键设计**：规则不支持「单条增删改」弹窗。无论新增/编辑/删除，都进入同一个 `dimEditor` 弹窗（维度级编辑面），因为「占比之和=100%」是维度级约束，必须整集原子保存。三种操作通过 `openDimensionEditor(rule?, opts?)` 的不同入参区分 (`1094`)。

**三种入口对比**

| 操作 | 调用 | `lockContext` | 行构建 | 初始 mode | 用途 |
|------|------|---------------|--------|-----------|------|
| 新增规则 | `openDimensionEditor()` 无参 | `false` | `_buildDimRows()` 基于所选维度全部指标 | `view` | 选维度+适用范围+年度，逐行设值后覆盖保存 |
| 编辑规则 | `openDimensionEditor(r)` | `true`（维度/年度锁定，适用范围可改） | 同维度全部指标，从历史规则派生 monthly/annual | `view` | 改既有规则集 |
| 删除某指标 | `openDimensionEditor(r,{preDelete:r.indicator})` | `true` | 同上 | `edit`（立即标记 `pendingDelete`） | 移除规则集中某指标，强制重平衡到 100% |

**新增规则 交互流**
1. 「+ 新增规则」→ `dimEditor` 打开，维度/适用范围/年度为空（`isGlobal=true, year=2026`）(`1105-1112`)。
2. 用户选维度 → `onDimEditorDimChange` 重建全部指标行（`_buildDimRows`）(`1123`)。
3. 选适用范围（全局/指定）+ 年度 → `onDimEditorCtxChange` 重建行，从历史规则派生对应 scope 的年度/月度 (`1133`)。
4. 逐行设占比%/强度/年度/12月；顶部「维度年度管控人数」可改，按比例联动重算各指标年度（`_redistributeAnnualByPct`）(`1213`)。
5. 保存：`saveDimRuleSet` → 4 道 gate → `PUT /dimensions/{id}/rules/` (`1265`)。

**编辑规则 交互流**
- 锁定维度/年度（身份），适用范围可改；改适用范围**不重建行**（保留编辑态），仅标记 `scopeDirty`；保存时若 `scopeDirty` 走「重定位」：删原 scope 规则集 + 新 scope 重建，并 `dialog.warning` 二次确认 (`1326-1338`)。
- 普通保存（未改 scope）无额外确认，直接 `doSave`。

**删除规则（行级）交互流**
- 行内「删除」按钮 → `toggleDimRowDelete(id)` 切 `pendingDelete`，行显示「待删」标签、可「恢复」(`1246/310-311`)。
- 删**部分**指标：其余行占比之和须仍=100%（`dimEditorSumOk` 校验）。
- 删**全部**指标：`validRows.length===0` → 保存被 `message.warning('请至少保留一个指标并设置占比')` 拦截（**D1 根因**）；即便绕过前端，后端 `set_rules` 空 rules 报「占比须=100%」400。
- ✅ 修复方向：见 D1，需支持「清空规则集」语义（前端放开全删校验 + 后端空 rules 走清空分支）。

**互斥守卫交互（保存前）**
- 保存为**全局**且同维度年度已存在指定范围 → `dialog.error` 直接拦截，提示「会清空指定范围」(`1318-1324`)。
- 保存为**指定范围**且会清全局 → `dialog.warning` 确认「跨适用范围保存确认」(`1341-1349`)。
- ⚠️ 指定范围保存会**静默 `delete` 全局规则**（D7），确认文案已提示但属不可逆数据变更。

### 7.5 G 人员：新增 / 编辑 / 删除

**新增 / 编辑（共用 `personModal`，width 560px）**
1. 入口：人员数据 Tab「+ 新增人员」或列表「编辑」(`openPersonModal`) (`1616`)。
2. 字段：编码、姓名（必填）；bu/院校/性别/专业/月份/状态（枚举下拉，带默认值）；预计入职/实际入职日期；position/level；`counted` 开关 (`1609-1615`)。
3. 提交：`upsertPerson`（带 `id`=编辑，无 `id`=新增），`counted` 默认 true (`1631-1638`)。
4. 校验：编码+姓名非空 (`1629`)；枚举合法性交由后端 Person serializer。

**删除（`removePerson`）**
- 入口：人员列表「删除」(`940`) → `dialog.warning` 正文「确认删除「X（编码）」？」(`1646`)。
- 硬删，仅 `loadPersons()` 刷新。

### 7.6 删除交互专项（四类删除语义对比）

| 删除对象 | 交互 | 删除性质 | 级联影响 | 风险点 |
|----------|------|----------|----------|--------|
| 维度 | 二次确认 | **硬删** | 指标 + 指标下规则 全 CASCADE | 文案缺「规则一并删」(D3) |
| 指标 | 二次确认 | **硬删** | 该指标名下规则全 CASCADE | 同上(D3) |
| 规则（行级） | pendingDelete 标记 + 整集保存 | **逻辑删除→原子替换** | 仅本(维度,scope,年)规则集 | 全删被拦截(D1)；指定范围静默清全局(D7) |
| 人员 | 二次确认 | **硬删** | 无（人员独立） | 误删影响历史快照；软删策略待定（D4） |

**删除交互统一改进建议**
1. 维度/指标删除确认文案补全级联规则数：「将同时删除该维度下的 N 条规则」（D3）。
2. 规则删除改为单行独立硬删 + 二次确认（D1 在扁平模型下自然消解，D7 被 6 字段组合唯一取代）；删除即失效。
3. Dimension/Indicator/Rule **维持硬删（D4 已关闭，豁免项目 P0 软删）**；Person 软删策略单列评估。
4. 指定范围保存的全局清理动作写审计日志（D7）。

### 7.7 交互一致性健康度

- ✅ **新增/编辑共用弹窗 + `editingId` 驱动** —— 四类实体一致，无重复代码。
- ✅ **删除二次确认统一 `dialog.warning`** —— 文案结构一致。
- ⚠️ **规则删除走「标记+整集保存」而非独立弹窗** —— 与维度/指标/人员的「即时硬删」语义割裂，是 D1/D7 的根源。
