## 2. UI 现有功能（v2.8 扁平模型）

### `RuleInput`（前端 `campusControl.ts:194`）

```ts
export interface RuleInput {
  bu: string
  position: string
  level: string
  dimension: string
  indicator: string
  year: number
  target: number        // 0~1，硬编码 1.0（不暴露 UI）
  strength: Strength
  annualTarget: number  // 年度管控人数
  monthlyTargets: number[] // 12 月
}
```

### 创建/编辑入口

1. **详情弹窗**（`RuleConfigDrawer.vue`）：3 模块——规则信息 / 管控目标 / 管控强度
   - **规则信息**：维度 / 指标 / 部门 / 职务 / 职级 / 生效年度（**无「目标占比」字段**）
   - **管控目标**：年度目标(人) / 月度目标(人) / alert 说明
   - **管控强度**：硬约束/软约束/仅提示

2. **`+ 新增规则` 按钮**：调用 `createRule(payload)`，payload.target 硬编码 1.0（v2.7 决策后从 UI 移除目标占比填写入口）
3. **`保存` 弹窗**：调用 `updateRule(id, payload)`，payload.target 仍硬编码 1.0

### 数据库模型（ControlRule）

```python
class ControlRule(models.Model):
    code = models.CharField(max_length=8)            # G+4 位
    is_active = models.BooleanField(default=True)
    bu / position / level = 三段适用范围
    dimension / indicator / year = 唯一键
    target = DecimalField(0~1)        # ← 占比管控上限，扁平模型下恒 1.0
    strength / annual_target / monthly_targets
```

### 唯一性

```
(bu, position, level, dimension, indicator, year, is_active) 唯一
```

即**每条规则 = 独占 (适用范围·指标·维度·年度) 组合**，不存在同一组合下"多指标占比加和"。

## 4. 后端导入行为（import_xlsx）— 与扁平模型对照

### `parse_import_workbook` 解析后分组（io_xlsx.py:181-263）

```python
scope_key = (bu, position, level, dimension, year)   # 5 元组
g = groups.setdefault(scope_key, {..., 'total_target': 0, 'rules': []})
# 一组内允许多个指标，按 target（占比）= 1.0 / 100 的倍数
```

### 组级校验（仍在 v2.8 跑）

| 校验 | 旧模型（多指标聚合） | v2.8 扁平模型 | 现状 |
|---|---|---|---|
| **占比之和 = 100%** | ✅ 必须（多指标分配） | ❌ 不适用（每条独占组合） | ⚠️ 旧校验仍在跑 |
| 月度之和 = 年度 | ✅ | ✅ | ✅ 通用 |
| 互斥：全局 vs 指定范围 | ✅ | ✅（按维度·年度） | ✅ 通用 |
| 互斥：同组唯一指标 | ✅ | ✅（实质"每条 = 唯一组"） | ✅ 但语义重复 |
| 维度/指标存在 | ✅ | ✅ | ✅ |

### _import_group 创建逻辑（views.py:1016+）

```python
# 同 (bu, position, level, dimension, year) 范围内
for r in rules_in:
    indicator = ... ; target = _to_decimal(r.get('target'))
    if not (0 <= target <= 1): error

    total += target
```

然后按 `total_target = sum(annual)` 创建多条 `ControlRule`，每条 `target=该指标占比值`，**不是 1.0**。

## 5. 不一致的具体危害

| 场景 | 现象 |
|---|---|
| ① 用户从模板填 1 行 → 占比 100% | ✅ 校验通过，1 条 rule 入库（target=1.0）→ 与 UI 一致 |
| ② 用户从模板填 2 行（同组多指标）→ 985=60%、211=40% | ✅ 校验通过，2 条 rule 入库（target=0.6/0.4）→ 与 UI 模型**冲突**：UI 单条独占，target 恒 1.0；导入产生 target=0.6 的规则在 UI 中**无对应来源** |
| ③ 看板（实时看板）计算 ratio = actual / denom | ratio 数值基于人员分布，不会因 target 而变；target 字段仅用作"高于上限"判定；导入的 target=0.6 规则可能误判（高于上限正常情况下应>60%，非 100%） |
| ④ `simulate()`（录入校验）按 target=0.6 计算上限 | 实际录入 50%（denom=100, 50=50%）应 PASS，但 target=0.6 → 50% < 60% → ✅ 通过；若 target=0.4 → 50% > 40% → ❌ 阻断——**校验行为因 target 值而漂移**，UI 永远 target=1.0（永不触发高于上限），导入则可能 target<1.0 |
| ⑤ 复制/停用/删除操作 | UI 复制出来的 target=1.0；导入规则可能 target=0.6——**同一张表里混着两种语义 target**，排查时极易困惑 |

## 6. 修复方案（待兵哥拍板）

### 方案 A：模板跟随扁平模型（推荐）

| 改动 | 涉及 |
|---|---|
| 1. `HEADERS` 去掉「目标占比(%)」列（list 由 21 列变 20 列）| `io_xlsx.py` |
| 2. `build_template_workbook` 示例行去掉 60 | 同上 |
| 3. `parse_import_workbook` 去掉占比 0~100 校验 + 默认 target=1.0 | 同上 |
| 4. 去掉组级「占比之和=100%」校验 | `views.py:_import_group` |
| 5. 更新模板说明文字（去掉"占比和=100%"那条） | `io_xlsx.py` |
| 6. 测试更新：`test_rule_import_export.py` 拆掉 `test_import_two_indicators_100pct` / `test_import_ratio_sum_not_100`（语义不再适用）| 测试 |
| 7. 现有 `target` 字段保留（兼容老数据 + 看板仍用 target=1.0 做"100%上限"基准） | 不变 |

**效果**：模板/导出/导入/UI 四 完全扁平化，target 统一为 1.0，新规则无歧义；老数据 target<1.0 仍在但无人能新建，逐渐冻结。

### 方案 B：保留旧模型 + 导入向导二次确认

- 保留 HEADERS「目标占比(%)」+ 100% 加和校验
- 在导入弹窗加提示："检测到 X 条占比<100% 的规则，将创建 target=X% 的管控上限规则（与界面新建的 100% 上限规则语义不同），确认继续？"
- 保留旧模型的灵活性（多指标占比管控），但要求用户明确知情

### 方案 C：双轨模板（两种 sheet）

- Sheet A: 「单指标规则」（扁平，无需占比）
- Sheet B: 「维度规则集」（旧多指标聚合+占比）
- 导入时按 sheet 分流

---

## 7. 决策建议

**推荐方案 A**：
1. 当前产品决策（v2.7/v2.8）已明确走扁平单行规则——模板是"实现细节残留"
2. 方案 B 维护成本高（双语义让新人不解）
3. 方案 C 复杂度高（产品已确认不需要多指标）

**落地成本**：
- 后端代码 ≈ -30 行（去掉旧校验）+ 测试 -3 条用例
- 前端导入弹窗提示文案微调（去掉"占比和=100%"）
- 1 个 commit，约 1 小时
