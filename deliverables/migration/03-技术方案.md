# 03-技术方案（冻结）

> 方案冻结线：本文档是「校招生管理助手」并入 ATS「校园招聘」模块的开发唯一事实来源。
> 开发阶段不得偏离接口契约、权限码、字典项、数据模型与前端改造清单。
> 凡标注【冻结】的条目，开发须严格实现，新增/变更须先回方案评审。

## 0. 决策摘要（冻结前提）

| 项 | 决策 |
|---|---|
| 新业务落位 | **新建独立 app `apps/campus_rotation/`**，承载「轮岗安排 / 轮岗资源 / 班级管理」；`campus` 与 `campus_control` 两 app 互不合并、互不迁移模型（严守警告） |
| 人员管理落位 | 复用 ATS 用户管理（UserDirectory.vue）+ 身份类型，**不建表**；校招生花名册复用 `campus_control.Person`（无账号，非 User） |
| 导师/班主任 | 作为 `User` 的身份类型（`RoleV2`：`CAMPUS_MENTOR` / `HEAD_TEACHER`），通过 `UserRoleV2` 授予，**不建表** |
| 直属上级 | 复用 `User.direct_manager`（已存在），**零 DDL** |
| 部门 | 单一真相源 = ATS `Department`（db_table=`departments`），原型两套部门常量全部废弃 |
| BU 语义 | BU = ATS `Department` 的**二级部门（部门层级=第2级：根组织之下第二层，根=第0级、事业群=第1级、BU=第2级）**；归属 BU 存该节点 id；写时校验 bu 节点 `parent IS NOT NULL AND parent__parent IS NULL`（深度==2），**不给 Department 加"层级角色"字段**（解 OQ-13，已对齐源口径：源 BU=二级部门） |
| 直播间平台/地点 | 迁为数据字典一类配置项（`LIVE_ROOM_PLATFORM` + `LOCATION`），字典模块零改动 |
| 权限范式 | 全部新端点接 `V2Permission` + `EnvelopeWriteMixin` + `CampusCRUDMixin`（软删），**严禁效仿 `campus/views.py` 的裸 `IsAuthenticated`** |
| 数据预置 | 按 OQ-2 **不预置真实人名/组织名**；迁移脚本仅提供幂等 + dry-run 框架，落地数据由运营在 UI 录入 |

## 1. 架构总览

### 1.1 三大业务模块 + 人员管理 落位

| 业务域 | App | 模型 | 路由前缀 | 说明 |
|---|---|---|---|---|
| 轮岗安排 | `campus_rotation`（新） | `RotationArrangement` | `/api/v1/campus-rotation/` | 校招生（Person）轮岗生命周期；引用 mentor/monitor/direct_manager（User）、class_room、department |
| 轮岗资源 | `campus_rotation`（新） | `LiveRoom` | 同上 | 直播间明细；department + bu(Department L1) + platform(字典) + location(字典) + capacity |
| 班级管理 | `campus_rotation`（新） | `ClassRoom` | 同上 | 班级；head_teacher(User,须 HEAD_TEACHER) + class_monitor(User) + hrbp |
| 人员管理 | `core`（复用） | `User` + `UserRoleV2`/`RoleV2` | `/api/v1/users/` | 复用用户管理；导师/班主任为身份类型；直属上级为 User 字段 |

**为何新建 `campus_rotation` 而非扩 `campus`**：`campus` app 现有 `CampusAmbassador`/`CampusSession` 走 `recruit_type` 硬分区（`ScopeQuerysetMixin`）+ 裸 `IsAuthenticated`（坏范式）。轮岗/资源/班级数据无 `recruit_type` 分区需求、且必须接 V2 权限，混进 `campus` 会污染其分区语义并拖累权限整改。新 app 干净隔离，且 `campus` 与 `campus_control` 仍各自独立（满足"勿合并"警告）。

**为何复用 `Person` 而非 Candidate/新建花名册**：`campus_control.Person` 已是校招生主数据（code/name/bu/school/sex/major/status + `user_id` 映射），且 `recruit:settings:campus-control:*` 权限与 Ratio 引擎均围绕它。校招生按 OQ-3 **不建账号**（非 User），与 Person 定位一致。轮岗安排通过 `person_id`（BigInteger，同 Person.user_id 口径，避免跨 app 外键耦合）关联 Person，不在 Person 上加轮岗字段，保护 Ratio 引擎纯净。

### 1.2 请求链路图

```
前端 校园招聘模块菜单 (Layout.vue 校园招聘分组)
  ├─ 轮岗安排  → /campus/rotation-arrangement  → GET/POST /api/v1/campus-rotation/rotation-arrangements/
  ├─ 轮岗资源  → /campus/live-room            → GET/POST /api/v1/campus-rotation/live-rooms/
  ├─ 班级管理  → /campus/class-room           → GET/POST /api/v1/campus-rotation/class-rooms/
  ├─ 人员管理  → /settings/users/all          → 复用 /api/v1/users/  (RoleV2 身份类型 + direct_manager)
  ├─ 校园大使  → /settings/campus-ambassador  → /api/v1/campus-recruit/ambassadors/   (整改为 V2)
  └─ 宣讲会    → /settings/campus-session     → /api/v1/campus-recruit/sessions/       (整改为 V2)

V2Permission ── 校验 resource_code ──> seed_v2_init.RESOURCES（新增 recruit:campus:*）
部门树 ── useDepartmentStore ──> /api/v1/departments/  (is_active 校验)
字典 ── /api/v1/dictionary/items/LIVE_ROOM_PLATFORM ──> DictionaryItem
```

## 3. 接口契约（冻结）

> 全局约定：camelCase 自动转换（djangorestframework-camel-case），请求/响应均用驼峰；分页 `PAGE_SIZE=20`（`StandardResultsSetPagination`）；写端点走 `EnvelopeWriteMixin`（响应 `{success, data}`）；错误码统一 `{success:false, detail}` 或 DRF 标准 400/403/404/409。

### 3.1 直属上级（需求 5，复用 /api/v1/users/）

| 项 | 说明 |
|---|---|
| 列表筛选 | `GET /api/v1/users/?direct_manager={user_id}` 按直属上级过滤；`?role=campus_mentor,head_teacher` 身份多选取并集 |
| 响应新增字段 | `directManager`（上级 id，可空）、`directManagerName`（上级姓名，只读派生） |
| 校验 | 设直属上级时防成环：不能选自己或自己的下属（`subordinates` 递归），否则 400 `{detail:"不能选自己或下属作为直属上级"}` |

JSON 示例（用户列表项）：
```json
{
  "id": "u_102", "username": "zhangsan", "realName": "张三",
  "employeeId": "E102", "department": "dep_77",
  "directManager": "u_050", "directManagerName": "李四",
  "userType": "INTERNAL", "status": "ACTIVE",
  "roleNames": ["招聘专员", "校园导师"]
}
```

## 7. 数据迁移脚本方案（按 OQ-2 推荐）

- **不预置真实人名/组织名**：种子与迁移脚本**不写**任何真实部门、人员、导师、平台实例。
- 幂等框架：提供 `apps/campus_rotation/management/commands/import_campus_data.py`，支持 `--dry-run` 打印匹配报告而不落库；重复执行 `update_or_create`（按业务唯一键：room_no / class code / person_id+stage）。
- 部门匹配：脚本读取原型部门名 → 按 `Department.name` 精确匹配 ATS 部门；**匹配不到不新建假部门**，写入报告 `unmatched_depts[]` 由运营在 UI 手工建。因 OQ-2 不预置，本期默认无待迁移真实数据，脚本主要作为后续真实数据接入通道。
- 导师/班主任/直属上级：若后续有真实数据，按 `employee_id`/`username` 映射到 ATS `User`；映射不到记 `unmatched_users[]`，不创建账号（OQ-3）。
