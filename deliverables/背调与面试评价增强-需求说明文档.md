# 背调与面试评价增强 — 需求说明文档

- 文档版本：v1.0
- 编写日期：2026-10-08
- 适用范围：ATS-NEW 招聘管理系统（Django + Vue3 / Naive UI）
- 状态：需求整理 + 本次已落地「发起背调」步骤式改造与面试评价字段；offer 问答题面板、待入职 UI 为后续迭代（见第 9 节）

---

## 1. 背景与目标

当前系统背调能力分散在两套体系：

1. **offer 应用 `BackgroundCheck`**（4 等级 + `note` 背调备注）—— offer 表单「背景调查」面板。
2. **integration 应用 `BackgroundCheckOrder`**（供应商订单状态机）—— 候选人详情「发起背调」弹窗。

本次需求核心目标：

- 在**面试评价表**沉淀结构化「综合评价 / 背调建议」（≤255 字），并贯穿到应聘记录展示。
- 以**面试官为单位**把「背调建议」转化为 offer 背景调查中的**问答题**，由招聘专家逐条回答并回填至背调备注。
- 面试官产出背调建议时，**在消息通知中着重提醒招聘专家**。
- 将「发起背调」弹窗重构为**步骤式统一流程**，覆盖「已有报告上传 / 没有报告系统下单 / 补充背调 / 自主背调 / 自主下单 / 系统下单」全场景，并与待入职阶段复用同一弹窗。

---

## 2. 术语

| 术语 | 含义 |
|---|---|
| 综合评价 | 面试评价表新增字段，面试官对候选人的总体评价文字，≤255 字 |
| 背调建议 | 面试评价表新增字段，面试官针对背景调查提出的关注点/问题，≤255 字；以面试官为单位每人生成一条 |
| 自主背调 | 不通过供应商、由用户自行完成并上传报告的方式（无供应商订单，订单渠道=SELF） |
| 自主下单 | 用户自行选择供应商下单；可选范围 = 自主背调 + 所有供应商 |
| 系统下单 | 由系统发起的下单；可选范围 = 系统已对接的供应商（`is_system_integrated=True`） |
| 已有报告上传 | 用户已持有背调报告，直接上传（含回答背调建议问题） |
| 补充背调 | 在已有背调基础上追加；仍需选择是否已有报告，复用统一弹窗 |
| 订单备注 | `BackgroundCheckOrder.remark`，无报告下单时承载背调建议；offer 侧对应 `BackgroundCheck.note`（背调备注） |

## 3. 功能需求

### FR1 面试评价表新增字段

- **F1.1** 面试评价表新增两个字段：
  - `综合评价`（overall_eval）：文本，字数限制 **≤255 字**。
  - `背调建议`（bg_suggestion）：文本，字数限制 **≤255 字**。
- **F1.2** 两个字段均需在**应聘记录**中展示（评价摘要卡 `InterviewEvalSummaryCard`）。
- **F1.3** 表单提交时后端做长度校验（>255 字拦截，返回 400）。

### FR2 背调建议生成与通知

- **F2.1** 背调建议以**面试官为单位**，每人生成**一条**；同一面试官多次提交以最新一次为准。
- **F2.2** 在 **offer 表单的「背景调查」字段**中，将各面试官的背调建议渲染为**问答题**（一题对应一位面试官的背调建议）。
- **F2.3** 招聘专家需**全部回答**所有背调建议问题，并将答案回填至**背调备注**（`BackgroundCheck.note`）。
- **F2.4** 当面试官提交**非空背调建议**时，系统向**招聘专家**发送站内信通知，并在通知中**着重提醒**（高优先级 `priority=HIGH`，标题含候选人姓名与「背调建议」标识）。

### FR3 发起背调弹窗步骤式重构

- **F3.1** 「添加背调」按钮调整，提供渠道选择：**自主背调 / 自主下单 / 系统下单**。
  - 自主下单可选范围：**自主背调 + 所有供应商**。
  - 系统下单可选范围：**系统已对接的供应商**（`is_system_integrated=True`）。
- **F3.2** 两条主路径：
  - **已有报告，立即上传**：用户选择上传已做好的背调报告。
  - **没有报告，立即下单**：用户通过系统下单。
- **F3.3** 添加**补充背调**时，仍需选择是否已有报告（与新增共用弹窗）。
- **F3.4** 弹窗统一步骤式处理：
  1. **第一步：是否已有背调报告？**
     - 选「已有报告」→ **直接上传**：上传报告（文件或报告链接），并**回答背调建议的问题**（来自各面试官），可填备注 → 提交（订单渠道=SELF，状态=已完成）。
     - 选「没有报告」→ **统一系统下单**：选择下单渠道（自主下单 / 系统下单）→ 选供应商 → 选套餐/检查项 → **背调建议自动填充至订单备注**（可编辑）→ 提交（订单渠道=SELF_ORDER / SYSTEM_ORDER）。

### FR4 待入职阶段背调

- **F4.1** 待入职阶段支持上传**新背调报告**。
  - 若**已有**背调报告 → 调用**补充背调接口**（`is_supplementary=True`，关联父订单）。
  - 若**完全没有**背调报告 → 调用**新增背调接口**。
- **F4.2** 若 offer 阶段未上传背调报告，待入职阶段上传时也**复用背调统一弹窗**。
- **F4.3** 若已有内容且**已审批通过**，已审批内容**不可修改**，但可**追加新内容**（新增补充背调记录）。

## 4. 数据模型变更

### 4.1 `integration.BackgroundCheckOrder`（迁移 0008）

| 字段 | 类型 | 说明 |
|---|---|---|
| `channel` | CharField(16)，choices `BGChannel` | `SELF`(自主背调) / `SELF_ORDER`(自主下单) / `SYSTEM_ORDER`(系统下单)，默认 `SYSTEM_ORDER` |
| `remark` | TextField | 订单备注 / 背调建议承载；无报告下单时填充背调建议 |
| `is_supplementary` | BooleanField，默认 False | 是否为补充背调 |
| `parent_order_id` | CharField(32)，blank | 补充背调关联的父订单 id |
| `bg_suggestions` | JSONField，默认 list | 背调建议快照（按面试官），如 `[{interviewer, interviewer_name, suggestion, answer}]` |

### 4.2 `integration.IntegrationConfig`（迁移 0008）

| 字段 | 类型 | 说明 |
|---|---|---|
| `is_system_integrated` | BooleanField，默认 True | 是否系统已对接供应商（决定「系统下单」可选范围） |

### 4.3 `interview.InterviewEvaluation`（迁移 0004）

| 字段 | 类型 | 说明 |
|---|---|---|
| `overall_eval` | CharField(255)，blank | 综合评价 |
| `bg_suggestion` | CharField(255)，blank | 背调建议 |

## 5. 接口设计（integration）

| 方法 / 路径 | 说明 |
|---|---|
| `GET /background-check/orders/suppliers/?mode=self_order\|system_order` | 列供应商。`self_order` 返回 SELF_CHECK 伪选项 + 所有启用供应商；`system_order` 仅返回 `is_system_integrated=True` 的供应商 |
| `GET /background-check/orders/products/?config_id=` | 拉取供应商套餐（原逻辑） |
| `POST /background-check/orders/create-order/` | 发起下单；新增入参 `channel`、`remark`、`parent_order_id`、`bg_suggestions`、`has_existing_report` |
| `POST /background-check/orders/upload-report/` | 已有报告上传；入参 `candidate_id/name/phone`、`report_url`（或文件）、`answers`、`remark`、`parent_order_id`、`bg_suggestions`；创建 `channel=SELF, status=已完成` 订单 |
| `GET /background-check/orders/bg-suggestions/?candidate_id=` | 聚合该候选人来自各面试官的背调建议（去重到面试官最新一条） |

> offer 侧 `BackgroundCheck`（`/offers/{id}/background-checks/`）保持原 4 等级能力；offer 问答题面板将在后续迭代接入 `bg-suggestions` 聚合结果并回填 `note`。

## 6. 前端交互

- **`InitiateBackgroundCheckModal.vue`** 重构为步骤式（NModal + NSteps）：
  - 步骤 1：是否已有报告（radio）。
  - 分支 A（已有）：上传区 + 动态渲染背调建议问答题（必答）+ 备注 → `upload-report`。
  - 分支 B（没有）：选择下单渠道（自主下单/系统下单）→ 供应商下拉（范围受渠道约束）→ 套餐/检查项 → 背调建议只读填充至订单备注 → `create-order`。
  - 支持 `isSupplementary` + `parentOrderId` 透传（补充背调）。
- **`InterviewEvaluationModal.vue`** 增加「综合评价 / 背调建议」两个文本域（≤255，计数提示）。
- **`InterviewEvalSummaryCard.vue`** 展示综合评价与背调建议。
- i18n：`zh-CN.ts` / `en-US.ts` 新增 `pages.candidate.InitiateBgCheck.*` 与 `pages.interview.InterviewEvaluationModal.*` 键。

## 7. 非功能与约束

- 字段长度后端 + 前端双重校验（255 字）。
- 背调建议通知为 fail-soft：通知发送失败不影响评价/订单主流程（best-effort）。
- 供应商密钥不随供应商列表/产品接口暴露（仅 id/name/provider）。
- 状态机：自主背调上传订单直接置「已完成」(status=1)；供应商下单维持原 8 态机。

---

## 8. 验收标准

- [ ] 面试评价可填写综合评价、背调建议，超过 255 字被拦截；应聘记录正确展示。
- [ ] 面试官提交背调建议后，招聘专家收到高优先级站内信提醒。
- [ ] 发起背调弹窗先问是否已有报告；已有→上传并回答建议问题；没有→系统下单且背调建议进订单备注。
- [ ] 自主下单可选「自主背调 + 所有供应商」；系统下单仅可选系统已对接供应商。
- [ ] 补充背调复用同一弹窗并标记 `is_supplementary` + 父订单。
- [ ] 待入职上传新报告：已有→补充接口，无→新增接口；已审批内容不可改、可追加。
